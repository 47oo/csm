## 1. 通用约定

- Base path：`/api/v1`（§25 CONFIRMED），认证端点挂载同一 `api_v1_router`。
- 认证载体：`csm_session` HttpOnly Cookie（服务端不透明会话，DR-08）**或** `Authorization: Bearer <API Key>`（机器凭据，定义见 docs/api/F017.md）。二者并存，同一 API 集合同时接受；请求携带 Bearer（scheme 大小写不敏感、token 非空）时走 API Key 路径并忽略 Cookie，否则走 Cookie 路径（非 Bearer 的 Authorization 头原样忽略）。Bearer 请求免除 §2.1 CSRF 同源校验。`/auth/login`、`/auth/logout` 仍为 Cookie 流程。
- 请求/响应体：`application/json`（204 无正文）。
- 时间表示：ISO-8601、UTC（timestamptz 存储，DB-D19），例 `2026-10-06T12:00:00+00:00`。

### 1.1 统一错误信封

```json
{ "error": { "code": "STRING_CODE", "message": "human readable", "details": {} } }
```

`code` 稳定机器可读；`message` 不泄露凭据/账号存在性/堆栈；`details` 无附加信息时为 `{}`。

### 1.2 错误码与 HTTP 映射

| HTTP | code | 触发 | details |
| --- | --- | --- | --- |
| 401 | `AUTH_REQUIRED` | 无有效凭据（csm_session 或 API Key）；令牌无法解析/已删除/已过期；会话对应用户非 ACTIVE；API Key 缺失/格式非法/哈希不匹配/已吊销/已过期/绑定账号非 ACTIVE | `{}` |
| 401 | `AUTH_INVALID_CREDENTIALS` | 登录凭据错误：密码不符、账号不存在、账号停用（统一不区分） | `{}` |
| 403 | `FORBIDDEN` | 已认证但角色缺权限；同源（CSRF）校验失败 | 可选 `{"reason":"permission"\|"csrf"}` |
| 409 | `VERSION_CONFLICT` | 乐观锁版本过期 | `{"current_version": int}` |
| 409 | `CONFLICT` | 业务冲突（唯一性/引用/恢复；F003 起扩展，见 docs/api/F003.md §1.2） | `{"reason": str, ...}` |
| 404 | `NOT_FOUND` | 目标资源/路径不存在 | `{}` |
| 413 | `IMPORT_FILE_TOO_LARGE` | 导入文件字节数超过上限（解析前拒绝；定义见 docs/api/F014.md v1 §1.2） | `{"limit_bytes": int}` |
| 413 | `IMPORT_ROW_LIMIT_EXCEEDED` | 导入数据行数超过上限（解析后、校验前拒绝；定义见 docs/api/F014.md v1 §1.2） | `{"limit_rows": int}` |
| 422 | `IMPORT_INVALID_FILE` | 导入文件不可解码/损坏/非 xlsx/空数据行/表头或列不符（定义见 docs/api/F014.md v1 §1.2） | `{"reason": str, "missing_columns": [str]?, "unknown_columns": [str]?}`；reason∈{unreadable, unsupported_format, header_missing, missing_columns, unknown_columns, column_order, empty_file} |
| 422 | `IMPORT_VALIDATION_FAILED` | 导入写入存在行错误，整批回滚（定义见 docs/api/F014.md v1 §1.2） | `{"total_rows": int, "importable_rows": int, "error_count": int, "errors": [...], "errors_truncated": bool}` |
| 422 | `VALIDATION_ERROR` | 请求体/参数校验失败 | `{"fields":[{"field": str, "message": str}]}` |
| 500 | `INTERNAL_ERROR` | 未预期服务端错误（不含堆栈/凭据） | `{}` |

401 = 尚无有效身份；403 = 身份有效但权限不足；未认证先于权限判定返回 401。

### 1.3 业务边界

- 登录缺字段/空白 username 或 password/类型错误 → 422 VALIDATION_ERROR（不创建会话）。
- 登录未知用户、密码错误、停用账号 → 401 AUTH_INVALID_CREDENTIALS，三者响应一致（不泄露账号存在性）。
- 登出无有效会话 → 401 AUTH_REQUIRED。
- /auth/me 会话过期/用户停用/无 Cookie → 401 AUTH_REQUIRED。
- 注册等未定义路径 → 404 NOT_FOUND。
- 版本冲突仅定义信封与处理器契约；端到端落 F003/T26。

## 2. Cookie 属性

| 属性 | 值 |
| --- | --- |
| name | `csm_session` |
| value | 不透明令牌（secrets.token_urlsafe(32)，43 字符）；DB 仅存 SHA-256 hex（user_sessions.token_hash，DB-D16） |
| HttpOnly | true |
| SameSite | Lax |
| Path | `/` |
| Secure | APP_ENV=production 时 true |
| Expires / Max-Age | 等于会话 expires_at（绝对过期，SESSION_TTL_HOURS 默认 12） |

绝对过期无滑动续期；登出删除会话行并下发清除 Cookie（Max-Age=0）。

### 2.1 CSRF 口径（本期实现）

- 主控制：SameSite=Lax。
- 纵深：对不安全方法（POST/PUT/PATCH/DELETE）**且携带 csm_session 且不含 `Authorization: Bearer`** 的请求：存在 Origin → 其 authority 须等于请求 Host（可被 AUTH_ALLOWED_ORIGINS 覆盖），否则 403 FORBIDDEN（details.reason="csrf"）；否则存在 Sec-Fetch-Site → 须为 same-origin，否则 403；两者皆缺（非浏览器客户端）→ 放行。携带 Bearer 的请求不经此校验（Bearer 不随跨站浏览器请求自动发送，见 docs/api/F017.md §1）。
- 安全方法（GET/HEAD）不做同源校验；不实现登录限流（本期 NOT_REQUIRED）。

## 3. 权限矩阵引用（§23）

| §23 操作行 | Capability | VIEWER | EDITOR | ADMIN |
| --- | --- | --- | --- | --- |
| 查询、搜索、详情 | `READ` | 允许 | 允许 | 允许 |
| 查看资源变更记录 | `VIEW_ACTIVITY` | 允许 | 允许 | 允许 |
| 新增、修改业务对象，分配及解绑 IP | `WRITE` | 拒绝 | 允许 | 允许 |
| CSV / Excel 资源导入 | `IMPORT` | 拒绝 | 允许 | 允许 |
| 删除、释放 IP、查看已删除对象、恢复 | `DELETE_OBJECT` / `RELEASE_IP` / `VIEW_DELETED` / `RESTORE` | 拒绝 | 拒绝 | 允许 |
| 用户、角色、系统设置、完整审计查询 | `USER_ADMIN` / `AUDIT_READ` | 拒绝 | 拒绝 | 允许 |

解绑属 WRITE（不释放 IP）；释放属 RELEASE_IP（ADMIN）。权限仅限制，不豁免对象状态/不可变字段/关系约束。API Key 继承绑定账号角色，按本矩阵逐行执行，不产生新权限语义、不支持 scope-down（docs/api/F017.md §1.2）；仅 ADMIN 行新增「创建/查看/吊销 API Key」复用语义。F002 无真实业务端点；矩阵经生产依赖在 F003+ 生效；F002 的 403 为机制级证据（测试挂载生产依赖路由），完整 T25 归 F003。

## 4. Endpoints

### 4.1 POST `/api/v1/auth/login`

- 认证：无需会话。
- 请求体：`username` string 必填（非空，服务端归一化去首尾空白+小写后匹配 `^[a-z0-9._-]{3,64}$`）；`password` string 必填（非空）。
- 成功 200：

```json
{
  "user": {
    "id": "6f1c…-uuid",
    "username": "admin",
    "role": "ADMIN",
    "status": "ACTIVE",
    "permissions": ["AUDIT_READ","DELETE_OBJECT","IMPORT","READ","RELEASE_IP","RESTORE","USER_ADMIN","VIEW_ACTIVITY","VIEW_DELETED","WRITE"]
  },
  "expires_at": "2026-10-06T12:00:00+00:00"
}
```

| 字段 | 类型 | nullable | 说明 |
| --- | --- | --- | --- |
| user.id | string(UUID) | 否 | users.id |
| user.username | string | 否 | 归一化小写 |
| user.role | string enum | 否 | VIEWER/EDITOR/ADMIN |
| user.status | string enum | 否 | ACTIVE/DISABLED |
| user.permissions | string[] | 否 | capability 枚举，排序；可空数组 |
| expires_at | string(ISO-8601 UTC) | 否 | 等于会话行 expires_at |

响应头 `Set-Cookie: csm_session=…`（属性见 §2）。错误：422 VALIDATION_ERROR；401 AUTH_INVALID_CREDENTIALS；403（携带旧 Cookie 的异源请求，CSRF）；500 INTERNAL_ERROR。

### 4.2 POST `/api/v1/auth/logout`

- 认证：需有效会话。请求体：无。
- 成功 204：无正文；`Set-Cookie: csm_session=; Path=/; Max-Age=0; HttpOnly; SameSite=Lax[; Secure]`；删除对应 user_sessions 行。
- 错误：401 AUTH_REQUIRED；403（CSRF）。

### 4.3 GET `/api/v1/auth/me`

- 认证：需有效会话。
- 成功 200：`{"user": { …同 §4.1 user 对象… }}`。
- 错误：401 AUTH_REQUIRED。GET 为安全方法，无同源校验。

## 5. 无注册端点声明（A3）

不提供自行注册接口：无 `POST /api/v1/auth/register`、`/signup` 或匿名创建用户端点；`POST /api/v1/users` 在 F002 不存在（用户管理 API 属 F015）。首个 ADMIN 仅经部署侧一次性 bootstrap 创建（应用侧 CLI，非迁移）。访问候选注册路径返回 404 NOT_FOUND（或 405）。

## 6. 版本冲突（409）说明

F002 定义 VERSION_CONFLICT 信封与处理器契约；`users.version`（ck_users_version: version >= 1，DB-D15）为机制级验证载体。过期版本被拒且不被覆盖；响应含 details.current_version；前端不得静默重试覆盖。业务对象端到端乐观锁归 F003/T26。
