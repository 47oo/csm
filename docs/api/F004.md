## 1. 通用约定

- Base path /api/v1（§25），挂载同一 api_v1_router。
- 认证：csm_session HttpOnly Cookie（复用 F002 DR-08）；未认证先于权限返回 401。
- 时间：ISO-8601 UTC（D01 §2；DB timestamptz）。
- 操作者：服务端从 request.state.operator 取，写 Audit 的 operator_user_id(users.id)+operator_username 快照（§22）；请求体不接受操作者字段。
- CSRF：不安全方法沿用 F002 §2.1；GET/HEAD 不校验。

### 1.1 统一错误信封（复用 F002 §1.1）

`{ "error": { "code": "STRING_CODE", "message": "human readable", "details": {} } }`

### 1.2 错误码与 HTTP 映射（F002 集 + F003 CONFLICT 复用）

| HTTP | code | 触发 | details |
| --- | --- | --- | --- |
| 401 | AUTH_REQUIRED | 无有效会话（复用 F002） | {} |
| 403 | FORBIDDEN | 已认证缺权限 | {"reason":"permission"} |
| 403 | FORBIDDEN | CSRF 校验失败（复用 F002） | {"reason":"csrf"} |
| 404 | NOT_FOUND | 不存在；或已软删且无 VIEW_DELETED（不泄露存在性）；或未定义路径 | {} |
| 409 | VERSION_CONFLICT | 乐观锁过期（复用 F002） | {"current_version": int} |
| 409 | CONFLICT | 唯一性/引用/恢复冲突 | 见下表 |
| 422 | VALIDATION_ERROR | 请求体/查询参数校验失败 | {"fields":[{"field":str,"message":str}]} |
| 500 | INTERNAL_ERROR | 未预期错误（不含堆栈/凭据） | {} |

（BareMetal hardware 相关 422 见 §2.4；VirtualMachine virtual_machine 相关 422 见 §2.5，含 BARE_METAL 请求体出现 virtual_machine。）

CONFLICT details.reason 枚举（复用 F003，F006 不新增 code）：unique_conflict（同 Cluster hostname 归一化后与现存未删冲突；field:"hostname"）；not_deleted（对未软删对象 restore）；dependency_deleted（恢复时依赖对象仍软删/缺失；conflicts:[{object_type,object_id}]；F004 cluster 依赖 object_type:"cluster"；F006 恢复 VIRTUAL_MACHINE 时 Host 软删/缺失 object_type:"resource"）；reference_exists（删除 Resource 被未删对象引用；references:[{object_type,object_id,label}]；F004 Resource 自身引用集为空，机制级，通常 []；F006 起 Host Resource 被未删 VIRTUAL_MACHINE 引用时 references 含该 VM，object_type:"resource"，label=<vm-hostname>）。错误码注册表以 docs/api/F002.md §1.2 为共享权威；F004 复用 F003 CONFLICT，F006 不新增。

### 1.3 权限（§23，复用 F002 §3）

列表/详情/模糊=READ；创建/更新=WRITE；删除（软删）=DELETE_OBJECT；查看已删除（deleted=include|only、详情 deleted=true）=VIEW_DELETED；恢复=RESTORE；Activity=VIEW_ACTIVITY（全角色）。服务端执行；前端隐藏不替代；未认证先于权限→401。

## 2. 字段契约与归一化

### 2.1 Resource hostname（D01 §5.3 裁定；F004 I-1）

服务端 trim→非空→禁内部空白（Unicode White_Space）与控制字符（Cc/Cf）→长度（Unicode code point）1–253→存归一化小写展示值。允许中文及其它 Unicode；允许 `.`；短名与 FQDN 按完整字符串不合并。

归一化键 hostname_key = ASCII_lower(btrim(hostname))：仅将 ASCII A-Z 折叠为 a-z，非 ASCII（含中文、ß、ﬁ）原样保留；**应用禁用 str.lower()**；DB 用 `translate(btrim(hostname),'ABCDEFGHIJKLMNOPQRSTUVWXYZ','abcdefghijklmnopqrstuvwxyz')`、**禁用 lower()**（F003-REV-1 同源口径，locale 无关）。内部列不暴露；DB ck_resources_hostname_key_matches 锁定口径。

唯一性：同 Cluster (cluster_id, hostname_key) **部分唯一 WHERE deleted_at IS NULL**；跨 Cluster 允许；软删后可重用；恢复重检冲突。与 Cluster code 全量唯一口径相反，不可互换。cn001/CN001/" cn001 " 同 Cluster 相同。示例：C1 存 cn001 后再传 CN001→409 CONFLICT{unique_conflict,field:"hostname"}；C2 传 cn001→201。

### 2.2 其它字段

- resource_type：必填无默认；∈{BARE_METAL,VIRTUAL_MACHINE}；创建后不可改；显式 null／非法→422。
- role：可选默认 OTHER；∈{COMPUTE,LOGIN,MANAGEMENT,STORAGE,SERVICE,GPU,OTHER}；显式 null／非法→422；可扩展。
- status：可选默认 UNKNOWN；∈{IDLE,ALLOC,DOWN,UNKNOWN}；显式 null／非法→422；人工维护。
- description：可选 nullable；未设置/显式 null 为 null；PATCH 显式 null 清空。
- metadata：可选默认 {}；必须 JSON object；整值替换；显式 null／非 object→422。
- cluster：创建必填；接受 Cluster UUID 或 code（code 经 code_key 大小写不敏感精确解析）；落库 UUID；创建后不可改。
- version：int≥1；创建默认 1；PATCH/DELETE/restore 必填。

### 2.3 长度口径（镜像 DB）

hostname 253；resource_type 32；role 16；status 16；activity.operator_username 64（Unicode code point）；**BareMetal 字符串字段（manufacturer/model/serial_number/cpu_model/gpu_model）255（§2.4，D01 §5.4）**；**VirtualMachine hypervisor 255（§2.5，D01 §5.5）。**

### 2.4 BareMetal hardware 字段契约（v2 新增；F005；D01 §5.4）

硬件字段仅适用于 `resource_type=BARE_METAL`，作为 Resource create/PATCH 的嵌套 `hardware` 对象与 Resource 响应的嵌套 `hardware` 暴露；**不新增独立端点**（§21 明细无独立入口、§18 硬件是 Resource Detail 区域）。字段来源 `bare_metal_details`（DB-D45–D52），与 Resource 同事务持久化。

| 字段 | 类型 | nullable | 创建省略默认 | 合法值 / 格式 |
| --- | --- | --- | --- | --- |
| manufacturer | string | 是 | null | trim 后非空；长度 ≤255 code point |
| model | string | 是 | null | 同上 |
| serial_number | string | 是 | null | 同上；**一期无全局唯一**（无 409 unique_conflict，无归一化键） |
| cpu_model | string | 是 | null | 同上 |
| cpu_sockets | int | 是 | null | 正整数 1..2147483647 |
| cpu_cores | int | 是 | null | 正整数 1..2147483647；**整机物理核心总数、不含超线程**；不自动探测、无跨字段推导 |
| memory_mb | int | 是 | null | 正整数 1..2147483647；**单位 MiB**；原样存储，不做换算 |
| gpu_model | string | 是 | null | trim 后非空；长度 ≤255 code point |
| gpu_count | int | 是 | null | 非负整数 0..2147483647；**0=明确无 GPU，null=未知** |
| metadata | object | 否 | {} | JSON object；整值替换（hardware.metadata，区别于 Resource.metadata） |

规则：
- **未知值存 null**，绝不以 0 代替；gpu_count=0 与 null 语义不同且可区分。
- **创建**：hardware 整体省略→全 null（metadata={}）；子字段省略→null；显式 null 于 nullable 子字段→null。无默认 0。
- **PATCH**：hardware 子字段级 exclude_unset——省略=保持原值；显式 null=清空该 nullable 子字段；hardware 整体显式 null、非 object、含未知键→**422**（hardware 本身不可清空）。
- **VM**：请求体出现 hardware（含显式 null）→**422 VALIDATION_ERROR**（不静默忽略，DR-51）；响应 hardware 恒为 null。
- **字符串口径**（DR-52/D01 §5.4）：服务端 trim 首尾空白→trim 后非空→禁控制字符（Cc/Cf，应用层；DB 为 ASCII backstop）→长度 ≤255 code point；空串/纯空白→**422（不转 null）**；区分大小写、保留展示。
- **数值口径**：cpu_sockets/cpu_cores/memory_mb ≤0 或非整数→422；gpu_count <0 或非整数→422；gpu_count=0 接受。严格整数语义（不接受 "192"/true/1.5）。
- **无 SN 唯一、无归一化键**：相同 serial_number 可登记；PATCH SN 不触发 409。
- 各字段独立，无 cpu_sockets×cpu_cores、无 GPU/Role 推导。
- 错误 fields[].field 用点路径，如 hardware.cpu_cores、hardware.metadata。

### 2.5 VirtualMachine virtual_machine 字段契约（v3 新增；F006；D01 §5.5）

VM 专有字段仅适用于 `resource_type=VIRTUAL_MACHINE`，作为 Resource create/PATCH 的嵌套 `virtual_machine` 对象与 Resource 响应的嵌套 `virtual_machine` 暴露；**不新增独立端点**（§21 明细无独立入口、§18 VM 展示 Host）。字段来源 `virtual_machine_details`（DB-D53–D63），与 Resource 同事务持久化。

| 字段 | 类型 | nullable | 创建省略默认 | 合法值 / 格式 |
| --- | --- | --- | --- | --- |
| host_resource_id | string(UUID) | 否 | — | 创建必填非 null；PATCH 显式 null→422；引用须存在、未软删、resource_type=BARE_METAL 且与 VM 同 Cluster |
| vcpu | int | 是 | null | 正整数 1..2147483647 或 null；0/负→422 |
| memory_mb | int | 是 | null | 正整数 1..2147483647 或 null；**单位 MiB**；1 GiB=1024 MiB；原样存储不换算 |
| disk_gb | int | 是 | null | 非负整数 0..2147483647 或 null；**单位 GiB**；**0=明确无磁盘** |
| hypervisor | string | 是 | null | trim 后非空或 null；长度 ≤255 code point；**一期无枚举** |
| metadata | — | — | — | **不接收、不暴露**：归 Resource 公共 metadata（§2.2/§3；DR-69） |

规则：
- **未知值存 null**，绝不以 0 代替；vcpu/memory_mb 的 0 非法（正整数），disk_gb=0 与 null 语义不同且可区分。
- **宿主校验**：host_resource_id 须同时满足存在、未软删、resource_type=BARE_METAL、与 VM 同 Cluster；任一不满足→**422**，`fields[].field="virtual_machine.host_resource_id"`（统一语义，不细分 code）。创建与换 Host 走同一校验。
- **换 Host**：PATCH `virtual_machine.host_resource_id` 换入另一 Host，仅限同 Cluster 且未软删 BARE_METAL；写 UPDATE Audit（before/after host_resource_id）；只改登记关系，不真实迁移（§9/§22）。**Host 写路径与 Host 软删路径须对目标 Host 行 `SELECT ... FOR UPDATE` 串行化（DR-71），避免检查后写入并发窗口。**
- **无容量超额校验**：不校验 VM 总 vcpu/memory_mb 是否超过 Host，不承担调度/容量准入（§9/T39）。
- **创建**：resource_type=VIRTUAL_MACHINE 时 virtual_machine 必须出现且 host_resource_id 必填非 null；vcpu/memory_mb/disk_gb/hypervisor 可省略/null→null。virtual_machine 整体省略、非 object、含未知键→422；含 metadata 键→422。
- **PATCH**：仅 VM 合法；子字段级 exclude_unset——省略=保持；host_resource_id 显式 null→422；vcpu/memory_mb/disk_gb/hypervisor 显式 null=清空为 null；virtual_machine 整体显式 null、非 object、含未知键→422（对象本身不可清空）。
- **互斥（对称）**：BARE_METAL 请求体出现 virtual_machine（含显式 null）→422；VIRTUAL_MACHINE 请求体出现 hardware（含显式 null）→422（§2.4）；两对象不共存，响应中另一方恒为 null。
- **响应**：virtual_machine = object（VM）| null（BARE_METAL）。对象含 host_resource_id、host{id,hostname}、vcpu、memory_mb、disk_gb、hypervisor；**不含独立 metadata 键**。host 为宿主 Resource 的 id 与 hostname 展示值（§2.1）；宿主此后被软删时详情仍展开其 id/hostname，不额外报错。
- **字符串口径**（DR-64/D01 §5.5）：trim 首尾空白→trim 后非空→禁控制字符（Cc/Cf，应用层；DB 为 ASCII backstop）→长度 ≤255 code point；空串/纯空白→**422（不转 null）**；区分大小写、保留展示；无枚举、不据值推导行为。
- **数值口径**：vcpu/memory_mb ≤0 或非整数→422；disk_gb <0 或非整数→422；disk_gb=0 接受。严格整数语义（不接受 "4"/true/1.5）。
- **错误 fields[].field** 用点路径，如 virtual_machine.host_resource_id、virtual_machine.vcpu。
- **校验顺序**：POST 401→403→body 形状/互斥(422)→cluster(422)→宿主校验(422)→hostname 唯一(409)→写 resource+detail 同事务→Audit→201；PATCH 401→403→body(422)→可见性(404)→宿主校验若变更(422)→version(409)→hostname 唯一(409)→写→Audit→200。

## 4. 分页/排序/过滤/模糊

分页 page≥1 默认1；page_size 1–100 默认20；越界/非整数 422。排序 sort∈{hostname,resource_type,role,status,created_at,updated_at} 默认 created_at；order∈{asc,desc} 默认 desc；非法 422；附 id 升序稳定；sort=hostname 按 hostname_key。过滤（AND，§25）：cluster=Cluster code（code_key 大小写不敏感精确；格式非法 422；不存在→空结果）；cluster_id=UUID（非 UUID 422）；host_resource_id=UUID（v3 新增；非 UUID 422；不存在的 UUID→空结果，非 404；与 type=VIRTUAL_MACHINE 组合用于 BareMetal Detail 列出其 VM，DR-67）；type=BARE_METAL|VIRTUAL_MACHINE（非法 422）；role/status=枚举精确（非法 422）。查询参数规范名 `type`（§25 示例），不提供 resource_type 别名；未列出参数忽略。模糊 q=hostname 大小写不敏感子串 ILIKE（不算 pg_trgm；A12 基础搜索入口，完整模糊/pg_trgm 归 F013）。条件仅作用于可见集合。**F005 不新增列表级 hardware 过滤/排序参数（I-1，不在范围；如需走变更控制）；F006 仅新增 host_resource_id 过滤，不新增 virtual_machine 排序/其它过滤参数。**

## 5. 软删可见性

列表 deleted∈{exclude,include,only} 默认 exclude；非法 422；include/only 需 VIEW_DELETED 否则 403 FORBIDDEN{reason:"permission"}。详情默认不可见软删对象；?deleted=true 需 VIEW_DELETED 否则 403；默认视图下软删返回 404（不泄露存在性）。Activity 对已删同理。

## 6. Endpoints

### 6.1 GET /api/v1/resources — READ（deleted=include|only 另需 VIEW_DELETED）
Query q/cluster/cluster_id/type/role/status/deleted/page/page_size/sort/order。成功 200 列表。错误 401/403/422/500。

### 6.2 POST /api/v1/resources — WRITE
Request cluster(必填 UUID 或 code)、hostname(必填 §2.1)、resource_type(必填)、role(可选默认 OTHER)、status(可选默认 UNKNOWN)、description(可选 null)、metadata(可选默认 {})、**hardware(可选；仅 BARE_METAL；见 §2.4)**、**virtual_machine(必填；仅 VIRTUAL_MACHINE；见 §2.5)**；未列/只读字段→422。成功 201 {"resource":Resource}（含 hardware 或 virtual_machine）；同事务写 detail（BARE_METAL hardware / VIRTUAL_MACHINE virtual_machine）+ CREATE Audit。cluster 缺失/不存在/已软删→422 details.fields[].field="cluster"（固定，不区分 404）。错误 401/403/409 CONFLICT{unique_conflict,field:"hostname"}/422（含 hardware/virtual_machine 非法、互斥 422、宿主校验 422）/500。校验顺序见 §2.5。

### 6.3 GET /api/v1/resources/{id} — READ
id=UUID（非 UUID 404）；Query deleted(bool 默认 false；true 需 VIEW_DELETED 否则 403)。成功 200 {"resource":Resource}。错误 401/403/404/500。

### 6.4 PATCH /api/v1/resources/{id} — WRITE
Body（exclude_unset，省略=保持不重置）：version(必填 int≥1)、hostname(可选，改后重检唯一)、role(可选；显式 null→422)、status(可选；显式 null→422)、description(可选；显式 null 清空)、metadata(可选；整值替换；显式 null→422)、**hardware(可选；BARE_METAL；子字段级 exclude_unset，见 §2.4)**、**virtual_machine(可选；VIRTUAL_MACHINE；子字段级 exclude_unset，见 §2.5)**；含 cluster/cluster_id/resource_type/只读字段→422。成功 200（含 hardware 或 virtual_machine）；version+1；写 UPDATE Audit（换 Host 记 before/after host_resource_id）。错误 401/403/404（不存在或已软删）/409 VERSION_CONFLICT/409 CONFLICT{unique_conflict,field:"hostname"}/422（含 hardware/virtual_machine 非法、互斥 422、宿主校验 422、host_resource_id 显式 null）/500。顺序 401→403→body(422)→可见性(404)→宿主校验若变更(422)→版本(409)→唯一(409)。

### 6.5 DELETE /api/v1/resources/{id} — DELETE_OBJECT
Query version(必填 int≥1)。软删（置 deleted_at、version+1、updated_at）；不级联；引用检查（F004 Resource 自身引用集为空，机制级；**F006 起 object_type="resource" 注册 resource←未删 VIRTUAL_MACHINE 反向检查：存在未删 VM 引用时删除 Host→409**）。成功 204；写 DELETE Audit。错误 401/403/404/409 VERSION_CONFLICT/409 CONFLICT{reference_exists,references}/422/500。顺序 401→403→对象(404)→version 校验(422)→版本(409)→引用(409)→软删。**删除 Host 时 details.reason="reference_exists"，references=[{object_type:"resource",object_id:<vm-uuid>,label:<vm-hostname>}]；被引用 VM 软删后放行（§21/T19/T23）。**

### 6.6 POST /api/v1/resources/{id}/restore — RESTORE
Query version(必填 int≥1)。置 deleted_at=null、version+1、updated_at；仅恢复自身不级联；重检唯一性与所属 Cluster 有效性（§21）；**恢复 VIRTUAL_MACHINE 时重检其 Host：host_resource_id 指向的 Resource 已软删/缺失→409，不覆盖新对象（§21/T24）**。成功 200；写 RESTORE Audit。错误 401/403/404（对象从不存在或调用者无 VIEW_DELETED）/409 CONFLICT{not_deleted}/409 VERSION_CONFLICT/409 CONFLICT{unique_conflict,field:"hostname"|dependency_deleted,conflicts:[{object_type:"cluster"|"resource",object_id}]}/422/500。顺序 401→403→查找(含软删,404)→未删则 409 not_deleted→版本(409)→依赖/唯一重检(409)→恢复。**VM 恢复依赖失败 details.conflicts=[{object_type:"resource",object_id:<host-uuid>}]；hostname 已被复用则 unique_conflict，二者不覆盖新对象。**

### 6.7 GET /api/v1/resources/{id}/activity — VIEW_ACTIVITY（全角色）
Query deleted(bool 默认 false；已删需 true+VIEW_DELETED)、page/page_size。返回 (object_type="resource",object_id=id) 审计 created_at 升序、同刻 id 升序。成功 200 {items:[ActivityItem],page,page_size,total}；ActivityItem{id,action(CREATE|UPDATE|DELETE|RESTORE),operator_user_id(UUID|null),operator_username,string,before_data(object|null),after_data(object|null),created_at}。只读无审计修改/删除入口（§22）。错误 401/403/404/422/500。

## 7. 并发与错误语义小结

乐观锁条件 UPDATE WHERE id AND version=:expected SET version=version+1；rowcount=0→对象仍可见则 409 VERSION_CONFLICT{current_version}，不可见/不存在则 404；无静默重试。唯一性：创建/改名冲突 409 CONFLICT{unique_conflict}；DB uq_resources_cluster_id_hostname_key 部分唯一兜底并发。删除/恢复冲突 409 CONFLICT。422=格式/字段非法（含 cluster 缺失/不存在/软删、role/status 显式 null、hostname 非法）；409=语义冲突。

## 8. Audit 一致性（D02 签核）

四类 action 各写一行 audit_logs；同事务（AuditService.record 业务 Service 内同 Session 一并 commit；异常一起 rollback，回滚不留 Audit，§22/A10）；快照白名单 {cluster_id,hostname,resource_type,role,status,description,metadata}，**v2 扩 hardware（BARE_METAL 为嵌套硬件对象含 hardware.metadata；VM 为 null）**，**v3 扩 virtual_machine（VIRTUAL_MACHINE 为嵌套对象含 host_resource_id、vcpu、memory_mb、disk_gb、hypervisor；BARE_METAL 为 null）；换 Host 记 UPDATE before/after host_resource_id**，不记敏感内容；object_type="resource"、object_id=Resource UUID；metadata 与 hardware 对象快照可 JSON 序列化；Activity 按 (object_type,object_id) 过滤；完整跨对象审计归 F015/F016。D02 复用 F003 §8/F002 §6，F005 无新增 D02 项。
