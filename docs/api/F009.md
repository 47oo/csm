## 1. 通用约定
- Base path /api/v1（§25），挂载同一 api_v1_router；路径 /api/v1/ip-pools。
- 认证：csm_session HttpOnly Cookie（复用 F002 DR-08）；未认证先于权限返回 401。
- 时间：ISO-8601 UTC（D01 §2）。
- 操作者：服务端从 request.state.operator 取，写 Audit 快照（§22）；请求体不接受操作者字段。
- CSRF：不安全方法沿用 F002 §2.1；GET/HEAD 不校验。
- IPPool 为独立可寻址对象（自身 UUID/version/软删/恢复/Activity，DR-102/DR-111）；归属 Network 经 network_id 关联；Network 本体不并入。

### 1.1 统一错误信封（复用 F002 §1.1）
`{ "error": { "code": "STRING_CODE", "message": "human readable", "details": {} } }`

### 1.2 错误码与 HTTP 映射（复用 F002 集 + F003/F008 CONFLICT；F009 仅新增 reason）

| HTTP | code | 触发 | details |
| --- | --- | --- | --- |
| 401 | AUTH_REQUIRED | 无有效会话 | {} |
| 403 | FORBIDDEN | 缺权限 / CSRF | {"reason":"permission"\|"csrf"} |
| 404 | NOT_FOUND | 不存在；或已软删且无 VIEW_DELETED；或未定义路径 | {} |
| 409 | VERSION_CONFLICT | 乐观锁过期 | {"current_version": int} |
| 409 | CONFLICT | 唯一/重叠/占用/恢复冲突 | 见下表 |
| 422 | VALIDATION_ERROR | 请求体/查询参数/恢复重检地址校验失败 | {"fields":[{"field":str,"message":str}]} |
| 500 | INTERNAL_ERROR | 未预期错误 | {} |

CONFLICT details.reason 枚举（复用 F003；F008 新增 range_overlap；F009 新增 address_in_use，不新增 code）：

| reason | 场景 | 附加字段 |
| --- | --- | --- |
| unique_conflict | 同 Network 未删 name（归一化键）冲突（创建/PATCH 改名/恢复重检） | field:"name" |
| range_overlap（复用 F008） | 同 Network 未删池闭区间重叠（含完全相同、共享端点；创建/PATCH/恢复重检） | field:"start_address"\|"end_address"；conflicts:[{object_type:"ip_pool",object_id,label,start_address,end_address}] |
| address_in_use（新，DR-110） | 新建/扩大 RESERVED、AUTO/MANUAL→RESERVED 后变更范围内存在未删 IP；或 RESTORE RESERVED 时范围内存在未删 IP；或 Network PATCH 设为已占用 gateway（含未绑定 Interface） | field∈{"start_address","end_address","allocation_mode","gateway"}；conflict_count:int（总数）；conflicts:[{object_type:"ip_address",object_id,address,bound:bool,interface_id:uuid\|null,resource_id:uuid\|null,resource_hostname:str\|null}]；conflicts_truncated:bool |
| not_deleted | 对未软删对象 restore | {} |
| dependency_deleted | 恢复重检：所属 Network 仍软删/缺失 | conflicts:[{object_type:"network",object_id}] |

- 错误码注册表以 docs/api/F002.md §1.2 为共享权威；F009 新增 `address_in_use` reason，并将 `range_overlap` 登记交叉引用（顺带闭合 F008-REV-03），无新 error code。
- **CONFLICT_PREVIEW_LIMIT**：服务端常量，默认 `100`，可经配置覆盖；作用于 `address_in_use` 的 `conflicts` 预览列表。`conflict_count` 为变更后范围内未删 IP 的**总数**；`conflicts` 至多返回 `CONFLICT_PREVIEW_LIMIT` 条；`conflicts_truncated=true` 表示被截断。完整明细由 F010 `GET /api/v1/ip-addresses`（network_id + 地址范围过滤）分页查询（I-5）。
- `range_overlap` 的 `conflicts` 为冲突池明细（同 Network 未删池数量有界，不设截断字段）。

### 1.3 权限（§23，复用 F002 §3）
列表/详情=READ；创建/更新=WRITE；删除=DELETE_OBJECT；查看已删除（deleted=include|only、详情 deleted=true）=VIEW_DELETED；恢复=RESTORE；Activity=VIEW_ACTIVITY（全角色）。服务端执行；前端隐藏不替代；未认证先于权限→401。

## 2. 字段契约与归一化

### 2.1 IPPool name（§4.1/§12，D01 §5.8，DR-103）
服务端 trim 首尾空白 → trim 后非空 → 禁控制字符（Unicode Cc/Cf，应用层；DB 为 ASCII backstop）→ 长度（Unicode code point）1–255。允许中文及其它 Unicode；允许内部普通空格且不自动合并；保留展示大小写。唯一：同 Network 未软删部分唯一 (network_id,name_key) WHERE deleted_at IS NULL；name_key=ASCII_lower(btrim(name))（仅 ASCII A-Z→a-z，非 ASCII 原样；应用禁 str.lower()，DB 禁 lower()，locale 无关）；软删后可复用；恢复重检冲突不覆盖新对象。跨 Network 同名允许。

### 2.2 其它字段
- network：创建必填；Network UUID；引用须存在、未软删，否则 422 field="network"；创建后不可改（PATCH 出现 network/network_id→422，DR-107）。
- start_address/end_address：创建必填；单个 IPv4 主机地址（PG inet，family=4 且 masklen=32；非 CIDR/掩码）；合法 IPv4；均属所属 Network 的 CIDR（越界→422）；start_address ≤ end_address（逆序→422）；start=end 允许（单地址池）。CIDR 包含由应用主校验 + DB 触发器 backstop 保证（DR-104/DB-D104）。
- allocation_mode：可选默认 MANUAL；∈{MANUAL,AUTO,RESERVED}；显式 null/非法→422。语义：AUTO 允许自动与手动；MANUAL 仅手动；RESERVED 禁止分配（分配执行 F010）。
- description：可选 nullable 文本；无长度上限。
- version：int≥1；创建默认 1；PATCH/DELETE/restore 必填。
- metadata：不接受、不暴露；请求含 metadata→422（作为未知字段）；响应不含（I-6）。

### 2.3 长度/数值口径（镜像 D01 §5.8 与 DB）
name 1–255；start/end IPv4 主机地址（family=4、masklen=32）；allocation_mode 16。错误 fields[].field 用点路径：network、name、start_address、end_address、allocation_mode、description。

### 2.4 省略语义（D01 §4）
创建省略非必填→默认/null；PATCH 字段省略=保持不重置（exclude_unset）；显式 null 仅清空 nullable（description）；必填/非 nullable 显式 null（network/name/start_address/end_address/allocation_mode）→422；不可变/只读字段（network、network_id、id、name_key、metadata、address_range）出现在请求体→422；未知字段→422。

## 4. 分页/排序/过滤
- 分页：page 整数 ≥1 默认 1；page_size 1–100 默认 20；越界/非整数→422。
- 排序：sort∈{name,start_address,end_address,allocation_mode,created_at,updated_at} 默认 created_at；order∈{asc,desc} 默认 desc；非法→422；附 id 升序稳定；sort=name 按 name_key。
- 过滤（AND）：
  - network_id=UUID（非 UUID→422；不存在→空结果）
  - allocation_mode∈{MANUAL,AUTO,RESERVED}（非法→422）
  - q=对 name 的大小写不敏感子串（trim 后空/纯空白视为未提供，不用 pg_trgm）
  - deleted∈{exclude,include,only} 默认 exclude
- 未列出参数忽略；条件仅作用于可见集合。

## 5. 软删可见性
列表 deleted∈{exclude,include,only} 默认 exclude；非法 422；include/only 需 VIEW_DELETED 否则 403 FORBIDDEN{reason:"permission"}。详情默认不可见软删对象；?deleted=true 需 VIEW_DELETED 否则 403；默认视图下软删返回 404（不泄露存在性）。Activity 对已删同理。

## 6. Endpoints

### 6.1 GET /api/v1/ip-pools — READ（deleted=include|only 另需 VIEW_DELETED）
Query network_id/allocation_mode/q/deleted/page/page_size/sort/order（§4）。成功 200 列表。错误 401/403/422/500。

### 6.2 POST /api/v1/ip-pools — WRITE
Request：network(必填 UUID)、name(必填 §2.1)、start_address(必填 §2.2)、end_address(必填 §2.2)、allocation_mode(可选默认 MANUAL)、description(可选 null)；未列/只读字段（含 metadata）→422。成功 201 {"ip_pool":IPPool}；同事务写 CREATE Audit。
错误：401/403 / 409 CONFLICT{unique_conflict,field:"name"} / 409 CONFLICT{range_overlap,field:"start_address",conflicts} / 409 CONFLICT{address_in_use,field:"allocation_mode",conflict_count,conflicts,conflicts_truncated} / 422（body、network 缺失/不存在/软删 field="network"、地址非法/越界 field="start_address"/"end_address"、mode 非法 field="allocation_mode"）/ 500。
**校验顺序**：401→403→body(422，含只读/未知字段)→network(422，含存在/未软删)→取 `_lock_network`（networks 行 FOR UPDATE）→地址格式/家属/属 CIDR/起≤止(422)→name 唯一(409 unique_conflict)→范围重叠(409 range_overlap)→RESERVED 占用(409 address_in_use)→写+Audit→201。
占用触发（POST）：仅当 allocation_mode=RESERVED 时对 [start_address,end_address] 检查；命中→409 address_in_use{field:"allocation_mode"}。
并发：写事务持有 networks 行锁（`_lock_network`）串行化与 Network 改 cidr/cluster、F010 分配。

### 6.3 GET /api/v1/ip-pools/{id} — READ
id=UUID（非 UUID→404）；Query deleted(bool 默认 false；true 需 VIEW_DELETED 否则 403)。成功 200 {"ip_pool":IPPool}。错误 401/403/404/500。

### 6.4 PATCH /api/v1/ip-pools/{id} — WRITE
Body（exclude_unset，省略=保持；含 version 必填 int≥1）：name(可选，改后重检唯一)、start_address(可选)、end_address(可选)、allocation_mode(可选；显式 null→422)、description(可选；显式 null 清空)；含 network/network_id/id/name_key/address_range/metadata/只读字段→422。
成功 200 {"ip_pool":IPPool}；version+1；写 UPDATE Audit（before/after）。当请求含 start_address/end_address/allocation_mode 时，事务内取 `_lock_network`（FOR UPDATE）。
错误：401/403/404 / 409 VERSION_CONFLICT / 409 CONFLICT{unique_conflict,field:"name"} / 409 CONFLICT{range_overlap,field:"start_address"|"end_address",conflicts} / 409 CONFLICT{address_in_use,field,conflict_count,conflicts,conflicts_truncated} / 422。
**校验顺序**：401→403→body(422)→可见性(404)→version(409)→（若含范围/mode，取 `_lock_network`）→地址格式/家属/属 CIDR/起≤止(422)→name 唯一(409)→范围重叠(409 range_overlap)→RESERVED 占用(409 address_in_use)→写+Audit→200。
**占用检查触发条件与 field 规则**（DR-110）：
- 变更后有效 allocation_mode ≠ RESERVED → 不做占用拒绝。
- 变更后有效 allocation_mode = RESERVED：
  - allocation_mode 由 AUTO/MANUAL 改为 RESERVED（mode 变更触发）→ 检查整个变更后 [start,end]；field="allocation_mode"。
  - 原 mode 已为 RESERVED 且未改 mode，仅范围变化：若范围**扩大**（start 变小或 end 变大）→ 检查变更后 [start,end]；field="start_address"（若仅 end 变大则 field="end_address"）；若范围**未扩大或缩小**→不检查。
  - 同时改 mode 与范围→按 mode 变更触发，field="allocation_mode"（检查覆盖整个变更后范围）。
- 缩小范围、RESERVED→AUTO/MANUAL、AUTO↔MANUAL 在满足其它约束后允许，不做占用拒绝（§12.1）。
- 变更后范围重叠检查独立于占用检查（先 overlap 后占用）。

### 6.5 DELETE /api/v1/ip-pools/{id} — DELETE_OBJECT
Query version(必填 int≥1)。软删（置 deleted_at、version+1、updated_at）；不级联；**不做 IP 分配来源引用检查**（§12/§21 例外，DR-108）；不回收、不删除已分配 IP。成功 204；写 DELETE Audit。
错误 401/403/404/409 VERSION_CONFLICT/422/500。
**顺序**：401→403→对象(404)→version 校验(422)→版本(409)→软删。

### 6.6 POST /api/v1/ip-pools/{id}/restore — RESTORE
Query version(必填 int≥1)。置 deleted_at=null、version+1、updated_at；仅恢复自身不级联；重检（§21）：同 Network name 唯一、所属 Network 未软删、起止仍属 Network CIDR、范围不重叠、RESERVED 另检占用冲突；失败不覆盖新对象。成功 200；写 RESTORE Audit。
错误 401/403 / 404 / 409 CONFLICT{not_deleted} / 409 VERSION_CONFLICT / 409 CONFLICT{unique_conflict,field:"name"} / 409 CONFLICT{dependency_deleted,conflicts:[{object_type:"network",object_id}]} / 422 VALIDATION_ERROR{field:"start_address"|"end_address"}（Network cidr 变更后软删池越界） / 409 CONFLICT{range_overlap,field:"start_address",conflicts} / 409 CONFLICT{address_in_use,field:"allocation_mode",conflict_count,conflicts,conflicts_truncated} / 500。
**优先级（确定性）**：401→403→查找(含软删,404)→未删则 409 not_deleted→版本(409)→name 唯一(409 unique_conflict) → Network 依赖(409 dependency_deleted) → **CIDR 包含重检(422)** → 范围重叠(409 range_overlap) → RESERVED 占用(409 address_in_use) → 恢复。
说明：name 复用优先于依赖失效与重叠；越界为 422（与创建/PATCH 地址越界同口径），DB 触发器 `trg_ip_pools_cidr_contains` 为兜底（越界 RESTORE 由应用先返回 422；DB 侧抛 restrict_violation 仅作为 backstop）。RESTORE RESERVED 的占用 field="allocation_mode"。

### 6.7 GET /api/v1/ip-pools/{id}/activity — VIEW_ACTIVITY（全角色）
Query deleted(bool 默认 false；已删需 true+VIEW_DELETED)、page/page_size。返回 (object_type="ip_pool",object_id=id) 审计 created_at 升序、同刻 id 升序。成功 200 {items:[ActivityItem],page,page_size,total}；ActivityItem{id,action(CREATE|UPDATE|DELETE|RESTORE),operator_user_id(UUID|null),operator_username(string),before_data(object|null),after_data(object|null),created_at}。只读无修改/删除入口（§22）。错误 401/403/404/422/500。

## 7. 并发与错误语义小结
- 乐观锁：条件 UPDATE WHERE id AND version=:expected SET version=version+1；rowcount=0→对象仍可见则 409 VERSION_CONFLICT{current_version}，不可见/不存在则 404；无静默重试。
- 范围不重叠：创建/改起止/恢复冲突 409 CONFLICT{range_overlap}；DB `excl_ip_pools_network_id_address_range`（EXCLUDE USING gist (network_id WITH =, address_range WITH &&) WHERE deleted_at IS NULL）并发兜底。
- 名称唯一：409 CONFLICT{unique_conflict}；DB `uq_ip_pools_network_id_name_key`（部分唯一 WHERE deleted_at IS NULL）兜底。
- CIDR 包含：应用 422；DB 触发器 `trg_ip_pools_cidr_contains`（BEFORE INSERT/UPDATE，对 networks 行 FOR KEY SHARE）兜底。
- 占用：409 CONFLICT{address_in_use}（F009 默认 `NullIpOccupancyProvider` 空集，F010 注册真实 `IpAddressOccupancyProvider`）。
- 锁域（DR-109）：POST 与 PATCH（含范围/mode）、RESTORE 及 Network gateway 变更与 F010 分配共用 `_lock_network`（networks 行 FOR UPDATE）。
- Network gateway 占用挂钩：`network.update_network` 在 gateway 变更且非空时先 `_lock_network` 再调用 occupancy provider；占用→409 address_in_use{field:"gateway"}（F009 空集不触发，F010 端到端）。
- 422=格式/字段/形状非法或恢复重检地址越界；409=语义冲突。

## 8. Audit 一致性（§22/D02）
四类 action 各写一行 audit_logs；同事务（业务 Service 内同 Session 一并 commit，异常一起 rollback，回滚不留 Audit）；object_type="ip_pool"、object_id=IPPool UUID；快照白名单 {network_id,name,start_address,end_address,allocation_mode,description}；UPDATE 记 before/after；不记敏感内容。Activity 按 (object_type,object_id) 过滤；完整跨对象审计归 F015/F016。

## 9. 业务边界
F009 交付 IPPool 独立对象与 /api/v1/ip-pools 7 端点，及可被 F010/F013 复用的池范围与 allocation_mode 语义，并定义占用检查接口/Network 行锁域/冲突返回结构。不实现 IP 分配与容量数值（F010/F013）、Endpoint/Service（F011/F012）、CSV/Excel 导入（F014）、全局搜索/Dashboard（F013）、完整 Audit（F015）；不做 IPv6/DHCP/路由/防火墙/VLAN 划分/网段发现/实时监控。Pool 不落 metadata/status/auto_allocate/IP 列表；不因 RESERVED 自动创建 IP 或 Endpoint；不由名称/范围推断地址分类。未定义路径/方法 404/405；id 非 UUID 404；不引入 pg_trgm/GIN。I-3 收紧建池范围限制属新业务限定，待用户裁定，不在本 Feature 实现。F010 须复用 `_lock_network` 并注册真实 `IpOccupancyProvider`（跨 Feature 协议，I-5）。

## F027 范围语义（加法引用）

自 F027 起，本 Contract 的列表、详情、Activity 与写路径受 `docs/api/F027.md` 的范围附录约束：非 ADMIN 仅能访问已授权 Cluster 内对象；列表 `items`/`total` 与分页同谓词；未授权对象详情/写路径返回 404 `NOT_FOUND`；请求体显式引用未授权/不可选 Cluster 或父对象返回 422 `VALIDATION_ERROR`；范围校验先于唯一性/重叠/引用检查，不通过 409 泄露。本文件端点、字段、错误码、权限矩阵与版本冲突语义不变。
