## 1. 通用约定

- Base path `/api/v1`（§25），挂同一 `api_v1_router`。
- 认证：`csm_session` HttpOnly Cookie（复用 F002 DR-08）；未认证先于权限返回 401。
- 时间：ISO-8601 UTC（D01 §2）。
- 只读：两端点均为 `GET`，无请求体、无 CSRF 校验、无写副作用、不产生 Audit（§22/A21）。重复调用幂等。
- 操作者：不适用（无写）。

### 1.1 统一错误信封（复用 F002 §1.1）
```json
{ "error": { "code": "STRING_CODE", "message": "human readable", "details": {} } }
```

### 1.2 错误码与 HTTP 映射（复用 F002 集；F013 不新增 code / reason）

| HTTP | code | 触发 | details |
| --- | --- | --- | --- |
| 401 | `AUTH_REQUIRED` | 无有效会话 | `{}` |
| 403 | `FORBIDDEN` | 缺权限（`deleted=include/only` 无 VIEW_DELETED） | `{"reason":"permission"}` |
| 422 | `VALIDATION_ERROR` | 查询参数校验失败（q 空/超长、type 非法、page/page_size 越界/非整数、deleted 非法） | `{"fields":[{"field":str,"message":str}]}` |
| 500 | `INTERNAL_ERROR` | 未预期错误 | `{}` |

- 不新增 error code 或 CONFLICT reason；错误码注册表以 F002 §1.2 / §1.2.1 为共享权威。
- `field` 使用查询参数名（`q`/`type`/`deleted`/`page`/`page_size`）。
- 校验顺序：401 → 403 → 参数 422 → 查询 → 200（V26/B13）。

### 1.3 权限（§23，复用 F002 §3）
- `GET /api/v1/search`、`GET /api/v1/dashboard`：READ，VIEWER / EDITOR / ADMIN 全部允许。
- 搜索 `deleted∈{include,only}` 另需 VIEW_DELETED（ADMIN），否则 403 `FORBIDDEN{reason:"permission"}`。
- `deleted=exclude`（默认）不受 VIEW_DELETED 约束。
- 无新增/修改/删除/恢复端点（§23；不得出现写入口）。

### 1.4 与各域列表的关系（I-17，DR-185）
- 本 Contract 只新增 `/api/v1/search`；各 DONE 域列表（F003/F004/F008/F009/F010/F011/F012）的 `q` 继续使用现有 `ILIKE` 子串实现，**行为语义不变、不追溯修改**。
- `/api/v1/search` 与各域列表 `q` 是不同接口、不同匹配实现：前者为跨对象全局入口（pg_trgm + 归一化键），后者为域内单对象过滤。
- 未来统一升级为 pg_trgm 须走 `docs/project/change-control.md`。
- **F018 不变项**：F018（全局搜索字段组合展示 → 本文件 v2）仅扩展 `resource` 行的展示字段（`resource.related`/`resource.related_total`，见 §2.9），**不**改变本 §1.4 的列表契约收敛；各域列表 `q` 仍保持现有 `ILIKE` 子串实现，行为语义不变、不追溯修改。

## 2. `GET /api/v1/search` — READ

### 2.1 查询参数

| 参数 | 类型 | 必填 | 默认 | 规则 |
| --- | --- | --- | --- | --- |
| q | string | 是 | — | trim 后非空、长度 1–255（Unicode code point）；空/纯空白/超长→422 field="q"；按目标列归一化键分别匹配（§2.6） |
| type | enum | 否 | 全部 | ∈{resource, cluster, ip_address, service}；非法→422 field="type" |
| deleted | enum | 否 | exclude | ∈{exclude, include, only}；非法→422 field="deleted"；include/only 需 VIEW_DELETED 否则 403 |
| page | int | 否 | 1 | ≥1；越界/非整数→422 field="page" |
| page_size | int | 否 | 20 | 1–100；越界/非整数→422 field="page_size" |

- `q` 整体作为一个查询串，不做 OR 拆词；空查询不返回全量、不 500（I-13/A9）。
- 空结果返回 200 空列表（I-3），不返回 404/500。
- 结果集上限由 `page_size`（1–100）与 `total` 计数约束，无无界返回（I-2/§28）。
- 不提供 `sort`/`order` 参数；排序固定（§2.4）。

### 2.2 响应对象（200）

```json
{
  "items": [ SearchItem, ... ],
  "page": 1,
  "page_size": 20,
  "total": 42
}
```

**SearchItem**（判别字段 `object_type`）

| 字段 | 类型 | nullable | 说明 |
| --- | --- | --- | --- |
| object_type | enum | 否 | resource \| cluster \| ip_address \| service |
| id | string(UUID) | 否 | 稳定 ID（§4）；跳转依据 |
| matched_field | enum | 否 | hostname \| address \| code \| name |
| matched_value | string | 否 | 命中展示值（原值，不改写） |
| resource | object | 是 | 承载/命中 Resource；见下 |
| cluster | object | 是 | 命中 Cluster；见下 |
| ip_address | object | 是 | 命中 IPAddress；见下 |
| service | object | 是 | 命中 Service；见下 |

嵌套对象：

| 对象 | 字段 |
| --- | --- |
| resource | id(UUID)、hostname(string)、resource_type(BARE_METAL\|VIRTUAL_MACHINE)、role(string)、status(string)、cluster{id,code,name}、related[SearchResourceRelated]、related_total(int≥0)。后两字段见 §2.9：仅 `object_type="resource"` 行填充；非 resource 行嵌套 `resource` 的 `related`/`related_total` 恒为 `null` |
| cluster | id(UUID)、code(string)、name(string)、status(ACTIVE\|INACTIVE) |
| ip_address | id(UUID)、address(string,点分十进制)、network{id,name}、interface{id,name}\|null |
| service | id(UUID)、name(string)、status(RUNNING\|STOPPED\|UNKNOWN) |

按 `object_type` 填充规则（其余嵌套字段为 null；字段集不因查询变化，便于前端判别）：

| object_type | 填充 | matched_field | 依据 |
| --- | --- | --- | --- |
| resource | resource | hostname | §17/§33/A2/A10 |
| cluster | cluster | code \| name | §17/§19/A6 |
| ip_address | ip_address +（绑定则 resource，未绑定 null） | address | §13/§33/A4/A5 |
| service | service + resource（承载 Resource） | name | §15/§33/A7 |

- `cluster` 命中的 `matched_field` 判定：`code_key` 命中取 `code`，否则 `name` 命中取 `name`；两者皆命中取 `code`（确定性）。
- `resource` 行仅由 hostname 命中产生；IP/Service 命中不合成额外 `resource` 行，而是各自嵌入 `resource`（§2.3）。

### 2.3 去重与排序（I-11 定稿，DR-174/DR-175）

- 去重键 `(object_type, id)`，同键仅一条。
- **采用 typed 行方案**：不为 `ip_address`/`service` 命中合成额外 `resource` 行；`resource` 行仅由 hostname 命中产生。IP/Service 行各自嵌入其 `resource`。
  - **定稿依据**：product §2.2 将「同一 Resource 多路径折叠为一条」记为 **PROPOSED**（非确认规则）；architecture §4.3/DR-174 给出 typed 行方案，§17/§33 的确认目的是「能找到对应 Resource」，类型化行同样满足且信息更完整、直接回答 §33「机器运行哪些 Service/某 IP 是哪台机器」。故由 Architect/Product 在 Contract 层面对 PROPOSED 默认作技术定稿，**不构成新增业务规则**，也不改变 §17/§33 的确认目的。
- 不同 Cluster 的同名 Resource / 同值 IP 为不同对象，不去重（§7/§14）。
- 排序：`similarity DESC`（精确命中记 1.0）→ `object_type` 序 `resource < cluster < ip_address < service` → `id ASC`；构成全序，分页稳定（V28/B9）。相似度不暴露。排序非参数化。

### 2.4 匹配语义（DR-173）

- **hostname**：对 `resources.hostname`（ASCII 小写归一化）trigram/子串匹配；返回 `resource`。
- **IP**：对 `ip_addresses.address` **精确匹配**（裸点分十进制整址，等值）；返回 `ip_address`；经 `interface→resource` 填 `resource`，未绑定填 null（不伪造归属，A5/I-6）。**非整址/带掩码输入不参与 IP 匹配**（不报错，仅不产生 `ip_address` 结果）。前缀/trigram 兜底**本期不采纳**（见 §8.5）。
- **Cluster**：对 `clusters.code_key`（ASCII 大写归一化）与 `clusters.name` 匹配；返回 `cluster`（A6）。
- **Service**：对 `services.name_key`（ASCII 小写归一化）匹配；返回 `service` + 承载 `resource`（A7）。
- 单次查询可同时返回多类结果；`type` 参数可收窄（仅保留指定 `object_type`）。

### 2.5 空查询与长度（I-13 定稿，DR-177）
- `q` 必填；服务端去首尾空白后必须非空。
- 空/纯空白 → 422 `VALIDATION_ERROR{fields:[{field:"q"}]}`；不返回全量、不 500。
- `q` trim 后长度（Unicode code point）1–255；>255 → 422 field="q"（V9/B1/B3）。

### 2.6 归一化（§4.1/§7，D01 §5/§5.1/§5.3/§5.10）
查询串按目标列分别归一化，且与唯一性同口径（仅 ASCII 折叠，禁用 `str.lower()`/`str.upper()`）：

| 目标列 | 归一化 | 与谁一致 |
| --- | --- | --- |
| `resources.hostname` | trim + ASCII A–Z→a–z | D01 §5.3 / DB-D36 |
| `clusters.code_key` | trim + ASCII a–z→A–Z | D01 §5.1 / DB-D22 |
| `clusters.name` | 原样（btrim 后比较） | 无归一化键（既有边界） |
| `services.name_key` | trim + ASCII A–Z→a–z | D01 §5.10 / DB-D130 |
| `ip_addresses.address` | 裸 IPv4 精确等值，不做文本归一化 | DB-D114 |

中文与内部普通空格保留、不自动合并（A3）。

### 2.7 业务边界
- Cluster 命中只返回 Cluster，不展开其下 Resources（I-12 定稿；导航至 §19 Cluster Detail）。
- 未绑定 Interface 的 IP 返回 `ip_address` 且 `resource=null`，不伪造归属（I-6/A5）。
- 默认软删隐藏（I-1/A8/A23）。
- SN / MAC / Role / GPU Model 无匹配路径、无 `type` 值（A24；本期不强制）。

### 2.8 错误
401 / 403（`deleted` 需 VIEW_DELETED）/ 422 / 500。校验顺序：401→403→参数 422→查询→200。

### 2.9 `resource` 行关联展示字段（F018，v2 新增）

> 仅 `object_type="resource"` 的**顶层结果行**携带下列字段；为**固定超集**，字段集与内容不随查询串或前端所选字段组合变化（A1/A9/A12）。不改匹配语义、结果集、去重（`(object_type,id)`）、顶层排序、分页与 `total`（A9）。只读、无审计（A10）。

**`resource.related`（数组）与 `resource.related_total`**

| 字段 | 类型 | nullable | 空语义 | 排序 | 上限/总数 |
| --- | --- | --- | --- | --- | --- |
| related | SearchResourceRelated[] | 否（resource 行） | 无已绑定 IP 时 `[]`，不伪造占位行（A5） | `interface.name COLLATE "C" ASC` → `ip_address.address ASC`（`inet` 数值序）→ `id ASC` | 最多 10 行 |
| related_total | int≥0 | 否（resource 行） | 无关联时为 `0` | — | 截断前关联总数；恒 `≥ len(related)`；超限时 `len(related)=10`、`related_total=总数`（A3/A6） |

**`SearchResourceRelated`**（每个已绑定 Interface 的 IPAddress 一行；`interface_id IS NULL` 的未绑定 IP 不出现，A8）

| 字段 | 类型 | nullable | 说明 |
| --- | --- | --- | --- |
| id | string(UUID) | 否 | 行身份 = IPAddress `id`（§4 稳定 ID）；排序末键 |
| interface | object | 否 | `{id(UUID), name(string), interface_type(string)}` |
| interface.interface_type | enum | 否 | ∈ `{PHYSICAL, VIRTUAL, BOND, BRIDGE, VLAN, LOOPBACK, OTHER}`（F007 七值，回显原值、不改写，B21） |
| ip_address | object | 否 | `{id(UUID), address(string 点分十进制)}` |
| network | object | 否 | `{id(UUID), name(string)}` |

- **挂载位置**：`related`/`related_total` 位于结果行的嵌套 `resource` 对象内（非顶层），与既有 `resource.cluster` 同级。
- **非 resource 行**：`object_type` ∈ `{cluster, ip_address, service}` 的响应**结构与展示不变**；其嵌套 `resource` 对象（`ip_address`/`service` 行存在时）的 `related` 恒为 `null`、`related_total` 恒为 `null`，不承载关联（A12/V14）。
- **软删口径**：关联（Interface / IPAddress / Network）随结果行 `deleted` 模式过滤——`exclude` 隐藏已软删关联；`include`/`only` 展示（端点既有 `VIEW_DELETED` 门控不变，无权限仍 403 `FORBIDDEN{reason:"permission"}`）；**不复用**对嵌入对象无条件 `include_deleted=True` 的 loader（§4/A7/A8）。
- **确定性**：排序构成全序，重复查询与分页稳定（A2）；`related_total` 与顶层 `total` 语义不同、不相加、不混用。
- **兼容性（加法兼容）**：仅新增字段；既有 `SearchItem` 与各嵌套对象字段名/语义、`matched_field`/`matched_value`、错误码（401/403/422/500）、权限与参数全部不变（A9/A12）。

## 3. `GET /api/v1/dashboard` — READ（I-14 定稿，DR-181）

### 3.1 查询参数

| 参数 | 类型 | 必填 | 默认 | 规则 |
| --- | --- | --- | --- | --- |
| page | int | 否 | 1 | ≥1；越界/非整数→422 field="page"（仅作用于 `networks.items`） |
| page_size | int | 否 | 20 | 1–100；越界/非整数→422 field="page_size" |

- 无 `deleted` 参数：计数与容量恒为未删口径（I-1/DR-180）。
- 无 `cluster_id` 过滤参数（I-8 未确认，不默认新增；DR-188）。
- 不提供 `sort`/`order`：`networks.items` 行序固定 `created_at DESC, id ASC`（沿用列表基线默认，保证分页稳定；`counts` 不受分页影响）。

字段说明：

| 字段 | 类型 | nullable | 说明 |
| --- | --- | --- | --- |
| counts.clusters | int≥0 | 否 | 未删 Cluster 数（含 INACTIVE） |
| counts.resources | int≥0 | 否 | 未删 Resource 总数（BARE_METAL + VIRTUAL_MACHINE） |
| counts.bare_metal | int≥0 | 否 | 未删 `resource_type=BARE_METAL` 数 |
| counts.virtual_machines | int≥0 | 否 | 未删 `resource_type=VIRTUAL_MACHINE` 数 |

- `counts` 与各域列表（`deleted=exclude`、无其它过滤）的 `total` 等价，便于交叉核对（V-DB-3）。
- `remaining` 为整数，**可为负，原样返回，不截断**（F010 DR-130 / §20）。

### 3.3 容量口径（只消费 F010 §6.9，不重算；DR-182，A14–A20）

- `capacity.allocatable_total` = Network 基础可用地址（§11.1 按前缀）− gateway − RESERVED 池范围 − 禁用地址（按集合去重）。
- `capacity.occupied` = 该 Network 下未删 IP 数（含未绑定 Interface、含池外手动地址）。
- `capacity.remaining` = `allocatable_total − occupied`（不设下限 0）。
- `auto_pools[].allocatable_total` = `|池范围 ∩ Network 可分配集合|`；`occupied` = 当前位于该交集的未删 IP 数（按当前地址、不按来源）；`remaining` = 差。
- 与 `GET /api/v1/networks/{id}/capacity`（F010 §6.9）**数值逐项一致**（A20；字段名一致，仅为 Dashboard 行的 `network` 附加 `cluster` 上下文）。
- 软删 Network 不出现在 `networks`；Network INACTIVE 仍出现且容量不清零；`status`/`auto_allocate` 与容量分别展示（A19）。
- 实现**复用** `app/services/ip_capacity.py` 的 `network_capacity` / `auto_pools_capacity`，不自行重算。

### 3.4 业务边界
- 不提供跨 Network 全局合计（I-16 定稿；不同 Cluster 可含相同地址，相加易误导）。
- 不是监控面板：不返回实时 CPU/内存/流量/可达性/健康状态（§3/§20）。

### 3.5 错误
401 / 403 / 422 / 500。校验顺序：401→403→参数 422→聚合→200。

## 4. 软删可见性
- 搜索：`deleted∈{exclude,include,only}` 默认 `exclude`；`include/only` 需 VIEW_DELETED，否则 403 `FORBIDDEN{reason:"permission"}`；非法值 422。
- Dashboard：无 `deleted` 参数，恒为未删口径。
- 搜索结果中的软删对象（`include/only`）仍返回相同条目结构；已删对象不改变去重/排序规则。
- F018 关联（`resource.related`）随结果行 `deleted` 模式过滤，口径与上列一致：`exclude` 不展示已软删 Interface/IPAddress/Network；`include`/`only` 由既有 `VIEW_DELETED` 门控保护（§2.9/A7）。

## 5. 只读与权限
- 两端点只读，无写能力、无 Audit、无副作用（§22/A21）；重复调用幂等。
- 全角色可搜索与查看 Dashboard（§23/A22）；未认证 401；查看已删限 ADMIN（仅搜索）。
- F018 为纯只读派生展示扩展：不新增端点/参数/权限/错误码，不产生 Audit，重复调用幂等（§2.9/A10）。
