# F013 用户与角色管理 — API Contract

> Status: **READY**
> Document Type: API Contract（唯一字段清单）
> Feature: F013；依据 ADR-003（已批准 2026-09-25）、`requirements-v2.md` §4.9
> Base Path: `/api/v1`
> 错误媒体类型：`application/problem+json`

前后端以本文件为准。字段类型使用 OpenAPI 3.1 词汇；`string(date-time)` 为 RFC 3339 UTC。

---

## 0. 通用约定

- 认证：HttpOnly Cookie `csm_session`（HTTP-only，无 `Secure`）。未认证 → `401`。
- 权限：用户管理端点仅 `admin`；越权 → `403 FORBIDDEN`，数据不变。
- 首登改密：`must_change_password=true` 时，除 `GET /auth/me`、`POST /auth/change-password`、`POST /auth/logout` 外，均返回 `403 PASSWORD_CHANGE_REQUIRED`。
- 枚举：
  - `Role = "viewer" | "maintainer" | "admin"`
  - `UserStatus = "enabled" | "disabled"`
- 用户名：**仅允许字母与数字、长度 1–128**，区分大小写；**创建后不可修改**（BQ-W/BQ-X）。
- 分页：`page`（int，默认 1，≥1）、`page_size`（int，默认 20，1–100）；返回 `total`。排序 `sort`，允许 `username` / `-username` / `created_at` / `-created_at`，默认 `username`。

### Problem+json（所有 4xx/5xx）
```json
{
  "type": "about:blank",
  "title": "string",
  "status": 422,
  "code": "VALIDATION_ERROR",
  "message": "string",
  "errors": [
    { "field": "password", "code": "PASSWORD_POLICY", "message": "口令至少 8 位且包含字母与数字" }
  ]
}
```
`errors` 可空/缺省。`code` 取值见各端点。

### 错误码总表
| code | HTTP | 语义 |
| --- | --- | --- |
| `INVALID_REQUEST` | 400 | 请求体/参数格式非法 |
| `VALIDATION_ERROR` | 422 | 字段级校验失败 |
| `INVALID_CREDENTIALS` | 401 | 未知账号或口令错误（统一文案） |
| `UNAUTHENTICATED` | 401 | 无有效会话 |
| `FORBIDDEN` | 403 | 角色不足 |
| `ACCOUNT_DISABLED` | 403 | 账号已禁用（凭据正确） |
| `PASSWORD_CHANGE_REQUIRED` | 403 | 首登须先改密 |
| `INVALID_CURRENT_PASSWORD` | 400 | 自助改密时当前口令错误 |
| `USER_NOT_FOUND` | 404 | 用户不存在 |
| `USERNAME_TAKEN` | 409 | 用户名被仍存用户或历史用户占用（不复用） |
| `VERSION_CONFLICT` | 409 | 乐观锁冲突 |
| `LAST_ADMIN` | 409 | 禁止删除或禁用最后一个启用中的平台管理员 |

## 2. 认证与会话

### 2.1 POST `/auth/login`
- 权限：匿名。
- Request：
```json
{ "username": "string", "password": "string" }
```
  | 字段 | 类型 | 必填 |
  | --- | --- | --- |
  | username | string | 是 |
  | password | string | 是 |
- Response `200`：`CurrentUser`；`Set-Cookie: csm_session=<opaque>; Path=/; HttpOnly; SameSite=Lax`。
- 错误：`422 VALIDATION_ERROR`（缺字段/空值）；`401 INVALID_CREDENTIALS`（未知账号或口令错误，统一文案）；`403 ACCOUNT_DISABLED`（凭据正确但禁用）。
- 业务边界：禁用/未知/错误口令均**不建立会话、不创建/修改业务数据**（场景 72、73）。未知账号与错误口令返回相同 401。

### 2.2 POST `/auth/logout`
- 权限：任意已登录（无会话时也返回 204，幂等）。
- Request：无 body。
- Response `204`；`Set-Cookie: csm_session=; Path=/; Max-Age=0`。
- 语义：撤销当前会话（场景 74）。

### 2.3 GET `/auth/me`
- 权限：任意已登录。
- Response `200`：`CurrentUser`。
- 错误：`401 UNAUTHENTICATED`。

### 2.4 POST `/auth/change-password`
- 权限：任意已登录（含 `must_change_password=true`）。
- Request：
```json
{ "current_password": "string", "new_password": "string" }
```
  | 字段 | 类型 | 必填 |
  | --- | --- | --- |
  | current_password | string | 是 |
  | new_password | string | 是 |
- Response `204`。
- 错误：`400 INVALID_CURRENT_PASSWORD`（当前口令错误）；`422 VALIDATION_ERROR`（`new_password` 不满足策略：≥8 位且含字母与数字）。
- 语义：成功后清除 `must_change_password`；旧口令失效；`PROPOSED` 使该用户其它会话失效（场景 78 自助部分）。

## 3. 用户管理（仅 admin；越权 403）

### 3.1 GET `/users`
- Query：
  | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | page | integer | 否 | 默认 1 |
  | page_size | integer | 否 | 默认 20，1–100 |
  | q | string | 否 | 用户名包含匹配（去首尾空格） |
  | role | Role | 否 | 角色过滤 |
  | status | UserStatus | 否 | 状态过滤 |
  | sort | string | 否 | 默认 `username` |
- Response `200`：`PagedUsers`。
- 边界：无匹配 → `200` + `items: []`、`total: 0`。
- 错误：`401`、`403 FORBIDDEN`。

### 3.2 POST `/users`
- Request：
```json
{ "username": "string", "password": "string", "role": "viewer|maintainer|admin" }
```
  | 字段 | 类型 | 必填 |
  | --- | --- | --- |
  | username | string | 是 |
  | password | string | 是（初始口令，须满足策略） |
  | role | Role | 是 |
- Response `201`：`UserDetail`。
- 错误：`422 VALIDATION_ERROR`（用户名非“仅字母与数字”或长度不在 1–128；口令策略）；`409 USERNAME_TAKEN`（仍存或历史用户名占用，大小写敏感、不复用）。
- 语义：写入 `reserved_usernames`；`status=enabled`；`PROPOSED` 新建用户 `must_change_password=true`（场景 75）。

### 3.3 GET `/users/{user_id}`
- Path：`user_id` integer。
- Response `200`：`UserDetail`。
- 错误：`404 USER_NOT_FOUND`。

### 3.4 PATCH `/users/{user_id}`
- Request（`version` 必填；**用户名不可修改**，仅可改角色）：
```json
{ "role": "viewer|maintainer|admin", "version": 3 }
```
  | 字段 | 类型 | 必填 |
  | --- | --- | --- |
  | role | Role | 否 |
  | version | integer | 是（乐观锁） |
- Response `200`：`UserDetail`（`version` 已自增）。
- 错误：`400 INVALID_REQUEST`（无可改字段或请求含不可改字段 `username`）；`409 VERSION_CONFLICT`；`404 USER_NOT_FOUND`；`422`。
- 语义：仅角色可变；角色变更后新操作按新角色鉴权（场景 76）。用户名创建后不可修改（BQ-X）。

### 3.5 DELETE `/users/{user_id}`
- Query：`version`（integer，必填，乐观锁）。
- Response `204`。
- 错误：`409 VERSION_CONFLICT`；`409 LAST_ADMIN`（目标为最后一个启用中的管理员）；`404 USER_NOT_FOUND`。
- 语义：移除账号、不能登录；`sessions` 删除；`reserved_usernames` 与 `audit_log` 保留 → 用户名不复用、历史审计保留（场景 77）。最后一个启用中的平台管理员不得删除（BQ-X）。其它用户与业务数据不受影响。

### 3.6 POST `/users/{user_id}/disable`
- Request：无 body。
- Response `204`（幂等：已禁用仍 204）。
- 错误：`404 USER_NOT_FOUND`；`409 LAST_ADMIN`（目标为最后一个启用中的管理员）。
- 语义：禁止登录、保留用户记录、可重新启用（场景 79）；最后一个启用中的平台管理员不得禁用（BQ-X）。

### 3.7 POST `/users/{user_id}/enable`
- Request：无 body。
- Response `204`（幂等）。
- 错误：`404 USER_NOT_FOUND`。

### 3.8 POST `/users/{user_id}/reset-password`
- Request：
```json
{ "new_password": "string" }
```
  | 字段 | 类型 | 必填 |
  | --- | --- | --- |
  | new_password | string | 是（须满足策略） |
- Response `204`。
- 错误：`422 VALIDATION_ERROR`；`404 USER_NOT_FOUND`。
- 语义：旧口令失效、新口令可登录；其它用户口令不受影响；`PROPOSED` 使该用户既有会话失效并置 `must_change_password=true`（场景 78 重置部分）。

## 4. 业务边界汇总

| 边界 | 结果 |
| --- | --- |
| 空用户列表 | `200`，`items: []`，`total: 0` |
| 不存在的用户（详情/修改/删除/禁用/启用/重置） | `404 USER_NOT_FOUND` |
| 用户名与仍存用户重复 | `409 USERNAME_TAKEN` |
| 用户名与**已删除历史**用户重复 | `409 USERNAME_TAKEN`（不复用） |
| 非管理员调用任意 `/users*` | `403 FORBIDDEN`，数据不变 |
| 未登录访问受保护资源 | `401 UNAUTHENTICATED` |
| 并发编辑同一用户 | `409 VERSION_CONFLICT`，前端保留输入 |
| 首登未改密访问其它接口 | `403 PASSWORD_CHANGE_REQUIRED` |
| 删除或禁用最后一个启用中的管理员 | `409 LAST_ADMIN`，数据不变 |

## 5. 角色枚举说明
角色为固定枚举 `viewer/maintainer/admin`（运维查看者/资源维护者/平台管理员）。不提供角色 CRUD 接口（`NOT_REQUIRED`：三角色由产品固定，`requirements-v2.md` §2.1）。前端负责中英文展示映射。
