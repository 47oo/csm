## 1. 通用约定

- Base path `/api/v1`，挂同一 `api_v1_router`（§25）。
- 认证：`csm_session` HttpOnly Cookie（复用 F002）；未认证先于权限返回 401。
- 操作者：服务端从 `request.state.operator` 取；写 Audit 的 operator 快照（§22）；请求体不接受操作者字段。
- CSRF：写入端点沿用 F002 §2.1（Origin/Sec-Fetch-Site）；预校验与模板语义只读但仍按实现同源校验处理。
- 时间：ISO-8601 UTC；本 Feature 响应不含时间戳（审计行可经 Activity 查看）。
- 错误信封：`{"error":{"code":str,"message":str,"details":{}}}`（复用 F002 §1.1）。

### 1.1 权限

| 端点 | Capability | VIEWER | EDITOR | ADMIN |
| --- | --- | --- | --- | --- |
| `POST /imports/resources/validate` | `IMPORT` | 403 | 允许 | 允许 |
| `POST /imports/resources` | `IMPORT` | 403 | 允许 | 允许 |
| `GET /imports/resources/templates` | `READ` | 允许 | 允许 | 允许 |

- `IMPORT` 已登记于 `docs/api/F002.md` v1 §3 权限矩阵，本 Feature 不新增 capability。
- 未认证 401 `AUTH_REQUIRED` 先于权限；已认证缺权限 403 `FORBIDDEN{reason:"permission"}`；CSRF 失败 403 `FORBIDDEN{reason:"csrf"}`（F002 §2.1）。
- 前端隐藏不替代服务端校验（§23/§24-4）。

### 1.2 错误码（本 Feature 新增 4 码，已登记 F002 §1.2）

| HTTP | code | 触发 | details |
| --- | --- | --- | --- |
| 413 | `IMPORT_FILE_TOO_LARGE` | 文件字节数 > `import_max_file_bytes`（解析前拦截） | `{"limit_bytes": int}` |
| 413 | `IMPORT_ROW_LIMIT_EXCEEDED` | 数据行数 > `import_max_rows`（解析后、校验前拦截） | `{"limit_rows": int}` |
| 422 | `IMPORT_INVALID_FILE` | 不可解码/损坏/非 `.xlsx`（含 `.xls`）/空数据行/表头或列不符 | `{"reason": str, "missing_columns": [str]?, "unknown_columns": [str]?}` |
| 422 | `IMPORT_VALIDATION_FAILED` | 写入端点存在行错误（整批回滚） | `{"total_rows": int, "importable_rows": int, "error_count": int, "errors": [RowError], "errors_truncated": bool}` |

- `IMPORT_INVALID_FILE.details.reason` 取值：`unreadable`、`unsupported_format`、`header_missing`、`missing_columns`、`unknown_columns`、`column_order`、`empty_file`。
- `RowError` = `{"row": int(1-based 文件行号), "field": str(模板列名), "reason": str, "related_row": int|null}`。
- 复用既有码：401 `AUTH_REQUIRED`、403 `FORBIDDEN`（reason=`permission`|`csrf`）、422 `VALIDATION_ERROR`（`format` 缺失/非法）、500 `INTERNAL_ERROR`。
- 4 个新码为独立 error code，非 `CONFLICT`，**不进入 F002 §1.2.1 reason 注册表**。

## 2. 请求

`validate` 与 `resources` 两端点共用的 `multipart/form-data`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | binary | 是 | CSV（UTF-8，兼容 BOM）或 `.xlsx`（OOXML，仅 `.xlsx`） |
| `format` | string | 是 | `csv` 或 `xlsx`（大小写不敏感） |

- 校验顺序：认证(401) → 权限(403) → `format` 形状(422 `VALIDATION_ERROR{fields:[{field:"format"}]}`) → 文件大小(413) → 解析(422 `IMPORT_INVALID_FILE`) → 行数(413) → 表头/列(422) → 逐行校验。
- 文件不落盘、服务端不保存临时文件；写入端点接收同一文件并完整重校验。
- 上限：`import_max_file_bytes`（默认 **5,242,880**）、`import_max_rows`（默认 **5000**）、`import_error_preview_limit`（默认 **1000**）。

## 3. `POST /api/v1/imports/resources/validate` — 预校验

- 权限 `IMPORT`；**无副作用、幂等、不写 Audit、不加锁**（I-3/DR-206）。
- 成功 200（合法解析，含行错误）：

```json
{
  "format": "csv",
  "total_rows": 12,
  "importable_rows": 10,
  "error_count": 3,
  "errors": [
    {"row": 4, "field": "cluster",  "reason": "cluster does not exist or is not selectable", "related_row": null},
    {"row": 7, "field": "hostname", "reason": "duplicate hostname within file (also at row 2)", "related_row": 2},
    {"row": 7, "field": "host",     "reason": "host must be an existing, undeleted BARE_METAL resource in the same cluster", "related_row": null}
  ],
  "errors_truncated": false
}
```

| 字段 | 类型 | nullable | 说明 |
| --- | --- | --- | --- |
| `format` | string | 否 | 规范化后的请求格式（`csv`/`xlsx`） |
| `total_rows` | int | 否 | 数据行数（不含表头） |
| `importable_rows` | int | 否 | `total_rows - 出现错误的数据行数` |
| `error_count` | int | 否 | 错误项全量计数（非截断后条数） |
| `errors` | RowError[] | 否 | 聚合行错误；`errors_truncated=true` 时最多 `import_error_preview_limit` 条 |
| `errors_truncated` | bool | 否 | `error_count > import_error_preview_limit` 时为 true |

- 文件级致命 → 4xx（§1.2），无 `errors` 列表。
- 错误：401/403；413；422 `IMPORT_INVALID_FILE`/`VALIDATION_ERROR`；500。

## 4. `POST /api/v1/imports/resources` — 写入

- 权限 `IMPORT`；同一事务再次校验；整批成功或整批回滚，回滚不留 Resource/明细/Audit/Activity（I-1/I-8）。
- 成功 201：`{"created": 10, "total_rows": 10}`；每行同事务写一条 CREATE Audit（§22）。
- 存在行错误（校验或并发归因）→ 422 `IMPORT_VALIDATION_FAILED`，`details` 携带同一聚合错误列表；**整批回滚**，无部分成功：

```json
{"error": {"code": "IMPORT_VALIDATION_FAILED", "message": "Import validation failed",
  "details": {"total_rows": 12, "importable_rows": 10, "error_count": 3,
              "errors": [{"row": 4, "field": "cluster", "reason": "…", "related_row": null}],
              "errors_truncated": false}}}
```

- 错误：401/403；413 `IMPORT_FILE_TOO_LARGE`/`IMPORT_ROW_LIMIT_EXCEEDED`；422 `IMPORT_INVALID_FILE`/`IMPORT_VALIDATION_FAILED`/`VALIDATION_ERROR`；500。
- 写入顺序：解析+表头校验 → 上限 → 逐行只读校验（批内重复/现存冲突/Host 批外快照）→ 无错误则插入阶段（逐行 SAVEPOINT + Host `FOR UPDATE` + flush + Audit staging）→ 全部成功 `commit`，否则 `rollback`。

## 5. `GET /api/v1/imports/resources/templates` — 模板规范（A25）

- 权限 `READ`；只读、无 Audit、幂等。
- 成功 200：

```json
{
  "templates": [
    {
      "resource_type": "BARE_METAL",
      "columns": [
        {"name": "cluster", "required": true, "target": "resource.cluster",
         "type": "string", "unit": null, "enum": null,
         "description": "Cluster code (case-insensitive) or UUID; must exist and be undeleted",
         "example": "N96P"},
        {"name": "memory_mb", "required": false, "target": "hardware.memory_mb",
         "type": "integer", "unit": "MiB", "enum": null,
         "description": "Physical memory; empty = unknown (null)", "example": "262144"}
      ]
    },
    {
      "resource_type": "VIRTUAL_MACHINE",
      "columns": [
        {"name": "host", "required": true, "target": "virtual_machine.host_resource_id",
         "type": "string", "unit": null, "enum": null,
         "description": "Hostname (or UUID) of an existing, undeleted BARE_METAL host in the same cluster",
         "example": "cn001"}
      ]
    }
  ]
}
```

| 列描述字段 | 类型 | nullable | 说明 |
| --- | --- | --- | --- |
| `name` | string | 否 | 冻结列名（§6） |
| `required` | bool | 否 | 是否必填 |
| `target` | string | 否 | 目标字段点路径 |
| `type` | string | 否 | `string`\|`integer`\|`enum` |

## 6. 模板列集（D03 冻结）

表头第 1 行，数据自第 2 行；两套固定模板；列名/顺序/必填/类型/单位/枚举冻结（DR-198）。

| 5 | `status` | 否 | resource.status | enum | 同 §6.1；空→`UNKNOWN` |
| 6 | `host` | 是 | virtual_machine.host_resource_id | string | 同 cluster 内**已存在、未软删、BARE_METAL** 的 Host 的 `hostname`（或 UUID）；**批外已存在**（§9/I-9） |
| 7 | `vcpu` | 否 | virtual_machine.vcpu | int | 正整数 1..2147483647 或空(=null) |
| 8 | `memory_mb` | 否 | virtual_machine.memory_mb | int **MiB** | 正整数 1..2147483647 或空(=null) |
| 9 | `disk_gb` | 否 | virtual_machine.disk_gb | int **GiB** | 非负整数 0..2147483647 或空(=null)；**0=明确无磁盘** |
| 10 | `hypervisor` | 否 | virtual_machine.hypervisor | string ≤255 | trim 后非空或空(=null)；一期无枚举 |

### 6.3 模板级约束

- 表头须与冻结模板**列名、顺序完全一致**；缺失必填列、多出未定义列、列序不符 → 422 `IMPORT_INVALID_FILE`（`missing_columns`/`unknown_columns`/`header_missing`/`column_order`），**不静默忽略、不按名重排**。
- 同一文件同一模板（一行一 `resource_type`）；BM 行出现 VM 专属列、VM 行出现 hardware 列 → 行/模板错误，与 F004 §2.4/§2.5 互斥 422 同口径。
- 模板不含 `metadata`/`description`（DR-200）；导入对象取默认（`metadata={}`、`description=null`）。
- 枚举取**大写规范值**，非规范值报错；可选列空/纯空白 = 省略（默认值生效；非必填→null），必填列空 = 行错误（DR-199）。

## 7. 解析与逐行校验

- **CSV**：Python 标准库 `csv`，UTF-8（兼容 BOM `utf-8-sig`），逗号分隔；引号内换行按**逻辑记录号**计行号（DR-194）。
- **`.xlsx`**：`openpyxl`（`read_only=True, data_only=True`），取**首个工作表**；不执行公式/宏；`.xls`/非 xlsx → `IMPORT_INVALID_FILE{unsupported_format}`。
- **逐行校验复用同一 Service Layer**：cluster 解析（`resolve_cluster`，批内缓存）、hostname 归一化与唯一（`normalize_hostname`/`hostname_key`）、type/enum/缺省、VM Host 四条件——与 F004 `create_resource` **完全同源**；导入层仅把空单元格按 DR-199 先归一为「省略」再进入服务层，**禁止直写 SQL/ORM 旁路**（A14/DR-202）。
- **行号约定**：1-based 文件行号，表头为第 1 行，数据自第 2 行；`field` 取模板列名（DR-194）。
- **引用解析**：`cluster`→`cluster_id`、`host`→`host_resource_id`（UUID 落库，不拼接字符串，I-14）。

## 8. 原子性、再次校验与并发

- **单事务**：写入端点在同一 DB 事务内完成「解析 → 再次校验 → 逐行创建 → Audit → commit」。
- **行级归因 + 全批回滚**：逐行 `db.begin_nested()`（SAVEPOINT）；某行 DB 失败（并发唯一/FK/触发器）→ 回滚该 SAVEPOINT、记录行错误；迭代结束若有错误 → `db.rollback()` 整批回滚；否则一次 `db.commit()`（DR-203/DR-206）。
- **写入前再次校验**：写入请求重新上传同一文件，服务端不留临时文件；基于事务内最新状态重跑全部校验（I-4）。**文件内重复**在插入前校验期检测并报两行行号（`related_row`）。
- **Host 批外已存在**：VM Host 仅从写入事务开始前的库快照解析；本批（含更早行）新建 BM 不进入解析集合（I-9/DR-205）。
- **并发**：hostname 唯一由 DB 部分唯一 `uq_resources_cluster_id_hostname_key` 兜底；VM Host 行 `FOR UPDATE` 与 Host 软删串行化（复用 F004 DR-71）；预校验 `lock=False` 只读。Cluster 软删窗口与 F004 `POST /resources` 同口径，导入不额外收紧（DB FK 保证引用行存在）。

## 10. D03 专业设计签核（Architect；Backend/Tester 复核项）

**签核结论**：固定模板（§6）、VM Host 引用列（§6.2 第 6 列）、逐列说明（§5/§6）、同步导入上限（本节）与性能依据，由 Architect 在本 CONTRACT Gate 签核；不改变 §24 已确认规则。

| 参数 | 签核值 | 依据 |
| --- | --- | --- |
| `import_max_file_bytes` | **5,242,880**（5 MiB） | 解析前拦截；5000 行 × 14 列短字符串文件通常 ≪1 MiB，5 MiB 留冗余；bounds 内存型 `read_only` xlsx 解析 |
| `import_max_rows` | **5000** | 同步处理上限；单行成本为常数级索引点查（cluster 批内缓存 + hostname 唯一 + host）+ 一次三表 INSERT，O(rows)；Database 裁定既有索引可承载（无新索引） |
| `import_error_preview_limit` | **1000** | 有界错误响应；`error_count` 仍为全量计数，`errors_truncated` 表截断 |
| 超限错误码 | 413 `IMPORT_FILE_TOO_LARGE`/`IMPORT_ROW_LIMIT_EXCEEDED` | 解析前/校验前拒绝，无部分导入 |

**性能验证义务（交 TEST）**：数值作为契约值生效；TEST 阶段须以**真实 PostgreSQL**产出证据：①接近 5000 行的导入耗时/内存基线；②上限处拒绝时延与「无部分导入」断言；③预览截断行为。若证据显示上限不安全，走 `docs/project/change-control.md` 变更控制修订本 Contract。

## F027 范围语义（加法引用）

自 F027 起，本 Contract 的列表、详情、Activity 与写路径受 `docs/api/F027.md` 的范围附录约束：非 ADMIN 仅能访问已授权 Cluster 内对象；列表 `items`/`total` 与分页同谓词；导入预校验与写入按行执行范围校验，范围外行返回行号/字段/原因并使整批失败；未授权对象详情/写路径返回 404 `NOT_FOUND`；请求体显式引用未授权/不可选 Cluster 或父对象返回 422 `VALIDATION_ERROR`；范围校验先于唯一性/重叠/引用检查，不通过 409 泄露。本文件端点、字段、错误码、权限矩阵与版本冲突语义不变。

## CSV 文本载体（加法引用）（增补节 v1，独立于上文正文版本）

本节只新增一层**载体**语义，不修改上文任何端点、字段、错误码、上限、权限或响应形状。前端导入面板自 F034 起提供两种**并列**载体：上传文件（含 `.xlsx`）与粘贴 CSV 文本；文件载体行为完全不变。

- **载体只决定 multipart `file` 部分的产生方式**：文本载体在前端把粘贴的文本按 UTF-8 编码构造为一个带固定文件名的 `File`，随既有 `POST /api/v1/imports/resources/validate` 与 `POST /api/v1/imports/resources` 的 multipart 提交；请求仍恰为 `file`（binary）+ `format`（string），wire 形状、multipart 字段名与顺序语义不变。
- **文本编码**：按 UTF-8 编码提交；前端不添加 BOM（若文本本身以 `U+FEFF` 开头则原样提交，服务端按 `utf-8-sig` 解码）；前端不做本地归一化（不 trim 内容、不改行尾、不转义、不补尾部换行）。浏览器文本控件可能把行尾呈现为 LF，服务端按 §7 的同一逻辑记录切分口径处理 CRLF / LF / 混用。
- **表头与分隔符**：文本必须自带与 §6 冻结模板**逐字逐序一致**的表头；仅逗号分隔；不做分隔符嗅探（制表符分隔的粘贴内容不被受理）、不自动补表头、不按列名重排、不做列名大小写折叠。不合规时按既有 `422 IMPORT_INVALID_FILE` 的 `header_missing` / `missing_columns` / `unknown_columns` / `column_order` / `empty_file` 原因拒绝，不静默忽略、不修补。
- **`format` 固定**：文本载体恒使用 `format=csv`（前端该字段只读）；不提供 `.xlsx` 的文本载体，`format` 取值语义与既有校验顺序（401 → 403 → `format` 形状 422 → 大小 413 → 解析 422 → 行数 413 → 表头/列 422 → 逐行）不变。
- **上限**：字节上限按文本 **UTF-8 编码后的字节数**适用 §10 的同一签核值 `import_max_file_bytes`（5,242,880，严格大于才拒绝）；行数上限与文件载体一致为 `import_max_rows`（5000）。数值不变更、不新增配置项。前端允许对空/纯空白内容与字节超限做**非权威**前置拦截（不发请求）；行数上限不在前端镜像，一律以服务端 413 为权威。
- **等价性**：逐字节相同的 CSV 字节，经文件载体与文本载体提交时，预校验与写入的行为、响应字段、`RowError`（`row` / `field` / `reason` / `related_row`）、行号口径、错误码与 `IMPORT_INVALID_FILE.details.reason` 集合完全一致。服务端判定始终为权威。
- **不变项（逐项维持原文）**：端点与方法、请求字段（`file` / `format`）、响应 Schema（`format` / `total_rows` / `importable_rows` / `error_count` / `errors` / `errors_truncated`；写入 `created` / `total_rows`）、§1.2 错误码与 `reason` 集合、§10 上限数值、1-based 行号与表头为第 1 行、`RowError` 形状、`IMPORT` / `READ` 权限矩阵与 401/403 顺序、§「F027 范围语义（加法引用）」的范围校验与行级拒绝、CSRF 同源校验、预校验无副作用与幂等（不加锁、不写 Audit）、写入整批成功/整批回滚与再校验、每对象 CREATE Audit。
- **不新增**：不新增 Endpoint、查询参数、请求字段、响应字段、错误码、`reason` 取值、上限或配置项；不新增权限项；不改模板列集与列序；不改变行号或 `related_row` 口径；不改变两步流程。
- **不留痕**：粘贴内容不落盘、不入库，不写入 Audit、日志或错误响应（服务端请求体处理沿用既有文件上传边界）。
