## 1. 通用约定

- **Base path**：`/api/v1`，挂同一 `api_v1_router`（§25 CONFIRMED）。
- **双认证载体**：同一 API 集合同时接受两类凭据 —— `csm_session` HttpOnly Cookie（F002）**或** `Authorization: Bearer <API Key>`（本 Feature）。不废除、不削弱 Cookie；同一端点两种载体均可调用。
- **Bearer 格式**：`Authorization: Bearer csm_ak_<token>`。`scheme` 大小写不敏感；凭据明文 = 前缀 `csm_ak_` + `secrets.token_urlsafe(32)`（43 字符）；服务端仅按 `hashlib.sha256(明文).hexdigest()`（64 位小写 hex）等值查找，不存明文。
- **载体优先级**：请求携带 Bearer（scheme 合法、token 非空）→ 走 API Key 路径且**忽略 Cookie**；否则走 Cookie 路径。非 Bearer 的 `Authorization` 头（如 `Basic`）原样忽略（保持 F002 既有行为）。缺失/格式非法/前缀不符/哈希不匹配一律 401。
- **CSRF 交互**：`GET` 免 CSRF；`POST` 仅在「不安全方法 **且** 携带 `csm_session` **且 无 `Authorization: Bearer`** **且** 非同源」时执行 F002 §2.1 同源校验（403 `FORBIDDEN{reason:"csrf"}`）。Bearer 请求免除同源校验；纯 Cookie 请求的 CSRF 行为逐字不变。
- **时间**：ISO-8601 带偏移、UTC（如 `2026-10-14T08:00:00+00:00`）；存储 timestamptz（D01 §2）。
- **错误信封**：复用 F002 §1.1 `{"error":{"code","message","details"}}`；`message` 不泄露凭据/账号存在性/堆栈；`details` 无附加信息时为 `{}`。
- **错误码**：复用 F002 §1.2，**不新增 error code**；新增 `CONFLICT` reason `already_revoked`，登记于 F002 §1.2.1（本文件 §4.6 定义）。
- **401 先于 403**：未认证 401 `AUTH_REQUIRED` 先于权限判定 403 `FORBIDDEN{reason:"permission"}`。

### 1.1 错误码与 HTTP 映射

| HTTP | code | 触发（本 Feature 相关） | details |
| --- | --- | --- | --- |
| 401 | `AUTH_REQUIRED` | 缺失/格式非法/哈希不匹配/已吊销/已过期 API Key；绑定账号非 ACTIVE；无有效 Cookie 且无有效 Bearer | `{}` |
| 403 | `FORBIDDEN` | 已认证但缺 `USER_ADMIN`；Cookie 请求同源校验失败 | `{"reason":"permission"\|"csrf"}` |
| 404 | `NOT_FOUND` | 详情/吊销的 `id` 非 UUID 或不存在 | `{}` |
| 409 | `CONFLICT` | 吊销已吊销 Key | `{"reason":"already_revoked"}` |
| 422 | `VALIDATION_ERROR` | 请求体/查询参数校验失败 | `{"fields":[{"field":str,"message":str}]}` |
| 500 | `INTERNAL_ERROR` | 未预期服务端错误（不含堆栈/凭据） | `{}` |

### 1.2 权限矩阵（§23 复用，不新增权限项/角色）

| 端点 | Capability | VIEWER | EDITOR | ADMIN |
| --- | --- | --- | --- | --- |
| `GET /api/v1/api-keys` | `USER_ADMIN` | 拒绝(403) | 拒绝(403) | 允许 |
| `GET /api/v1/api-keys/{id}` | `USER_ADMIN` | 拒绝(403) | 拒绝(403) | 允许 |
| `POST /api/v1/api-keys` | `USER_ADMIN` | 拒绝(403) | 拒绝(403) | 允许 |
| `POST /api/v1/api-keys/{id}/revoke` | `USER_ADMIN` | 拒绝(403) | 拒绝(403) | 允许 |
| 任意已受保护业务端点（带 API Key） | 绑定账号对应 Capability | 按 VIEWER | 按 EDITOR | 按 ADMIN |

- 服务端强制鉴权；前端隐藏不替代。
- API Key 身份等于绑定账号，权限为其角色权限逐行执行，不产生新语义、不支持 scope-down（§23.1）。
- 校验顺序：401（未认证）→ 403（已认证缺权限）→ 其余。

## 2. ApiKeyRow 对象（列表/详情/创建/吊销共用）

| 字段 | 类型 | nullable | 说明 |
| --- | --- | --- | --- |
| `id` | string(UUID) | 否 | `api_keys.id`（`gen_random_uuid()`） |
| `user_id` | string(UUID) | 否 | 绑定账号 `users.id` |
| `username` | string | 否 | 绑定账号 username |
| `label` | string | 否 | 可读标签，1..255 code point |
| `status` | string enum | 否 | 派生：`revoked_at != null` → `REVOKED`；否则 `expires_at <= now` → `EXPIRED`；否则 `ACTIVE`（REVOKED 优先于 EXPIRED） |
| `created_at` | string(ISO-8601 UTC) | 否 | 创建时间 |
| `expires_at` | string(ISO-8601 UTC) | 否 | 过期时间（创建时确定，不可改） |
| `revoked_at` | string(ISO-8601 UTC) | 是 | `null` 表示未吊销 |
| `created_by` | string(UUID) | 否 | 创建人 `users.id` |
| `created_by_username` | string | 否 | 创建人 username |

- **绝不包含 `key_hash` 或明文**。所有响应永不含二者。
- 追加字段 `plaintext` 仅出现在创建 201 响应（§4.3），其余任何端点/出口不返回。

## 3. 分页 / 排序 / 过滤基线

- 分页：`page` ≥1 默认 1；`page_size` 1–100 默认 20；越界/非整数 → 422 `VALIDATION_ERROR{fields}`。
- 空结果：200 `{items:[],page,page_size,total:0}`。
- 排序（仅列表）：`sort ∈ {created_at,expires_at,label}` 默认 `created_at`；`order ∈ {asc,desc}` 默认 `desc`；非法 → 422。同刻以 `id` 升序稳定。
- 过滤（仅列表）：`user_id`（UUID，可选）、`status`（`ACTIVE|REVOKED|EXPIRED`，可选，按派生状态过滤）、`q`（label 大小写不敏感子串；`trim` 后为空或 >255 code point → 422）。条件 AND。

## 4. Endpoints

### 4.1 `GET /api/v1/api-keys` — 列表

- 权限：`USER_ADMIN`。
- 查询参数：`user_id`、`status`、`q`、`page`、`page_size`、`sort`、`order`（见 §3）。
- 成功 200：

```json
{"items":[{
  "id":"…uuid","user_id":"…uuid","username":"user01","label":"ci-runner",
  "status":"ACTIVE","created_at":"2026-10-14T08:00:00+00:00",
  "expires_at":"2027-01-12T08:00:00+00:00","revoked_at":null,
  "created_by":"…uuid","created_by_username":"admin"
}],"page":1,"page_size":20,"total":3}
```

- 错误：401、403、422、500。校验顺序 401→403→422→200。

### 4.2 `GET /api/v1/api-keys/{id}` — 详情

- 权限：`USER_ADMIN`。
- `id` 非 UUID 或不存在 → 404 `NOT_FOUND`。
- 成功 200：`{"api_key": ApiKeyRow}`（不含 `key_hash`/明文）。
- 错误：401、403、404、500。校验顺序 401→403→404→200。

### 4.3 `POST /api/v1/api-keys` — 创建

- 权限：`USER_ADMIN`。
- Request：

| 字段 | 类型 | nullable | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| `user_id` | string(UUID) | 否 | 是 | 须引用存在且 `status='ACTIVE'` 的账号；不存在/非 UUID/非 ACTIVE → 422 `VALIDATION_ERROR{fields:[{field:"user_id",message:…}]}` |
| `label` | string | 否 | 是 | `trim` 后非空、禁控制字符（Unicode Cc/Cf）、长度 1..255 code point；空/纯空白/超长/含控制字符 → 422；**不要求唯一** |
| `validity_days` | integer | 否 | 否（缺省=90） | 整数 1..365（含端点）；显式 `null`/`0`/负值/`>365`/非整数 → 422；无「永不过期」取值 |

- 服务端语义：`expires_at` 由**同一事务内的数据库 `now()`**（`transaction_timestamp()`）派生，不提供永不过期。
- 成功 201：

```json
{"api_key":{
  "id":"…uuid","user_id":"…uuid","username":"user01","label":"ci-runner",
  "plaintext":"csm_ak_…",
  "status":"ACTIVE","created_at":"…","expires_at":"…","revoked_at":null,
  "created_by":"…uuid","created_by_username":"admin"
}}
```

- 一次性明文纪律：`plaintext` **仅此一次**返回；此后列表/详情/日志/审计/错误响应及数据库均不含明文或哈希（库仅存 `key_hash`）。
- 审计：同事务写 `object_type="api_key"` / `action="CREATE"`，after=`{user_id,label,expires_at,revoked_at:null}`（白名单不含 `key_hash`/明文）。
- 错误：401 `AUTH_REQUIRED`；403 `FORBIDDEN{reason:"permission"}`；422；500。校验顺序 401→403→422→201。

### 4.4 `POST /api/v1/api-keys/{id}/revoke` — 吊销（无请求体）

- 权限：`USER_ADMIN`。
- 成功 200：`{"api_key": ApiKeyRow}`，其中 `revoked_at` 已置、`status="REVOKED"`。
- 未知/非 UUID `id` → 404 `NOT_FOUND`。
- 已吊销 → 409 `CONFLICT{reason:"already_revoked"}`（不写审计、不改状态）。
- 已过期但未吊销 → 允许，置 `revoked_at`，返回 200 `status="REVOKED"`。
- 审计：成功时同事务写 `object_type="api_key"` / `action="UPDATE"`，before/after 仅 `revoked_at` 差异。
- 不提供重新启用；不提供更新/删除端点（`PUT`/`PATCH`/`DELETE` 对该路径 → 404/405）。
- 错误：401、403、404、409、500。校验顺序 401→403→404→409→200。

### 4.5 非端点声明

- `PATCH /api/v1/api-keys/{id}`、`DELETE /api/v1/api-keys/{id}`、`POST /api/v1/api-keys/{id}/restore`、`POST /api/v1/api-keys/{id}/enable` 均不提供（404/405）。

## 5. 一次性明文与脱敏纪律

- 明文 `csm_ak_…` 只在创建 201 出现一次；列表 / 详情 / 吊销 / 日志 / 审计 / 错误响应均无明文或等价可还原凭据。
- DB 仅存 `key_hash`（SHA-256 hex）；无明文列。
- `SENSITIVE_FIELDS` 覆盖 `api_key`、`api_key_hash`、`key_hash`、`plaintext`、`bearer`（`authorization` 已存在）；`api-keys` 端点不记录请求体。

## 6. 审计语义

- `object_type="api_key"`：登记于本契约并同步 F015 object_type 注册表（F015 v2 §2.1/§6）。
- `AUDITABLE_FIELDS["api_key"]` = `("user_id","label","expires_at","revoked_at")`（不含 `key_hash`/明文）。
- 创建 `action="CREATE"`；吊销 `action="UPDATE"`（revoked_at 状态变更）；不新增 §22 action 取值；与业务写同事务提交。
- 使用 API Key 的写操作：Audit `operator_username` = 绑定账号 username，`api_key_label` = 该 Key 标签（`audit_logs.api_key_label`，可空，无 FK，快照语义）。Cookie/system 路径 `api_key_label` 为 NULL。

## 7. 数据库依赖（权威见 `docs/database/f017-api-key.md` v1）

本契约依赖以下 DB 保证（DB-D301–DB-D316）：

- `api_keys` 表：`id`/`user_id`/`label`/`key_hash`/`created_by`/`created_at`/`expires_at`/`revoked_at`；无 `deleted_at`/`version`/`last_used_at`；不继承 `SoftDeleteMixin`（DR-305/DB-D301）。
- `key_hash varchar(64) NOT NULL` + `uq_api_keys_key_hash` + `ck_api_keys_key_hash_format`（`^[0-9a-f]{64}$`）；认证等值查找 O(1)（DR-309/DB-D304）。
- `label varchar(255) NOT NULL` + not-blank CHECK；`btrim(label) <> ''`（DB-D305）。
- 时间 CHECK：`expires_at > created_at`、`revoked_at IS NULL OR revoked_at >= created_at`；backstop `ck_api_keys_expires_within_max` = `expires_at <= created_at + interval '365 days' + interval '5 minutes'`（DB-D306/DB-D307）。`created_at` 为 `server_default now()`；服务端须以 DB 事务 `now()` 派生 `expires_at`，使 365 天边界精确成立；`+5 minutes` 为时钟偏差容差，不放宽应用侧 `>365 → 422` 权威上限。
- `user_id`、`created_by` FK → `users.id` `ON DELETE RESTRICT`；索引 `ix_api_keys_user_id`、`ix_api_keys_created_by`（DB-D303）。
- `audit_logs.api_key_label varchar(255) NULL` + nullable-safe not-blank CHECK；无 FK；既有行自动 NULL；append-only 触发器不变（DB-D309/DB-D310/DB-D311）。
- 迁移 `0014_api_keys`（`down_revision=0013_search_indexes`，单 head；upgrade 建表→索引→增列→增 CHECK，downgrade 逆序）（DB-D312）。
- 认证逐请求读取已提交状态，无缓存/无惰性清理；吊销提交后后续请求即 401（DR-307）。

## 8. 业务边界

- 缺 Key、格式非法、哈希不匹配、已吊销、已过期、绑定账号 DISABLED → 一律 401 `AUTH_REQUIRED`，响应等价、不泄露凭据/账号存在性。
- 401 先于 403：带无效 Key 调 ADMIN 端点 → 401（非 403）。
- 使用 API Key 的受保护请求身份等于绑定账号；`/auth/me` 亦然。
- `POST /auth/login`、`POST /auth/logout` 仍为 Cookie 流程；带 API Key 调 `logout` 为无害 no-op（清理 Cookie，不影响 Key）。
- 创建 Key 不改变绑定账号状态。
- 未定义路径/方法 → 404/405。
