## 1. 通用约定

- Base path `/api/v1`，三端点挂同一 `api_v1_router` 现有 `imports` router。
- 认证：`csm_session` HttpOnly Cookie 或 `Authorization: Bearer <API Key>`（复用 F002 §1）；未认证先于权限返回 401。
- 操作者：服务端从 `request.state.operator` 取；写 Audit 快照（§22）；请求体不接受操作者字段。
- CSRF：写入端点 `POST /imports/resource-interfaces-ips` 沿用 F002 §2.1；`validate` 为 POST，按 F014 同源口径；`templates` 为安全方法。
- 时间：ISO-8601 UTC；响应不含时间戳。
- 错误信封：`{"error":{"code":str,"message":str,"details":{}}}`（复用 F002 §1.1）。
- **错误码全部复用 F014/F002，本 Feature 不新增任何 error code，不改 F002 §1.2 注册表。**

## 2. 请求
`validate` 与写入共用 `multipart/form-data`：
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | binary | 是 | CSV（UTF-8，兼容 BOM）或 `.xlsx`（仅 OOXML `.xlsx`） |
| `format` | string | 是 | `csv` 或 `xlsx`（大小写不敏感） |

- 校验顺序：401 → 403 → `format` 形状(422 `VALIDATION_ERROR`) → 文件大小(413) → 解析(422 `IMPORT_INVALID_FILE`) → 行数(413) → 表头/列(422) → 逐行/分组校验。
- 文件不落盘；写入端点接收同一文件并完整重校验。
- 上限复用 F014：`import_max_file_bytes`=5,242,880、`import_max_rows`=5000、`import_error_preview_limit`=1000；不新增设置。

## 3. `POST /imports/resource-interfaces-ips/validate` — 预校验
权限 `IMPORT`；无副作用、幂等、不写 Audit、不加锁。成功 200：
```json
{"format":"csv","total_rows":5,"importable_rows":3,"error_count":2,
 "errors":[{"row":4,"field":"ip","reason":"…","related_row":null}],"errors_truncated":false}
```
`total_rows`=数据行数；`importable_rows`=`total_rows`−错误行数；`error_count`=全量计数；`errors` 聚合（`errors_truncated=true` 时最多 `import_error_preview_limit` 条）。文件级致命→4xx，无 `errors`。错误：401/403；413；422 `IMPORT_INVALID_FILE`/`VALIDATION_ERROR`；500。

## 4. `POST /imports/resource-interfaces-ips` — 写入
权限 `IMPORT`；同一事务再校验；整批成功或整批回滚（无 Resource/Interface/IPAddress/Audit/Activity 残留）。成功 201：
```json
{"created":3,"total_rows":5,"interfaces_created":4,"ip_addresses_created":5}
```
- `created`=**新建 Resource 对象数**：按 `(cluster,hostname)` 合并后、按 §8.1 二态判定为「新建」的组数；**向既有 Resource 追加的组不计入**，因此纯追加批次整批成功时 `created=0`（成功信号，不是失败或空批次；不新增响应字段）。`interfaces_created`=去重后新建 Interface 数（含在既有 Resource 下新建的 Interface）；`ip_addresses_created`=新建 IP 数（成功时 == `total_rows`）。
- 每成功对象同事务各写一条 CREATE Audit。
- 存在行错误 → 422 `IMPORT_VALIDATION_FAILED`（`details` 同上聚合），整批回滚、无部分成功。
- 错误：401/403；413；422 `IMPORT_INVALID_FILE`/`IMPORT_VALIDATION_FAILED`/`VALIDATION_ERROR`；500（含死锁兜底）。
- 写入顺序：解析+表头 → 上限 → 逐行/分组只读校验 → 无错误则按 §12.3 锁序在 SAVEPOINT 外一次性取锁 → 按资源组 SAVEPOINT 写入（Resource→Interface→IPAddress，含 Audit staging）→ 全成功 commit，否则 rollback。

### 6.1 逐行适用性
- BM 行：`host`/`vcpu`/`disk_gb`/`hypervisor` 必须空；硬件列 #11–#18 可填。
- VM 行：硬件列 #11–#18 必须空；`host` 必填。
- `memory_mb`（#8）两类均可，按类型映射。
- 出现「不适用该行类型的非空列」→ 行错误，`field` 取该列名。
- 同文件允许 BM/VM 混排，逐行以 `resource_type` 判定。

### 6.2 三元组与省略语义
- 三元组必填：`cluster`、`hostname`、`resource_type`、`name`、`ip`。
- 可选列空/纯空白=省略（非必填→null，枚举/布尔取默认）；枚举取大写规范值；`enabled` 空→`true`、`interface_type` 空→`OTHER`、`role` 空→`OTHER`、`status` 空→`UNKNOWN`。
- 模板不含 `metadata`/`description`（Resource 取 `metadata={}`/`description=null`；Interface 取 `metadata={}`/`description=null`）；一期不含 `parent_interface`。

## 7. 解析与行号
- CSV：`csv` 标准库，UTF-8（兼容 BOM），逗号分隔；引号内换行按逻辑记录号计行号。
- `.xlsx`：`openpyxl`（`read_only`/`data_only`），取首个工作表；不执行公式/宏；`.xls`/非 xlsx → `IMPORT_INVALID_FILE{unsupported_format}`。
- 行号：1-based，表头第 1 行、数据自第 2 行；`field` 取模板列名。
- 逐行校验复用同一 Service Layer；导入层仅按省略语义归一空单元格，禁止直写 SQL/ORM 旁路。

## 8. 分组、合并与组内一致性

### 8.1 分组/合并与组键 → Resource 二态
- Resource：组键 `(cluster_id, hostname_key)` → 恰好 1 个**宿主** Resource，逐组按下列二态判定（仅统计 `deleted_at IS NULL` 的 Resource）：
  - **不存在**（含仅存在已软删行）→ **新建**：本组在该批内创建 1 个 Resource，计入 `created`。
  - **存在且未软删** → **追加**：本组以该 Resource 为宿主，仅在其下新建 Interface 与 IPAddress 并绑定；本批**不创建、不修改**该 Resource 的任何字段（不计入 `created`；不产生 `resource` UPDATE Audit / Activity；`version`、`updated_at` 不变）。
  - **已软删** → 按「不存在」处理：不得追加、不得复活，按新建处理并受 §14 的 hostname 唯一约束。
- 二态在**组级**判定：同组全部行共用同一判定，不存在「同组内部分行新建、部分行追加」。
- Interface：Resource 内键=归一化后 `name`（区分大小写）→ 恰 1 个 Interface（新建组与追加组同）。
- IPAddress：**每行 → 恰 1 个 IPAddress**，绑定该行所属 Interface（本批新建的 Resource 或既有 Resource 下本批新建的 Interface）。
- 同 Interface 多行=多 IP，**仅限本批新建的 Interface**；同 Resource 多 Interface 合法。
- 追加**不支持**向既有 Interface 再绑定 IP：行 `name` 命中宿主已存在未软删同名 Interface → 行错误 `field="name"`（§11）。

### 8.2 组内一致性
- Resource 组内资源级字段（`cluster/hostname/resource_type/role/status/host/vcpu/memory_mb/disk_gb/hypervisor/manufacturer/model/serial_number/cpu_model/cpu_sockets/cpu_cores/gpu_model/gpu_count`）：多行给出不同规范化值 → 行错误（`field` 取冲突列，`related_row` 指首个给出该字段的行）；相同/仅一处 → 取该值；均省略 → 默认/null。
- Interface 组内接口级字段（`interface_type/mac_address/speed_mbps/mtu/enabled`）：多行不同值 → 行错误（`related_row` 指前一处）；相同/仅一处/均省略 → 取值或默认。
- `resource_type` 组内不一致 → 冲突（`field="resource_type"`）。
- 比较以服务层归一化后的值为准。

## 9. Network 解析
对每行在该行 `cluster` 内解析 IP 所属 Network：
1. **`network` 列非空（优先，权威）**：先按 `name_key`（trim + ASCII `A-Z`→`a-z`）匹配未软删 Network `name`；无名称命中则解析为 CIDR 按**精确相等**匹配 `cidr`；均无命中 → 行错误（`field="network"`），**不回退**到 `/mask`。
2. **`network` 列空且 `ip` 含 `/mask`**：构造 `network_of(ip, mask)`，在同 Cluster 未软删 Network 中按 **CIDR 精确相等**匹配（不重叠故至多命中 1 行）；无命中 → 行错误（`field="ip"`）。
3. **两者皆缺**（`network` 空且 `ip` 无 `/mask`）→ 行错误（`field="network"`）。
- Network 必须已存在且未软删；不存在/软删 → 行错误；新建 IP 要求 `status=ACTIVE`，INACTIVE → 行错误；**不创建** Network/Pool/Cluster/Host。
- `ip` 必须落在解析 CIDR 内并满足 §11.1；`network` 列优先时仍校验 `ip ∈ CIDR`。
- **落库剥离掩码**：`address` 存 masklen=32 裸主机地址。
- 解析按 Network 批内缓存。

## 10. IP 与 Interface 校验
- IP（手动分配语义 §13.2/§14）：复用 `ip_capacity` 可分配集合（属 CIDR、非网络/广播、非 gateway、非 RESERVED、非禁用 5 段）；同 Cluster 未软删唯一（`uq_ip_addresses_cluster_id_address`）；绑定须同 Cluster；`ip_pool_id` 由所在未软删 Pool 推导（可空）；**不触发自动分配、不校验 auto_allocate、不消耗 Pool**。
- Interface：`normalize_interface_name`（trim/非空/无内部空白/无控制字符/≤64，区分大小写）；同资源未软删唯一；`interface_type` 默认 OTHER、不推断；`enabled` 默认 true；`mac/speed/mtu` 复用 F007；不含 `parent_interface`；`description=null`、`metadata={}`。

## 11. 文件内重复与现存冲突
- 同 `(cluster, ip)` 多行 → 行错误（`field="ip"`，报后出现行，`related_row`=先出现行）。
- 同 `(cluster, hostname)` 多行、同 `(resource, name)` 多行 → **非错误**（按 §8 合并/去重）。
- 现存 `(cluster, hostname)`：
  - 存在**未软删** Resource → **不报冲突**，该组按 §8.1「追加」处理；但组内显式给出的 Resource 级列（`resource_type`、`role`、`status`、`host`、`vcpu`、`memory_mb`、`disk_gb`、`hypervisor` 与硬件列）必须与宿主既有**规范化值**逐一相等，不一致时报行错误（`field` = 对应模板列名；`resource_type` 不一致同样是 `field="resource_type"`），不覆盖既有值；留空的 Resource 级列视为**省略、不参与比较、不把既有值置空**（因此既有的 `null` 值不能经导入补填）。
  - 仅存在**已软删** Resource → 按「不存在」新建（§8.1）。
  - 本版起**不再存在**「hostname 已存在」行错误（v1 该口径已被 §8.1 二态替代）；并发新建同 hostname 的唯一性仍由数据库部分唯一索引兜底并归因 `field="hostname"`（§12.5）。
- 追加组内 Interface 命中宿主**已存在、未软删、同名**（区分大小写）Interface → 行错误 `field="name"`；**不做幂等跳过、不自动忽略重复行、无部分成功**。
- 现存 `(cluster, ip)` 未软删 IPAddress 冲突 → 行错误 `field="ip"`（新建组与追加组同口径）。
- 其他非法行（枚举/整数/bool/长度/适用性/Network/Host 等）→ 行错误含行号/字段/原因。
- 文件内重复、现存冲突、二态判定与既有值一致性比较在预校验与写入再校验均执行，口径一致。
- **归因澄清（`F035-FU-01` / F036，2026-10-26，不升版）**：`RowError.field` 恒为冻结模板列名。① 追加组 Resource 级列与既有规范化值不一致 → `field` = 对应列名（`resource_type` 同样）；② 宿主在写入阶段因**并发软删 / 不再可选**导致资源侧锁定失败（`prepare_interface` 的 `_lock_resource`）→ `field="hostname"`（该行的资源标识列），`reason` 为服务层**自由文本**（当前实现取值 `resource does not exist or is not selectable`，见 §1.2 澄清；客户端与测试**不得逐字符依赖**），`related_row=null`；③ 数据库唯一约束兜底仍按 §12.5 归因（`uq_resources_cluster_id_hostname_key` → `hostname`）。三种情形一律整批 422 `IMPORT_VALIDATION_FAILED`、行号为 1-based 物理行号、零写入残留；不新增错误码、`IMPORT_INVALID_FILE.details.reason` 取值、响应字段或模板列。

## 12. 原子性、再校验、锁序与约束归因

### 12.1 单事务 + SAVEPOINT
- 写入在同一事务内「解析 → 再校验 → 插入 → Audit → commit」。
- 按资源组 `(cluster_id, hostname_key)` `begin_nested()`；组内顺序 Resource → Interface → IPAddress；每对象同事务写 CREATE Audit。
- 任一组任一错误 → 回滚该 SAVEPOINT 并归因 → 有错误则 `db.rollback()` 整批回滚，零残留；全成功才 commit。

### 12.2 写入前再次校验
- 写入重新上传同一文件，基于事务内最新状态重跑全部校验；覆盖预校验后状态变化窗口；冲突时 422 `IMPORT_VALIDATION_FAILED` 整批回滚，不静默覆盖。
- VM Host 仅从**批外快照**解析；本批新建 BM 不进入 Host 解析集合。

### 12.3 确定性锁序（吸收 F023-DB-01；v2 扩展 `resources` 预锁集合）
并发兜底：三个部分唯一索引（`uq_resources_cluster_id_hostname_key`、`uq_interfaces_resource_id_name`、`uq_ip_addresses_cluster_id_address`）+ `_lock_network`（`networks` 行 FOR UPDATE）+ VM Host FOR UPDATE。为避免跨批次 `40P01` 死锁，写入事务在**进入任何 SAVEPOINT 之前**按全局锁序一次性取锁：
1. 收集 ①本批全部 VM Host `resource_id`、②本批**全部追加宿主**（§8.1「存在且未软删」组）的既有 `resource_id`、③全部解析出的 `network_id`。
2. 固定表顺序 **先 `resources` 后 `networks`**，每表内按 `id` 升序、各以单条语句加锁：`SELECT ... FROM resources WHERE id IN (①∪②) ORDER BY id FOR UPDATE`；`SELECT ... FROM networks WHERE id IN (③) ORDER BY id FOR UPDATE`。追加宿主在后续 `prepare_interface` 内被同事务再次 `FOR UPDATE`，不改变既有锁序。
3. 锁在 SAVEPOINT 外获取，所有批次同序（新建组与追加组混排亦同序），消除锁环。
预校验只读、不加锁（`lock=False`）。

### 12.4 死锁兜底（40P01）
仍发生 `40P01` → 整批回滚（无部分写入）、**不静默重试**，返回 500 `INTERNAL_ERROR`（无新增错误码）；客户端可安全重传（整批成功或整批回滚，无残留）。

### 12.5 DB 约束归因（吸收 F023-DB-02）
SAVEPOINT 内 `IntegrityError` 映射为 RowError：
| 来源 | 归因字段 |
| --- | --- |
| `diag.constraint_name = uq_resources_cluster_id_hostname_key` | `hostname` |
| `diag.constraint_name = uq_interfaces_resource_id_name` | `name` |
| `diag.constraint_name = uq_ip_addresses_cluster_id_address` | `ip` |
| `diag.constraint_name ∈ {ck_ip_addresses_address_host, ck_ip_addresses_address_not_disabled}` | `ip` |
| `trg_virtual_machine_details_host_valid`（`constraint_name` 可用） | `host` |
| FK（`host_resource_id`/`resource_id`/`network_id`/`interface_id`） | 所属列 |
| 触发器 `fn_ip_addresses_cidr_contains`（无 `constraint_name`，`restrict_violation`） | 按消息 → `ip` |
| 触发器 `fn_ip_addresses_cluster_consistent`（无 `constraint_name`） | 按消息 → `network`/`ip` |
| 触发器 `fn_ip_addresses_interface_cluster`（无 `constraint_name`） | 按消息 → `name` |
| 未知 | `resource_type`，并整批回滚 |

- `diag.constraint_name` 仅对 UNIQUE/CHECK/FK/NOT NULL 填充；`fn/trg_ip_addresses_*` 须按 RAISE 消息/SQLSTATE 归因（复用 `ip_address.py::_translate_integrity_error` 文本分支）。
- SAVEPOINT 内触发器抛错可捕获并 `ROLLBACK TO SAVEPOINT`，不污染外层事务。

## 13. 业务边界
- 仅新增 BM/VM Resource 及其 Interface/IPAddress；**本入口支持向已存在且未软删的 Resource 追加 Interface/IPAddress**，但**不新建、不修改该 Resource 的任何字段**，也不覆盖既有 Interface/IPAddress（§8.1/§11、requirements §24.6）。无部分成功；同步处理。
- 资源导入（F014，BM 14 / VM 10 列模板，不含 Interface/IP）**不提供追加**：对已存在 hostname 仍按冲突报错；该差异须在界面说明。
- 一期**不支持**向既有 Interface 追加 IP：同一张网卡多地址须在同一批首次导入中提供，或经 IP 侧绑定入口维护。
- 由于整批原子与「既有子对象仍报错」，含已导入行的批次会整批失败；补录既有机器时 CSV 应**只包含新增行**（界面须说明）。
- 回滚无 Resource/Interface/IPAddress/Audit/Activity 残留（新建组与追加组同事务）。
- 不导入/创建 Network/IP Pool/Cluster/Host/Service/Endpoint；不触发自动分配；软删 Resource 视为不存在（不得追加、不复活）。
- 未定义路径/方法 404/405；`format` 缺失/非法 422 `VALIDATION_ERROR`；超限 413。
- Network INACTIVE：允许作为已有引用被查询，但禁止新增 IP（导入按行错误）；软删 Network 视为不存在。

## CSV 文本载体（加法引用）（增补节 v1，独立于上文正文版本）

本节只新增一层**载体**语义，不修改上文任何端点、字段、错误码、上限、权限或响应形状。前端「资源+网卡+IP」导入面板自 F034 起提供两种**并列**载体：上传文件（含 `.xlsx`）与粘贴 CSV 文本；文件载体行为完全不变。

- **载体只决定 multipart `file` 部分的产生方式**：文本载体在前端把粘贴的文本按 UTF-8 编码构造为一个带固定文件名的 `File`，随既有 `POST /api/v1/imports/resource-interfaces-ips/validate` 与 `POST /api/v1/imports/resource-interfaces-ips` 的 multipart 提交；请求仍恰为 `file`（binary）+ `format`（string），wire 形状不变。
- **文本编码**：按 UTF-8 编码提交；前端不添加 BOM（若文本本身以 `U+FEFF` 开头则原样提交，服务端按 `utf-8-sig` 解码）；前端不做本地归一化（不 trim 内容、不改行尾、不转义、不补尾部换行）。浏览器文本控件可能把行尾呈现为 LF，服务端按 §7 的同一逻辑记录切分口径处理 CRLF / LF / 混用。
- **表头与分隔符**：文本必须自带与 §6 冻结 26 列统一宽模板**逐字逐序一致**的表头；仅逗号分隔；不做分隔符嗅探、不自动补表头、不按列名重排、不做列名大小写折叠。不合规时按既有 `422 IMPORT_INVALID_FILE` 的 `header_missing` / `missing_columns` / `unknown_columns` / `column_order` / `empty_file` 原因拒绝。
- **`format` 固定**：文本载体恒使用 `format=csv`（前端该字段只读）；不提供 `.xlsx` 的文本载体，`format` 取值语义与既有校验顺序（401 → 403 → `format` 形状 422 → 大小 413 → 解析 422 → 行数 413 → 表头/列 422 → 逐行/分组校验）不变。
- **上限**：字节上限按文本 **UTF-8 编码后的字节数**适用 §14 的同一签核值 `import_max_file_bytes`（5,242,880，严格大于才拒绝）；行数上限与文件载体一致为 `import_max_rows`（5000）。数值不变更、不新增设置。前端允许对空/纯空白内容与字节超限做**非权威**前置拦截（不发请求）；行数上限不在前端镜像，一律以服务端 413 为权威。
- **等价性**：逐字节相同的 CSV 字节，经文件载体与文本载体提交时，预校验与写入的行为、响应字段（`created` / `total_rows` / `interfaces_created` / `ip_addresses_created`）、`RowError`（`row` / `field` / `reason` / `related_row`）、行号口径、错误码与 `IMPORT_INVALID_FILE.details.reason` 集合完全一致。服务端判定始终为权威。
