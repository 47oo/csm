## 1. 通用约定

- Base path `/api/v1`；认证载体：`csm_session` Cookie 或 `Authorization: Bearer csm_ak_…`，二者并存。
- CSRF：GET 免校验；两个 POST 在 Cookie 且无 Bearer 且非同源时校验，失败 403 `FORBIDDEN{reason:"csrf"}`；Bearer 豁免。
- 时间：ISO-8601 带偏移、UTC。
- 错误信封：F002 §1.1 `{"error":{"code","message","details"}}`；不新增 error code；新增 CONFLICT reason `already_granted`，复用并扩义 `already_revoked`。
- 校验顺序：401 → 403（CSRF/角色）→ 422（请求体 schema）→ 404（路径对象）→ 422（语义）→ 409 → 2xx。
- 未定义路径/方法：PATCH/DELETE/detail/batch/restore/全局列表一律 404/405。

## 3. 列表 GET `/api/v1/users/{user_id}/cluster-authorizations`

- 权限 `USER_ADMIN`；返回该用户全部授权历史（ACTIVE + REVOKED，含软删 Cluster 行）。
- 响应 `{items, page, page_size, total}`；空结果 200 `{items:[],page:1,page_size:20,total:0}`。
- 查询参数：

| 参数 | 默认 | 规则 |
| --- | --- | --- |
| `status` | 不过滤 | ACTIVE / REVOKED |
| `cluster_id` | 不过滤 | 非 UUID → 422；不存在/已软删可作为过滤值，空结果 200 |
| `q` | 不过滤 | Cluster code/name 大小写不敏感子串，转义 `% _ \`；trim 后空、>64 或含控制字符 → 422 |
| `page` | 1 | ≥1 |
| `page_size` | 20 | 1–100 |
| `sort` | granted_at | granted_at / revoked_at |
| `order` | desc | asc / desc |

- 同刻 `id` 升序稳定；`total` 与 items 同 filters。
- 未声明查询参数 → 422（本端点收紧，不改既有端点）。
- 路径 `user_id` 非 UUID 或不存在 → 404。

## 4. 端点

### 4.1 GET 列表

见 §3。错误 401/403/422/404/500。

### 4.2 POST `/api/v1/users/{user_id}/cluster-authorizations` 授予

- 权限 `USER_ADMIN`；路径 user 非 UUID/不存在 → 404。
- 请求体（`extra="forbid"`）：`{"cluster_id":"<uuid>"}`。
- 语义：
  - 目标账号为 ADMIN → 422 `fields[{field:"user_id"}]`，不写行/审计。
  - cluster_id 缺失/非 UUID/未知字段 → 422。
  - cluster_id 不存在或已软删 → 422 `fields[{field:"cluster_id"}]`；INACTIVE 允许。
- 成功 201 `{"cluster_authorization": Row}`，status=ACTIVE、effective 按 §2、revoked_at=null、granted_by=操作者、granted_at=事务 now()。
- 同事务写 Audit。
- 重复授予（已有有效行）→ 409 `CONFLICT{reason:"already_granted"}`，不新增行、不改既有行、不写 Audit；并发后到者同样 409（DB 部分唯一索引兜底；`ON CONFLICT DO NOTHING` 0 行必须映射 409）。
- 撤销后重授 → 新行、新 id，旧行保持 REVOKED 且不改写。

### 4.3 POST `/api/v1/cluster-authorizations/{authorization_id}/revoke` 撤销

- 权限 `USER_ADMIN`；路径 id 非 UUID/不存在 → 404。
- 无请求体，服务端忽略正文。
- 成功 200 `{"cluster_authorization": Row}`，status=REVOKED、revoked_at/revoked_by 已置、effective=false；软删 Cluster 上的有效授权允许撤销。
- 已撤销 → 409 `CONFLICT{reason:"already_revoked"}`，状态/撤销时间/操作者不变、不写 Audit。
- 条件更新 `WHERE id=:id AND revoked_at IS NULL`，rowcount=0 → 409。
- 不物理删除、不改归属/granted_at/granted_by。

## 5. 错误映射

| HTTP | code | 触发 | details |
| --- | --- | --- | --- |
| 401 | `AUTH_REQUIRED` | 无有效凭据；失效 Key；账号 DISABLED | {} |
| 403 | `FORBIDDEN` | 非 ADMIN；CSRF | `{reason:"permission"}` / `{reason:"csrf"}` |
| 404 | `NOT_FOUND` | 路径 user_id / authorization_id 不存在或非 UUID | {} |
| 409 | `CONFLICT` | 重复授予 / 撤销已撤销 | `{reason:"already_granted"}` / `{reason:"already_revoked"}` |
| 422 | `VALIDATION_ERROR` | 请求体/查询/语义非法 | `{fields:[{field,message}]}` |
| 500 | `INTERNAL_ERROR` | 未预期 | {} |

P-1 固定口径：**路径对象不存在或非 UUID → 404；请求体/语义非法 → 422**。列表端点先校验路径 `user_id` 存在性（404），再对自由字符串 `q` 做语义校验（422）；`status`/`cluster_id`/`sort`/`order`/`page`/`page_size` 为 FastAPI 类型化参数，在进入 handler 前校验（422），因此未知用户 + 这些非法参数返回 422 而非 404。路径账号不存在 → 404；目标为 ADMIN、cluster_id 非 UUID/不存在/已软删、分页排序 q 非法、未知查询参数 → 422。403 先于 422/404/409。

`already_granted` 首次引入并登记 F002 §1.2.1 v3；`already_revoked` 复用 F017 字面，F026 扩义到集群授权（不写审计、不改状态）。

**非唯一完整性错误语义（v3 补记，记录既有实现，不改变任何映射）**

授予端点在 §4.2 的 `IntegrityError` 处理中，**仅**当违反部分唯一索引
`uq_user_cluster_authorizations_user_id_cluster_id` 时返回 409 `CONFLICT{reason:"already_granted"}`。
其他完整性失败——例如校验通过后瞬态竞态导致的外键或触发器失败——**不被改写成 409 或 422**，
而是原样上抛，由统一异常处理返回 500 `INTERNAL_ERROR{}`，且不新增授权行、不写 Audit。
§4.2 的「cluster_id 不存在或已软删 → 422」是校验阶段结论，与上述校验后兜底不冲突；
该情形不构成 §1/§5 P-1 错误顺序的放宽，也不新增 error code 或 reason。
证据：F030 服务层用例（外键违约不被映射为 `already_granted`、无授权行与 Audit 残留）+
F002 500 信封用例。

## 9. 业务边界

### 9.1 ADMIN 目标
授予 ADMIN → 422，不建行、不写 Audit；ADMIN 范围恒 unrestricted；回填跳过 ADMIN。

### 9.2 Cluster 状态
授予目标必须未软删；已软删/不存在 → 422；INACTIVE 允许。ACTIVE⇄INACTIVE 不改授权/effective/解析集合。软删后行保留、effective=false、解析排除；允许撤销；恢复后原授权自动生效，软删期间撤销的恢复后仍不生效。新建 Cluster 不自动授权。

### 9.3 账号停用（A-1）
停用不删除/修改授权；停用期间无法认证；允许为 DISABLED 账号授予；回填包含 DISABLED；启用后按既有行恢复。

### 9.4 重复/已撤销
重复授予 409 `already_granted`；撤销已撤销 409 `already_revoked`；均不改状态、不写 Audit。先查 + 条件写入 + 唯一约束兜底，不以异常做正常业务分支。

### 9.5 重授
重授新建行；已撤销行永久保留不改写；1 有效 + N 已撤销合法；无物理删除。

### 9.6 AccessScope 与 F026 边界（A19–A24）
交付 `AccessScope(unrestricted, cluster_ids)` 与 `get_access_scope`；F026 不用于既有业务端点过滤，不产生越权 404。非 ADMIN = ACTIVE 授权 ∩ Cluster 未软删；零授权空集默认拒绝；ADMIN unrestricted。逐请求解析、同请求稳定、不跨请求缓存；授权/角色变更下一请求即时反映（含 API Key）。

### 9.7 回填（A-3、A26–A29）
迁移执行时既有非 ADMIN × 既有 Cluster（含软删、含 DISABLED）；granted_by=NULL；granted_at=now()；幂等、不复活已撤销；不改变角色/状态/业务对象；不写业务 Audit。证据 = 迁移计数断言（ADMIN=0、missing=0、duplicate_active=0、total=active=非 ADMIN 用户数 × Cluster 数，失败整体回滚）+ T99。

### 9.8 其他
升级为 ADMIN 的账号既有行可查；E2 授予拒绝、E3 可撤销。失败不改状态、无审计残留。
