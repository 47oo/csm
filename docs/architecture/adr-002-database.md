# ADR-002 数据库与数据行为

- **决策 ID**：D-ARCH-DB
- **状态**：ACCEPTED（2026-09-25，用户批准，revision 8 / BQ-V）
- **影响**：F013、F001、F002、F004、F005、F006、F007、F009、F012（等）

## 背景

`docs/product/domain-model.md` §5 与 `requirements-v2.md` §9.3 要求唯一性、并发不重复由数据库/后端最终保证；BQ-M 取消逻辑删除、统一真实删除，但要求保留资源历史/审计，且集群 `code`、服务编号真实删除后永不复用（BQ-M、BQ-U）。

## 决策

- **唯一主库**：PostgreSQL 16/17（唯一权威数据源）。
- **唯一性由数据库保证**：业务表上以 `UNIQUE` 约束/部分唯一索引表达「仍存对象」唯一；IPv4 同集群唯一、资源名/接口名/网段名/规范化 CIDR 唯一等由约束保证，不由应用层单独兜底。
- **真实删除 + 标识不复用**：受管资源业务行真实删除；另设**独立保留标识表**保存 `code`、服务编号等永不复用的比较键，不依赖业务行是否仍存在。**不预设直接删行业务数据**。
- **历史与审计**：采用**追加写**的历史/审计表；真实删除业务对象不删除历史；历史不作为在用关联或恢复入口。资源历史 P0 仅管理员可查、长期保留、不自动到期清除（BQ-Q、BQ-V）。
- **比较键**：`code` 统一大写、规范化 CIDR、IP 数值等比较键单独存储；展示保留用户输入形态，比较与唯一性只使用比较键。
- **并发**：MVCC 事务 + 唯一约束 + 乐观锁 `version`（见 ADR-003）。
- **迁移策略（BQ-V 选择 a）**：P0 为绿地，**不引入 Alembic 等迁移工具**，以初始化建表脚本建立 Schema；后续表结构变更仍须按 AGENTS §6 显式评估已有数据并保留变更流程。

## 备选与取舍

| 备选 | 取舍 |
| --- | --- |
| MySQL 8 | 可行；部分唯一索引/复杂约束表达弱于 PostgreSQL |
| 逻辑删除替代真删 | **违反 BQ-M**，不采用 |
| 历史与业务同表加 `deleted_at` | 与“真实删除、无恢复”语义混淆，不采用 |

## 仍开放（不阻塞本决策）

- `D-NAME-COMPARISON`（名称/用户名比较口径）、`D-RESOURCE-HISTORY`（历史/审计载体边界与 Schema 表达）仍 `OPEN`，由受影响设计阶段裁定。
