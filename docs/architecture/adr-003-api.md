# ADR-003 API 风格与契约

- **决策 ID**：D-ARCH-API
- **状态**：ACCEPTED（2026-09-25，用户批准，revision 8 / BQ-V）
- **影响**：全部 Feature（affects=ALL）

## 背景

需求 §4.5 / §7.3 / 场景 42/43/47 要求整单原子提交、区分「删除子项 vs 未修改」、并发拒绝静默覆盖、错误定位到字段与冲突对象；§8 要求服务端分页与模糊搜索；§9.1 要求三角色服务端鉴权。

## 决策

- **风格**：REST + JSON，资源导向；每个 Feature 一份 `docs/api/<feature>.md` 契约，底层 OpenAPI 3.1（FastAPI 自动生成）作为机器可校验契约。
- **整单更新**：采用 **显式子项操作（增/改/删）**，明确区分「删除网卡/IP」与「未修改」；任一失败整单不生效（单事务）。
- **并发**：乐观锁版本号（`version` 字段或 `ETag`/`If-Match`）；冲突返回 **409**，提示刷新并由前端保留输入。
- **错误语义**：`application/problem+json`，含 `code`、`message`、字段级 `errors[]`（定位字段与冲突对象）；状态码 400/422 校验、403 权限、404 未找到、409 并发或关联保护冲突。
- **分页与搜索**：`page`/`page_size` + `q`（模糊）+ 过滤参数 + `sort`，稳定排序并返回 `total`；服务端全量匹配而非当前页；1000 规模采用 offset 分页。
- **权限**：三角色由服务端校验，越权返回 403；集群选择是查询作用域，不是授权边界。

## 备选与取舍

| 备选 | 取舍 |
| --- | --- |
| GraphQL | 内部 CRUD + 强约束场景收益低，治理成本高，不采用 |
| 命令式 RPC | 原子表达直接，但与 REST 契约一致性弱，不采用 |
| 完整目标状态 PUT | 可能覆盖未加载字段，不采用（选显式子项操作） |
| 游标分页 | 1000 规模收益有限，offset 更简单可维护 |

## 影响

- 各 Feature 的 `contract` 在本决策批准后可由 Architect 产出 `docs/api/<feature>.md` 并转 READY；契约未批准前 `contract.status` 保持 `BLOCKED`。
- 前端需实现竞态防护、冲突保留输入、字段级错误展示；后端需实现单事务原子、版本校验与唯一约束冲突映射。
