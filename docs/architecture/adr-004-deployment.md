# ADR-004 部署形态与环境

- **决策 ID**：D-ARCH-DEPLOY
- **状态**：ACCEPTED（2026-09-25，用户批准，revision 8 / BQ-V）
- **影响**：F011（部署/非功能验收）及全部 Feature 的部署前提

## 背景

需求 §9.1 要求仅内网访问、三角色服务端鉴权；§9.3 原要求备份/恢复演练与审计保留周期由部署方案确定。用户已通过 BQ-V 明确部署口径。

## 决策

- **拓扑**：内网部署；反向代理进入前端静态资源与后端 API；后端与 PostgreSQL 同内网网段，不直接暴露公网。
- **协议**：**仅启用 HTTP、不启用 HTTPS**；接受内网明文传输风险（BQ-V）。
- **部署方式**：**Docker Compose** 起步；不强制依赖 K8s。
- **环境**：至少 `dev` / `staging` / `prod`；配置经环境变量/密钥文件注入，不硬编码。
- **备份**：**P0 不做备份、不做恢复演练**；接受数据丢失风险（BQ-V）。审计与资源历史仍按 §9.1 长期保留于同一存储。
- **认证源**：平台自建用户管理，不接入组织既有认证（BQ-V，功能见 `requirements-v2.md` §4.9）。

## 备选与取舍

| 备选 | 取舍 |
| --- | --- |
| HTTPS/TLS 终止 | 更安全；用户明确选择 HTTP-only，接受明文风险 |
| 裸机/systemd | 更简单；容器化环境一致性更好 |
| 内网 K8s | 如需复用现有平台可采用；本期不强制 |
| 每日备份 + PITR + 恢复演练 | §9.3 原方案；用户明确选择不做备份，接受数据丢失风险 |

## 影响与风险

- 需求 §9.1/§9.3 的备份与 HTTPS 表述已被 BQ-V 覆盖；`requirements-v2.md` 已同步。
- 风险：无备份意味着数据不可恢复；HTTP 明文可能泄露登录口令与审计数据。均已由用户明确接受。
- F011 的部署/可靠性验收应以本 ADR 为准，不再要求备份/恢复演练。
