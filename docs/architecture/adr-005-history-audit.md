# ADR-005 资源历史与审计载体

- **决策 ID**：D-RESOURCE-HISTORY
- **状态**：ACCEPTED（2026-09-25，用户确认，BQ-W）
- **影响**：F001、F002、F005、F006、F007、F012、F013

## 背景

BQ-M 取消逻辑删除、统一真实删除，但要求审计与资源历史**不随业务对象真实删除而消失**；资源历史至少保留操作人与删除/变更内容，P0 仅平台管理员可查、长期保留、不自动到期（BQ-N、BQ-Q、BQ-V）。同时集群 `code` 与服务编号真实删除后永不复用（BQ-M、BQ-U）。§11.2 原先将“历史与审计的载体边界及 Schema 表达”列为未决。

## 决策

- **历史与审计分表承载，且**均为**追加写（append-only）**：业务操作只新增记录，不修改/删除既有历史或审计行；真实删除业务对象不清除历史。
- **资源历史**：记录受管对象的删除/变更（至少操作人 + 删除或变更的内容）；**仅平台管理员可查询**，查看者与资源维护者由服务端拒绝；**长期保留、不自动到期清除**；历史不作为仍存业务关联，也不作为业务恢复入口。
- **操作审计**：记录操作者、时间及关键变更；保留策略与资源历史一致（长期、不自动清除）。用户/角色管理操作进入审计，但不并入仅管理员可查的**受管资源历史**（`requirements-v2.md` §4.9）。
- **标识不复用**：集群 `code`、服务编号的“永不复用”由**独立保留标识表**保证，不依赖业务行是否仍存在（见 ADR-002）。
- **表结构、字段、索引与查询实现**由 Database 在受影响 Feature 的设计阶段确定；本 ADR 只固定上述行为边界。

## 备选与取舍

| 备选 | 取舍 |
| --- | --- |
| 历史/审计与业务同表加删除标记 | 与“真实删除、无恢复”语义混淆，不采用 |
| 允许修改/压缩历史 | 破坏可追溯性，不采用 |
| 审计与资源历史合并为一张表 | 语义与权限不同（审计含用户管理操作，资源历史只针对受管资源），不采用 |

## 影响

- §11.2 的 `RESOURCE-HISTORY`（载体边界部分）与 `NAME-COMPARISON` 关闭；不再阻塞 F012/F013 等。
- 所有受影响 Feature 的“删除/变更历史写入”与 F012/F007 的查询能力须按本 ADR 实现；`code`/服务编号不复用须有持久保留标识。
- 无备份（ADR-004）意味着历史/审计与业务数据同存储，丢失风险已由用户接受（BQ-V）。
