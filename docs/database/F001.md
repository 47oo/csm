## 0. 交付边界

本设计覆盖 F001 需要的 3 张表：

- `clusters`：集群主表（新增）。
- `reserved_cluster_codes`：`code` 跨真实删除永不复用的独立保留标识表（新增）。
- `resource_history`：跨受管对象共享的 append-only 资源历史表（**F001 首次引入**；后续 F002/F005/F006/F007 写入，F012 查询）。

明确不在本设计范围：

- `audit_log`：由 `docs/database/F013.md` §2.5 定义、F013 初始化建表；F001 只以 `target_type='cluster'` 追加。
- 后续 Feature 引入的关联表及其对 `clusters(id)` 的 `ON DELETE RESTRICT` 外键；本文件只声明该约束约定（§4）。
- 集群聚合计数（F010）、资源历史查询 API（F012）、其它受管对象 Schema。

**F001 与 F013 的建表依赖**：`resource_history.actor_user_id` 引用 `users(id)`，初始化顺序必须先建立 F013 的 `users`。

## 1. 实体与关系概览

```
clusters (1) ── 被后续对象 cluster_id 引用   [F001 不建 FK；后续 Feature 对 clusters(id) 建 ON DELETE RESTRICT]
clusters                             [code_key 与 reserved_cluster_codes 共同保证 code 不复用]
reserved_cluster_codes               [无 FK；主键比较键；只增不删]
resource_history ── actor_user_id → users(id) ON DELETE SET NULL
resource_history.target_id (text)    [无对业务表的阻塞 FK；可指向已真实删除对象]
```

- 主键统一 `BIGINT GENERATED ALWAYS AS IDENTITY`；`reserved_cluster_codes.code_key` 为自然主键。
- 时间列统一 `TIMESTAMPTZ`（RFC 3339 UTC）。
- 枚举以 `TEXT + CHECK` 表达，不使用 PostgreSQL 原生 enum。
- 比较键与展示值分离：`code` 存去首尾空格的输入形态、`code_key` 存规范化比较键；`name` 本身即比较键（大小写敏感，无空格）。

## 2. 表设计

### 2.1 `clusters`

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | 稳定集群 ID；供后续对象 `cluster_id` 引用 |
| `code` | `text` | NOT NULL | — | `CHECK (code = btrim(code) AND btrim(code) <> '')` | 展示编号：去首尾空格的输入形态，保留大小写；创建后不可修改 |
| `code_key` | `text` | NOT NULL | 生成列 | `GENERATED ALWAYS AS (upper(btrim(code))) STORED`；`UNIQUE`；`CHECK (code_key ~ '^[A-Z0-9]{1,32}$')` | 比较/判重键（BQ-Z） |
| `name` | `text` | NOT NULL | — | `CHECK (name ~ '^[A-Za-z0-9_\u4e00-\u9fff]{1,64}$')`；`UNIQUE` | 名称；区分大小写判重 |
| `purpose` | `text` | NOT NULL | — | `CHECK (btrim(purpose) <> '' AND char_length(purpose) <= 200)` | 用途；非空、上限 200（PROPOSED） |
| `version` | `integer` | NOT NULL | `1` | `CHECK (version >= 1)` | 乐观锁 |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — | |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | — | 任何 UPDATE 由 Backend 刷新 |

**约束与索引**：`pk_clusters(id)`；`uq_clusters_code_key(code_key)`；`uq_clusters_name(name)`；`chk_clusters_code_trimmed`；`chk_clusters_code_key_format`；`chk_clusters_name_format`；`chk_clusters_purpose`；`chk_clusters_version`；`ix_clusters_code`；`ix_clusters_created_at`。

**乐观锁写模式**：
```sql
UPDATE clusters SET name=:name, purpose=:purpose, version=version+1, updated_at=now()
 WHERE id=:id AND version=:expected_version;
DELETE FROM clusters WHERE id=:id AND version=:expected_version;
-- rowcount=0 → 404（不存在）或 409 VERSION_CONFLICT
```

### 2.2 `reserved_cluster_codes`

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `code_key` | `text` | NOT NULL | — | PK；`CHECK (code_key ~ '^[A-Z0-9]{1,32}$')` | 规范化比较键；永不删除 |
| `reserved_at` | `timestamptz` | NOT NULL | `now()` | — | 首次占用时间 |

**约束/触发器**：`pk_reserved_cluster_codes(code_key)`；`chk_reserved_cluster_codes_format`；`trg_reserved_cluster_codes_append_only`（BEFORE UPDATE/DELETE，复用 F013 `csm_reject_mutation()`）。

**写入规则**：创建集群时同事务先 `INSERT reserved_cluster_codes`，冲突 → `409 CLUSTER_CODE_TAKEN`；`code` 不可改；删除集群不删保留行。

### 2.3 `resource_history`

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | |
| `occurred_at` | `timestamptz` | NOT NULL | `now()` | — | 变更/删除时间 |
| `actor_user_id` | `bigint` | NULL | — | FK → `users(id)` ON DELETE SET NULL | 操作者；用户删除后置 NULL、历史保留 |
| `actor_username_snapshot` | `text` | NOT NULL | — | `CHECK (btrim(actor_username_snapshot) <> '')` | 操作者名快照 |
| `target_type` | `text` | NOT NULL | — | `CHECK (btrim(target_type) <> '')` | 目标类型（集群为 `cluster`） |
| `target_id` | `text` | NULL | — | 无 FK | 目标稳定 ID 字符串；对象真实删除后仍可读 |
| `target_key_snapshot` | `text` | NULL | — | — | 目标关键标识快照（集群 `code`）（PROPOSED） |
| `action` | `text` | NOT NULL | — | `CHECK (action IN ('update','delete'))` | F001 取值集 |
| `change` | `jsonb` | NOT NULL | `'{}'::jsonb` | — | update: `{name:{from,to}, purpose:{from,to}}`；delete: `{code,name,purpose}` |

**约束/索引**：`pk_resource_history`；`fk_resource_history_actor`（ON DELETE SET NULL）；`chk_resource_history_actor_snapshot`；`chk_resource_history_target_type`；`chk_resource_history_action`；`ix_resource_history_occurred_at(occurred_at DESC)`；`ix_resource_history_actor(actor_user_id)`；`ix_resource_history_target(target_type,target_id)`；`trg_resource_history_append_only`（拒绝 DELETE/内容 UPDATE，仅豁免 actor SET NULL）。

> `target_id` 为 `text` 且无 FK；不得对 `clusters(id)` 建阻塞 FK。

## 4. 关联保护设计

- 集群仍有关联时禁止真实删除、不级联；DB 侧由**后续关联表**对 `clusters(id)` 建 `ON DELETE RESTRICT`。
- F001：`DELETE` 触发 `SQLSTATE 23503` → 映射 `409 CLUSTER_HAS_ASSOCIATIONS`，事务回滚。
- F001 实现期无关联表，删除空关联集群必然成功（场景 71）；关联行为侧由 F002/F005/F007 验收（§51 最终闭环归 F007）。
- 历史/审计表不得建阻塞 FK；禁止用应用层计数替代 DB 约束。

## 5. 删除 / 编辑行为

### 5.1 编辑（PATCH）
- 仅 `name`/`purpose` 可变；`code` 无更新路径（400 CODE_IMMUTABLE）。
- 名称冲突 → `409 CLUSTER_NAME_TAKEN`；乐观锁不符 → `409 VERSION_CONFLICT`。
- 同事务追加 `audit_log(cluster.update)` 与 `resource_history(update)`。

### 5.2 真实删除（DELETE）
单事务：① `audit_log(cluster.delete)`；② `resource_history(delete)`；③ `DELETE ... WHERE id AND version`；④ `RESTRICT` FK 触发 `23503` → 回滚 → 409。

保留：`reserved_cluster_codes`（`code` 不复用）、`resource_history`、`audit_log`；`name` 随行删除 → 可复用；无恢复入口。

## 8. Backend 可依赖的保证

1. `clusters.code_key` 与 `reserved_cluster_codes.code_key` 唯一，后者只增；冲突映射 `409 CLUSTER_CODE_TAKEN`。
2. `code_key` 恒等于 `upper(btrim(code))`（生成列）。
3. 格式/枚举由 CHECK 保证。
4. `version` 条件更新实现乐观锁。
5. 删除 `clusters` 不删保留表/历史/审计；不应对其执行 DELETE/UPDATE。
6. 关联冲突以 `23503` 出现，映射 `409 CLUSTER_HAS_ASSOCIATIONS`。
7. `resource_history` 单行插入、append-only、`target_id` 无 FK。
8. 初始化幂等。
