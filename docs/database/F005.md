## 0. 交付边界

本设计覆盖 F005 需要的 2 张表：

- `network_segments`：网段主表（新增）。
- `segment_reserved_addresses`：网段保留地址子表（新增）。

明确**不在本设计范围**：

- `clusters`：由 F001 定义与初始化；F005 仅新增指向 `clusters(id)` 的 `ON DELETE RESTRICT` 外键，**不修改** `clusters` Schema。
- `resource_history` / `audit_log`：由 F001（`resource_history`）/ F013（`audit_log`）定义与初始化；F005 **只写入**（`target_type='segment'`），**不建表、不改 Schema、不提供查询**。两者的 append-only 触发器由 F001/F013 初始化脚本建立。
- `network_interfaces.segment_id`（F002）、IP 分配表对 `network_segments(id)` 的 `ON DELETE RESTRICT`（F006）：属后续 Feature；本设计只声明约定（§7）。
- 网段聚合计数（F010）、资源历史查询 API（F012）、其它受管对象 Schema。

**初始化依赖顺序（`CONFIRMED`）**：F013 `users` → F001 `clusters` + `resource_history` → F005 `network_segments` + `segment_reserved_addresses`。`network_segments.cluster_id` 引用 `clusters(id)`，故必须先建 `clusters`；本设计**不**新建 `resource_history`/`audit_log`。

## 1. 实体与关系概览

```
clusters (1) ──── (N) network_segments            [cluster_id → clusters(id) ON DELETE RESTRICT]
network_segments (1) ──── (N) segment_reserved_addresses
                                                   [segment_id → network_segments(id) ON DELETE RESTRICT]
network_segments ──写入──> audit_log(target_type='segment')            [F013 已建，无 FK]
network_segments ──写入──> resource_history(target_type='segment')     [F001 已建，无 FK]
```

- 主键统一 `BIGINT GENERATED ALWAYS AS IDENTITY`（与 F001/F013 一致）。
- 时间列统一 `TIMESTAMPTZ`（RFC 3339 UTC）；`updated_at` 由 Backend 在任何 UPDATE 时刷新。
- 枚举以 `TEXT + CHECK` 表达，**不使用 PostgreSQL 原生 enum**（ADR-002/AGENTS §2.6）。
- **无 `status`、无 `deleted_at`、无软删**：网段与保留地址均只支持真实删除（BQ-M、§4.6、§5）。
- 展示/比较键分离（ADR-002）：网段 CIDR 为**全函数规范化**（网络地址 + 前缀唯一确定），架构 §4.2 明确 `cidr` 展示值即比较键；本设计仍单列 `cidr_key` 承载唯一性目标与 ADR-002 的「比较键单独存储」约定（§2.1）。
- **无独立保留标识表**：网段不设类似 `reserved_cluster_codes` 的复用禁用表（见 §8）。

## 2. 表设计

### 2.1 `network_segments`

**用途**：网段主表（身份、所属集群、名称、规范化 CIDR、用途、技术类型、VLAN、网关、自动分配范围、乐观锁）。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | 稳定网段 ID；供 F002 网卡、F006 IP 分配 `segment_id` 引用 |
| `cluster_id` | `bigint` | NOT NULL | — | FK → `clusters(id)` `ON DELETE RESTRICT` | 所属集群；仍存网段阻止集群删除（F001 `23503` → `409 CLUSTER_HAS_ASSOCIATIONS`） |
| `name` | `text` | NOT NULL | — | `CHECK (name = btrim(name) AND btrim(name) <> '' AND char_length(name) <= 128)`；`UNIQUE (cluster_id, name)` | 网段名；去首尾空格后存储、**区分大小写**、禁纯空白、长度 1–128（BQ-W、架构 §4.1 PROPOSED） |
| `cidr` | `text` | NOT NULL | — | `CHECK (cidr ~ <IPv4-CIDR 正则>)` | 展示值 = 规范化 IPv4 CIDR（如 `192.168.1.0/24`） |
| `cidr_key` | `text` | NOT NULL | 生成列 | `GENERATED ALWAYS AS (cidr) STORED` | 比较键；`UNIQUE (cluster_id, cidr_key)` |
| `purpose` | `text` | NOT NULL | — | `CHECK (btrim(purpose) <> '' AND char_length(purpose) <= 200)` | 用途；自由文本、非空有界（架构 §4.3 PROPOSED、§6.5） |
| `technology` | `text` | NOT NULL | — | `CHECK (btrim(technology) <> '' AND char_length(technology) <= 100)` | 技术类型；自由文本、非空有界（架构 §4.3 PROPOSED、§6.5） |
| `vlan` | `integer` | NULL | — | `CHECK (vlan IS NULL OR vlan BETWEEN 1 AND 4094)` | VLAN；未填 `NULL`（架构 §4.4 PROPOSED） |
| `gateway` | `text` | NULL | — | `CHECK (gateway IS NULL OR gateway ~ <IPv4 正则>)` | 单个 IPv4 或 `NULL`；**是否落在 CIDR 内由应用保证**（§5） |
| `auto_alloc_start` | `text` | NULL | — | 见成对约束 | 自动分配起始；未启用 `NULL` |
| `auto_alloc_end` | `text` | NULL | — | 见成对约束 | 自动分配结束；未启用 `NULL` |
| `version` | `integer` | NOT NULL | `1` | `CHECK (version >= 1)` | 乐观锁（PATCH/DELETE 条件更新） |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — | |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | — | 任何 UPDATE 时由 Backend 刷新 |

**CIDR 格式 CHECK 正则（辅助校验，非语义等价）**：
```
^((25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.){3}(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])/(3[0-2]|[12]?[0-9])$
```
（拒绝前导零八位组、前缀 0–32；**不校验主机位是否归零**——规范化是 Backend 职责，见 §5。）

**IPv4 地址 CHECK 正则（`gateway`/`auto_alloc_*`/保留地址端点共用，辅助校验）**：
```
^(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])$
```

**自动分配成对约束**：
```
CHECK (
  (auto_alloc_start IS NULL) = (auto_alloc_end IS NULL)
  AND (auto_alloc_start IS NULL
       OR (auto_alloc_start ~ <IPv4 正则> AND auto_alloc_end ~ <IPv4 正则>))
)
```
保证「两端同为 `NULL`（未启用）或同为非空且为合法 IPv4」；**「起 ≤ 止」「落在 CIDR 内」由应用保证**（§5）。

**约束与索引**

| 名称 | 类型 | 定义 | 服务的查询/约束 |
| --- | --- | --- | --- |
| `pk_network_segments` | PK | `(id)` | 详情/编辑/删除按 ID |
| `fk_network_segments_cluster` | FK | `cluster_id → clusters(id) ON DELETE RESTRICT` | 集群存在性 + 集群删除保护（23503 → 409） |
| `uq_network_segments_cluster_name` | UNIQUE | `(cluster_id, name)` | 同集群仍存网段名唯一（区分大小写）；服务集群内列表 `ORDER BY name` |
| `uq_network_segments_cluster_cidr` | UNIQUE | `(cluster_id, cidr_key)` | 同集群规范化 CIDR 唯一；其隐式 btree 索引即 `(cluster_id, cidr_key)` 查询路径（见下） |
| `chk_network_segments_name` | CHECK | `name = btrim(name) AND btrim(name) <> '' AND char_length(name) <= 128` | 去空格存储、非空、长度 |
| `chk_network_segments_cidr` | CHECK | `cidr ~ <IPv4-CIDR 正则>` | CIDR 格式辅助校验 |
| `chk_network_segments_purpose` | CHECK | `btrim(purpose) <> '' AND char_length(purpose) <= 200` | 用途非空有界 |
| `chk_network_segments_technology` | CHECK | `btrim(technology) <> '' AND char_length(technology) <= 100` | 技术类型非空有界 |
| `chk_network_segments_vlan` | CHECK | `vlan IS NULL OR vlan BETWEEN 1 AND 4094` | VLAN 取值域 |
| `chk_network_segments_gateway` | CHECK | `gateway IS NULL OR gateway ~ <IPv4 正则>` | 网关格式 |
| `chk_network_segments_auto_alloc` | CHECK | 成对约束（见上） | 自动范围成对/格式 |
| `chk_network_segments_version` | CHECK | `version >= 1` | 乐观锁数值合法 |
| `ix_network_segments_cluster_id` | btree | `(cluster_id)` | 按集群筛选列表；FK RESTRICT 检查；集群删除保护 |

> **关于任务所列 `(cluster_id, cidr_key)` 索引**：`uq_network_segments_cluster_cidr` 已在 `(cluster_id, cidr_key)` 上建立唯一 btree 索引，按该列组合的等值/前缀查询直接命中，**不再另建同名物理索引**以避免重复（AGENTS §2.6）。
> **列表排序**：集群内按名称排序可由 `uq_network_segments_cluster_name (cluster_id, name)` 的隐式索引支持；跨集群列表 P0 规模（~千级网段）无需额外索引。
> **大小写敏感性假设**：`name` 唯一性依赖数据库默认排序规则的**大小写敏感**比较（如 `C`/默认 `en_US.utf8`）。若部署采用大小写不敏感/非确定性 collation，需显式指定确定性 collation 或改用 `name` 的确定性表达；P0 默认假定大小写敏感（§10 `OPEN`，非阻塞）。

**乐观锁写模式（Backend 必须遵守，REQUIRED；ADR-003）**
```sql
UPDATE network_segments
   SET name=:name, cidr=:cidr, purpose=:purpose, technology=:technology,
       vlan=:vlan, gateway=:gateway,
       auto_alloc_start=:a_start, auto_alloc_end=:a_end,
       version=version+1, updated_at=now()
 WHERE id=:id AND version=:expected_version;

DELETE FROM network_segments WHERE id=:id AND version=:expected_version;
-- rowcount=0 → 不存在(404) 或 409 VERSION_CONFLICT
-- DELETE 触发 fk_network_segments_reserved (RESTRICT) → 23503 → 409 SEGMENT_HAS_RESERVED_ADDRESSES
```

### 2.2 `segment_reserved_addresses`

**用途**：网段保留地址子表（单个地址或起止范围）；逐条显式增/删、无逻辑删除。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | 稳定保留地址 ID |
| `segment_id` | `bigint` | NOT NULL | — | FK → `network_segments(id)` `ON DELETE RESTRICT` | 所属网段；仍存保留地址阻止网段删除 |
| `start_ip` | `text` | NOT NULL | — | `CHECK (start_ip ~ <IPv4 正则>)` | 起始 IPv4；单地址时 `start_ip = end_ip` |
| `end_ip` | `text` | NOT NULL | — | `CHECK (end_ip ~ <IPv4 正则>)` | 结束 IPv4 |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — | |

**约束与索引**

| 名称 | 类型 | 定义 | 服务 |
| --- | --- | --- | --- |
| `pk_segment_reserved_addresses` | PK | `(id)` | 按 ID 删除单条保留地址 |
| `fk_segment_reserved_addresses_segment` | FK | `segment_id → network_segments(id) ON DELETE RESTRICT` | 所属网段存在性 + 网段删除保护（不级联） |
| `chk_segment_reserved_addresses_start_ip` | CHECK | `start_ip ~ <IPv4 正则>` | 起始地址格式 |
| `chk_segment_reserved_addresses_end_ip` | CHECK | `end_ip ~ <IPv4 正则>` | 结束地址格式 |
| `ix_segment_reserved_addresses_segment_id` | btree | `(segment_id)` | 按网段取保留地址列表；FK RESTRICT 检查 |

> **约束边界**：`start_ip ≤ end_ip`、两端落在所属网段 CIDR 内、同一网段保留范围不重叠/不重复（`RESERVED_OVERLAP`）均由应用保证（§5、架构 §4.7 PROPOSED）；`start_ip = end_ip` 表示单地址（应用判定，DB 不禁止）。
> **不建 append-only 触发器**：需求要求保留地址可**逐条真实删除**（§4.4/§5、BQ-O），故本表**不加** `csm_reject_mutation` 等只增不删触发器；历史保留由 `resource_history` 承载（§3.3、§8）。
> **不建数值键列**：`start_ip`/`end_ip` 为 `text`；地址数值比较与范围/重叠运算由 `app.network_segments.addressing` 纯函数完成（架构 §2.1、§7）。保留地址列表「按 `start_ip` 升序」（Contract §3.1）由应用按 IPv4 数值排序后返回（详见 §6 偏差说明）。

## 4. 删除 / 编辑行为

### 4.1 编辑（PATCH）
- 可变列：`name`、`cidr`（条件可变）、`purpose`、`technology`、`vlan`、`gateway`、`auto_alloc_start/end`；`cluster_id`、`id` 无更新路径。
- 同集群名称冲突 → `409 SEGMENT_NAME_TAKEN`；同集群 CIDR 冲突 → `409 SEGMENT_CIDR_TAKEN`；乐观锁不符 → `409 VERSION_CONFLICT`。
- 同事务追加 `audit_log(segment.update)` 与 `resource_history(update)`。
- 存在已分配 IP 时禁止改 CIDR（`409 CIDR_IMMUTABLE`，F006 生效）为**应用规则**，DB 不强制。

### 4.2 真实删除（DELETE）单事务
1. 应用校验 `confirm`（去首尾空格后等于 `name`，区分大小写）→ 不匹配 `422 DELETE_CONFIRMATION_MISMATCH`，不删除。
2. 事务内读父行并检查 `gateway IS NULL`，否则 `409 SEGMENT_GATEWAY_NOT_CLEARED`；检查保留地址计数，否则 `409 SEGMENT_HAS_RESERVED_ADDRESSES`。
3. `audit_log(segment.delete)`、`resource_history(delete)`（先写后删）。
4. `DELETE ... WHERE id AND version`；`fk_segment_reserved_addresses_segment` 触发的 `23503` 兜底映射 `409 SEGMENT_HAS_RESERVED_ADDRESSES`；F002/F006 引入的 FK `23503` 映射 `409 SEGMENT_HAS_INTERFACES`/`SEGMENT_HAS_ALLOCATIONS`（按 `constraint_name`/`table_name` 区分）。
5. rowcount=0 → 404 或 `409 VERSION_CONFLICT`。

- **不级联**：删除 `network_segments` 不删除任何 `segment_reserved_addresses` 行（RESTRICT）；保留地址须逐条先删。
- **保留**：`resource_history`、`audit_log` 行长期保留；网段删除后不再可作为可分配网段。

### 4.3 保留地址增删
- 新增：应用校验端点格式/在 CIDR 内/`start_ip ≤ end_ip`/同网段不重叠后 `INSERT`；事务内对父网段 `SELECT ... FOR UPDATE` 串行化（PROPOSED），**不改变父网段 `version`**。
- 删除：`DELETE FROM segment_reserved_addresses WHERE id=:id AND segment_id=:segment_id`，rowcount=0 → `404 RESERVED_ADDRESS_NOT_FOUND`；真实删行、无恢复。

## 5. DB 保证 vs 应用保证（依据架构 §9.3 / ADR-002）

### 5.1 由数据库保证（约束/触发器）
1. `cluster_id` 存在且删除受 RESTRICT 保护（`fk_network_segments_cluster`）。
2. `segment_id` 存在且删除受 RESTRICT 保护（`fk_segment_reserved_addresses_segment`）。
3. 同集群 `name` 唯一（区分大小写）、`cidr_key` 唯一；跨集群可重复。
4. 名称去空格/非空/长度、`purpose`/`technology` 非空有界、`vlan` 取值域、`gateway`/`auto_alloc_*`/保留地址端点的 IPv4 格式、自动范围成对 `NULL`、`version ≥ 1` 由 CHECK 保证。
5. 主键、非空、时间默认值。

### 5.2 由应用保证（Backend，DB 无法可靠表达或属业务规则）
1. **CIDR 规范化**：`ipaddress.IPv4Network(raw, strict=False)` → 网络地址字符串；`cidr`/`cidr_key` 均已归零主机位；IPv6/非法 → `422`。CHECK 正则只保证格式，**不保证主机位归零**。
2. **IPv4 语义合法性**：`ipaddress` 判定（含拒绝前导零等非规范写法）；CHECK 仅为辅助护栏。
3. **网关/自动范围/保留地址落在所属网段 CIDR 内**；`auto_alloc_start ≤ auto_alloc_end`；保留 `start_ip ≤ end_ip`。
4. **保留范围同网段不重叠/不重复**（`RESERVED_OVERLAP`）。
5. **集群存在性错误语义**：新增前查 `clusters` → `404 CLUSTER_NOT_FOUND`（FK 只保证引用完整，不提供 404 语义）。
6. **删除前置「网关未清空」**（列值检查）与**二次确认**校验。
7. **存在已分配 IP 时禁止改 CIDR**（`CIDR_IMMUTABLE`，F006 生效）。
8. **重叠检测与分配排除集计算**（§5.1/§5.2 架构）。
9. **审计 / 资源历史写入时机与内容**，删除时先写后删。

> 说明：可由数据库可靠保证的完整性（唯一性、格式护栏、FK RESTRICT、成对约束）不留给应用单独兜底（AGENTS §6）；业务语义（CIDR 内、范围序、重叠）在 P0 无扩展/函数前提下由应用承担，并在 §9 测试项中覆盖。

## 6. 与架构 §3 的偏差与 PROPOSED 项

**无阻塞性偏差。** 对齐说明：

1. **与架构一致**：`network_segments` 的列集合、`UNIQUE(cluster_id, name)`、`UNIQUE(cluster_id, cidr_key)`、对 `clusters(id)` 的 RESTRICT FK、`segment_reserved_addresses` 对 `network_segments(id)` 的 RESTRICT FK、保留地址可逐条删除、`resource_history`/`audit_log` 复用不建表——均与架构 §3 一致。
2. **偏差 A（数值键列缺省）**：架构 §3.1/§3.2 以括号形式允许「`gateway`/`auto_alloc_*`/`start_ip`/`end_ip` + 数值键（或 Database 选定等价表达）」。本设计**不新增 `_num` 数值列**，等价表达为：地址数值比较/区间/重叠/排序由 `app.network_segments.addressing` 纯函数在应用层完成（架构 §2.1 已规划该模块供 F006 复用）。依据：P0 规模（~千级网段、保留地址量小）、避免冗余派生列与自定义不可变转换函数/表达式索引复杂度（AGENTS §2.6）。若后续出现 SQL 侧数值排序/范围查询压力，可按 AGENTS §6 增量新增「不可变 `ipv4_to_int(text)` 函数 + 表达式索引」，不改本表列语义（PROPOSED，非阻塞）。
3. **偏差 B（`cidr_key` 表达）**：架构 §4.2 明确 `cidr` 展示值即 `cidr_key`。本设计保留单列 `cidr_key GENERATED ALWAYS AS (cidr) STORED`，使其恒等于 `cidr`、作为 `UNIQUE` 目标并沿用 F001/F013 的比较键命名约定，**不引入第二处规范化来源**（避免应用可写不一致）。若不希望保留该冗余生成列，可退化为直接 `UNIQUE (cluster_id, cidr)`；当前设计选择保留命名稳定性（PROPOSED）。
4. **PROPOSED（不阻塞）**：
   - `purpose ≤ 200`、`technology ≤ 100`、`name ≤ 128`、`vlan ∈ 1–4094`、CIDR `/(0..32)` 接受主机位输入并规范化为网络地址；网关为单个 IPv4（架构 §4.3–§4.5 PROPOSED）。
   - CIDR/IPv4 正则作为 CHECK 辅助护栏（架构 §3.1 REQUIRED-3「可辅以 CHECK，Database 决定」）。
   - 保留地址增删、网关清空不改父网段 `version`（架构 §6.3 PROPOSED；Contract §3.2/§3.3 一致）。
   - 同集群重叠仅提示、允许保存（无 DB 约束）。
5. **OPEN（非阻塞本设计，回 Product）**：`purpose`/`technology` 是否受控枚举及取值集；VLAN 是否必填；网关是否允许多值；网段名称字符集；CIDR 是否要求严格网络地址输入；`name` 大小写比较所需 collation（§10）。以上不改变本 Schema 结构即可后续收敛。

## 7. 关联保护与跨 Feature 约定

- **F001 集群删除保护**：`fk_network_segments_cluster ON DELETE RESTRICT` → F001 删除集群时若仍存网段，`SQLSTATE 23503` → `409 CLUSTER_HAS_ASSOCIATIONS`（§4.1.9、场景 51）。
- **F002 网卡引用（PROPOSED，机制）**：`network_interfaces.segment_id → network_segments(id) ON DELETE RESTRICT` → `409 SEGMENT_HAS_INTERFACES`。
- **F006 IP 分配引用（PROPOSED，机制）**：IP 分配记录对 `network_segments(id)` 建 `ON DELETE RESTRICT` → `409 SEGMENT_HAS_ALLOCATIONS`；存在已分配 IP 时的 `CIDR_IMMUTABLE` 由 F006 查询接入。
- **历史/审计表不得对 `network_segments(id)` 建阻塞 FK**：`resource_history`/`audit_log` 用 `target_id text`、无 FK，保证「仅余历史不阻止删除」（ADR-005、架构 §2.3）。F005 不新建此类 FK。
- **删除冲突区分**：Backend 需按 `constraint_name`/`table_name` 将 `23503` 映射到 `SEGMENT_HAS_RESERVED_ADDRESSES`/`SEGMENT_HAS_INTERFACES`/`SEGMENT_HAS_ALLOCATIONS`（架构 §12 PROPOSED-7）。

## 8. 数据安全与保留语义（含「真实删除后可复用」确认）

1. **真实删除即删行**：`network_segments`/`segment_reserved_addresses` 均物理删除；无 `deleted_at`/`status`/恢复入口（BQ-M）。
2. **历史保留**：删除/变更操作在 `resource_history`（`target_type='segment'`、`target_id=str(segment.id)`、`target_key_snapshot=segment.name`、`action ∈ {update, delete}`）append-only 保留；审计在 `audit_log`（`target_type='segment'`）append-only 保留；**不随业务行删除而清除**。
3. **无独立保留标识表**：`reserved_cluster_codes` 一类只适用于集群 `code`/服务编号等「真实删除后永不复用」的标识。**不适用于网段**——`network_segments` 名称与 CIDR **均未要求跨删除禁用**。据此确认：
   - **网段名称删除后可复用**（同集群内，`uq_network_segments_cluster_name` 只约束仍存行）；
   - **同一 CIDR 可被其它集群复用**（`uq_network_segments_cluster_cidr` 作用域含 `cluster_id`）；
   - **同集群同一 CIDR 在网段被真实删除后可再次登记复用**（唯一约束仅覆盖仍存行）。
   本设计**不为**网段建保留标识表，也不因删除保留名称/CIDR。
4. **历史不参与分配排除**：排除计算只读现存 `network_segments`/`segment_reserved_addresses` 行，**绝不读 `resource_history`**（架构 §3.2、BQ-O）。

### 9.1 幂等初始化（与 `backend/app/bootstrap.py` 风格一致）

## 11. Backend 可依赖的保证（公共契约）

1. **唯一性**：`network_segments` 在 `(cluster_id, name)` 与 `(cluster_id, cidr_key)` 上唯一（作用域限仍存行）；跨集群可重复；冲突可直接映射 `409 SEGMENT_NAME_TAKEN`/`409 SEGMENT_CIDR_TAKEN`。删除后名称/CIDR 可复用（无保留表）。
2. **比较键一致**：`cidr_key` 恒等于 `cidr`（生成列）；Backend 只需在写入前完成 CIDR 规范化即保证唯一性口径正确。
3. **引用完整与删除保护**：`cluster_id`/`segment_id` 为 RESTRICT FK；`23503` 出现即表示仍有关联，映射 `409`（按约束名区分），事务回滚。
4. **字段护栏**：名称/用途/技术/VLAN/地址格式/自动范围成对/`version` 由 CHECK 保证；CIDR 主机位归零、CIDR 内、范围序、保留重叠属应用保证。
5. **并发**：以 `version` 条件 UPDATE/DELETE 实现乐观锁，DB 保证 `version ≥ 1`。
6. **删除语义**：删除网段不级联保留地址；历史/审计无业务 FK、append-only、长期保留。
7. **保留地址可真实删行**（无 append-only 触发器）；`start_ip = end_ip` 合法。
8. **初始化幂等**：新增两表由 `create_all` 覆盖，无新增触发器；重复执行不报错。

  5. 保留地址增删/网关清空不改父网段 `version`（`SELECT ... FOR UPDATE` 串行化）。
- `OPEN`（**非阻塞本设计**，回 Product 在 Database 设计之后、实现之前收敛）：
  1. `purpose`/`technology` 是否受控枚举及取值集；
  2. VLAN 是否必填；
  3. 网关是否允许多值；
  4. 网段名称字符集限制；
  5. CIDR 是否要求严格网络地址输入（拒绝主机位）；
  6. 数据库 collation 对 `name` 大小写比较确定性的影响（P0 假定大小写敏感默认 collation）。
  以上不改变 `network_segments`/`segment_reserved_addresses` 结构即可后续收敛；若收敛为受控枚举，按 AGENTS §6 以 CHECK 增量调整并记录。

## 14. Database 交付边界声明

本设计仅定义数据模型、约束、索引与初始化/变更纪律。**DDL 脚本、SQLAlchemy 映射、事务与业务写入逻辑（CIDR 规范化、保留地址/网关校验与增删、唯一与 FK 冲突 409 映射、乐观锁条件更新、二次确认、计数/重叠计算、审计与资源历史写入）由 Backend 实现。** Database 不写业务实现、不执行数据库变更、不修改产品规则。设计完成不等于数据库实现完成。
