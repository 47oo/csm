## 0. 交付边界

本设计覆盖 F006 的数据库部分：

- `ip_addresses`：IPv4 分配记录表（**新增**）。
- `resources.management_ip_id`：F002 已交付表上的**附加可空列** + 复合 FK（管理 IP 归属本资源）+ 索引（**增量**）。
- `network_interfaces`：F002 已交付表上的**附加唯一约束**（作为 `ip_addresses` 复合 FK 目标）（**增量**）。
- `SegmentUsage` 两个只读查询的落地口径（F005 扩展点，F006 填充；**Database 只给查询口径，不写实现**）。
- `ip_addresses` 与 `resources.management_ip_id` 相关的 `23503`/`23505` 映射约定。

明确**不在本设计范围**：

- `resources` / `network_interfaces` 的既有列与语义（F002 已交付，F006 只附加列/约束/索引）；`network_segments` / `segment_reserved_addresses`（F005 已交付）。
- `resource_history` / `audit_log`：由 F001 / F013 建立；F006 **只写不建**（`target_type='resource'`），不新增 IP 级历史表，不得对其建阻塞 FK。
- 选址算法、排除集计算、错误语义、管理 IP 解析、审计/历史写入（Backend）。
- 独立 IP 写端点（F006 不提供；IP 增/删经资源表单事务）。
- 全局 IP 查询（F010）、资源历史查询（F012）。

**初始化依赖顺序（`CONFIRMED`）**：F013 `users` → F001 `clusters`+`resource_history` → F005 `network_segments`+`segment_reserved_addresses` → F002 `resources`+`network_interfaces` → **F006 附加 `network_interfaces` 唯一约束 → `ip_addresses` → `resources.management_ip_id`+复合 FK**。

## 1. 实体与关系概览

```
resources (1) ──── (0..N) network_interfaces        [(resource_id, cluster_id) → resources(id, cluster_id) ON DELETE RESTRICT]（F002）
network_segments (1) ── (0..N) network_interfaces   [(segment_id, cluster_id) → network_segments(id, cluster_id) ON DELETE RESTRICT]（F002）

ip_addresses (0..N) ── interface_id → network_interfaces(id)  ON DELETE RESTRICT        [INTERFACE_HAS_IPS]
ip_addresses (0..N) ── segment_id   → network_segments(id)    ON DELETE RESTRICT        [SEGMENT_HAS_ALLOCATIONS]
ip_addresses ── (interface_id, segment_id)            → network_interfaces(id, segment_id)            ON DELETE RESTRICT   [IP 属于网卡所选网段]
ip_addresses ── (interface_id, resource_id, cluster_id) → network_interfaces(id, resource_id, cluster_id) ON DELETE RESTRICT [冗余列钉住]
resources (1) ── (id, management_ip_id) → ip_addresses(resource_id, id) ON DELETE RESTRICT            [管理 IP 归属本资源]

ip_addresses ──写入──> audit_log(target_type='resource')        [F013 已建，无 FK]
ip_addresses ──写入──> resource_history(target_type='resource') [F001 已建，无 FK]
```

- 主键统一 `BIGINT GENERATED ALWAYS AS IDENTITY`；时间列统一 `TIMESTAMPTZ`（RFC 3339 UTC）。
- 枚举以 `TEXT + CHECK` 表达，不使用 PostgreSQL 原生 enum。
- **无 `status`/`deleted_at`/软删**：IP 仅真实删除（删行、释放占用、可复用），历史由 `resource_history` 承载。
- 比较键与展示值分离（ADR-002）：`ip` 为规范化点分十进制展示值，`ip_key` 为生成列比较键，恒等于 `ip`。

## 2. 表设计

### 2.1 `ip_addresses`（IP 分配记录，新增）

**用途**：记录一张网卡分配到的单个 IPv4；同集群有效 IPv4 全局唯一；逐项显式增/删、无逻辑删除。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | 稳定 IP 记录 ID；供管理 IP 引用与 F012 查询 |
| `interface_id` | `bigint` | NOT NULL | — | FK 组成列 | 所属网卡（§4.2.2/3、§4.4.3） |
| `resource_id` | `bigint` | NOT NULL | — | 复合 FK 组成列 | **冗余列**：所属资源；源自网卡，用于管理 IP 归属与查询 |
| `cluster_id` | `bigint` | NOT NULL | — | 复合 FK 组成列 | **冗余列**：所属集群；源自资源，用于「同集群唯一」作用域与 `allocated_ip_nums` |
| `segment_id` | `bigint` | NOT NULL | — | FK 组成列 | 分配时所选网段（§4.6.6/7、§5） |
| `ip` | `text` | NOT NULL | — | `CHECK (ip ~ <IPv4 正则>)` | 规范化点分十进制 IPv4；仅 IPv4（§4.2.8） |
| `ip_key` | `text` | NOT NULL | 生成列 | `GENERATED ALWAYS AS (ip) STORED` | 比较键，恒等于 `ip`（与 F005 `cidr_key` 同约定） |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — | 创建时间；IP 地址不可改，无 `updated_at` |

**IPv4 地址 CHECK 正则（与 F005 `gateway`/`auto_alloc_*`/保留地址端点同一正则，辅助护栏）**：
```
^(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])$
```
（拒绝前导零八位组；数值语义合法性、规范化仍由 Backend `app.network_segments.addressing` 负责。）

**约束与索引**

| 名称 | 类型 | 定义 | 服务的查询/约束 |
| --- | --- | --- | --- |
| `pk_ip_addresses` | PK | `(id)` | 按 ID 引用/删除 |
| `uq_ip_addresses_cluster_ip` | UNIQUE | `(cluster_id, ip_key)` **`DEFERRABLE INITIALLY IMMEDIATE`** | 同集群仍存有效 IP 全局唯一；真实删除后可复用；支持同事务先删后建同址（§2.4、§7.1） |
| `uq_ip_addresses_resource_id` | UNIQUE | `(resource_id, id)` | 供 `resources(id, management_ip_id)` 复合 FK 引用（PK 已保证 `id` 唯一，此为 FK 目标所必需；**必须非延迟**——PostgreSQL FK 目标不允许延迟唯一约束） |
| `chk_ip_addresses_ip` | CHECK | `ip ~ <IPv4 正则>` | IPv4 格式护栏；无 IPv6 路径 |
| `fk_ip_addresses_interface` | FK | `interface_id → network_interfaces(id) ON DELETE RESTRICT` | 网卡存在性 + 删除保护（`23503` → `409 INTERFACE_HAS_IPS`） |
| `fk_ip_addresses_segment` | FK | `segment_id → network_segments(id) ON DELETE RESTRICT` | 网段存在性；`409 SEGMENT_HAS_ALLOCATIONS` 主要**由应用前置检查 `allocated_count > 0` 返回**，本 FK 为兜底（有 IP 时通常先命中网卡 FK，见 §5） |
| `fk_ip_addresses_interface_segment` | FK(复合) | `(interface_id, segment_id) → network_interfaces(id, segment_id) ON DELETE RESTRICT` | **「IP 属于网卡所选网段」由数据库保证**（§2.4）；网卡改段而仍有 IP → `23503` |
| `fk_ip_addresses_interface_resource` | FK(复合) | `(interface_id, resource_id, cluster_id) → network_interfaces(id, resource_id, cluster_id) ON DELETE RESTRICT` | 钉住冗余 `resource_id`/`cluster_id` 恒等于所属网卡（进而是资源）的值 |
| `ix_ip_addresses_interface_id` | btree | `(interface_id)` | 按网卡取 IP（升序）+ `fk_ip_addresses_interface`/复合 FK RESTRICT 检查 |
| `ix_ip_addresses_segment_id` | btree | `(segment_id)` | `allocated_count(segment_id)` + F005 FK RESTRICT 检查 |
| `ix_ip_addresses_resource_id` | btree | `(resource_id)` | 按资源取 IP + 管理 IP/归属查询 |

> `(cluster_id, ip_key)` 查询路径由 `uq_ip_addresses_cluster_ip` 的隐式唯一 btree 索引覆盖（`allocated_ip_nums(cluster_id)` 走 `cluster_id` 前缀），**不另建**同组合普通索引（AGENTS §2.6）。
> 复合 FK 的 RESTRICT 检查以 `ix_ip_addresses_interface_id` 的 `interface_id` 前缀列为主，无需为每个复合 FK 单独建索引。

### 2.2 `resources.management_ip_id`（F002 表附加列，新增）

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `management_ip_id` | `bigint` | NULL | — | 复合 FK 组成列 | `NULL` 或指向本资源某个网卡的 IP（§4.2.9）；不新增独立 IP 记录 |
| `fk_resources_management_ip` | FK(复合) | `(id, management_ip_id) → ip_addresses(resource_id, id) ON DELETE RESTRICT` | 管理 IP 必须属于本资源；删除仍被引用的 IP 前必须同次清空/重选（`23503` → `422 MANAGEMENT_IP_REQUIRED`，见 §5） |
| `ix_resources_management_ip_id` | btree | `(management_ip_id)` | 服务 `fk_resources_management_ip` 的 RESTRICT 检查；按管理 IP 反查资源 |

> `MATCH SIMPLE`：`management_ip_id IS NULL` 时约束不检查，天然支持「资源可无管理 IP」。`id` 为 `resources` PK，故复合 FK 的引用侧取值 `(resources.id, resources.management_ip_id)` 唯一对应一行。
> 不得使用 `ON DELETE SET NULL`：删除管理 IP 必须由应用在同次提交显式清空/重选，不得静默清空（§4.2.11、场景 46）。

### 2.3 `network_interfaces` 附加唯一约束（F002 表，新增）

作为 `ip_addresses` 复合 FK 的目标，需在 F002 已交付的 `network_interfaces` 上附加：

| 名称 | 定义 | 用途 | 破坏性 |
| --- | --- | --- | --- |
| `uq_network_interfaces_id_segment` | UNIQUE `(id, segment_id)` | `fk_ip_addresses_interface_segment` 的 FK 目标 | 无（含 PK `id`，恒唯一；纯附加约束） |
| `uq_network_interfaces_id_resource_cluster` | UNIQUE `(id, resource_id, cluster_id)` | `fk_ip_addresses_interface_resource` 的 FK 目标 | 无（含 PK `id`，恒唯一；纯附加约束） |

> 两个约束均含 PK `id`，对任何已有数据必然满足唯一性，**增量添加不会失败、无需回填**；不新增列、不改语义、不改既有数据。

### 2.4 「IP 属于网卡所选网段」的 DB 表达（决策 `PROPOSED` → 采用复合 FK）

**问题**：IP 的 `segment_id` 必须等于其网卡当前 `segment_id`（§4.6.6、跨表完整性，`CHECK` 无法表达）。

**候选方案**

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **A. 复合 FK（采用）** | `ip_addresses.segment_id NOT NULL`；`network_interfaces` 加 `UNIQUE(id, segment_id)`；建 `(interface_id, segment_id) → network_interfaces(id, segment_id) ON DELETE RESTRICT` | 由数据库**声明式**保证「IP 属于网卡所选网段」，并**顺带保证「网卡改段须先释放 IP」**（父行 `segment_id` UPDATE 立即违反 → `23503`）；符合 AGENTS §6；与 F002 §2.3 复合 FK 先例一致 |
| B. 应用保证 + 测试 | 仅 `segment_id → network_segments(id) ON DELETE RESTRICT`，成员关系由 `app.ip_allocation` 校验并测试 | 把 DB 可表达的完整性降级为应用保证，与 AGENTS §6 相悖；网卡改段一致性仍需应用兜底 |
| C. 触发器 | 新建校验触发器 | 引入非声明式逻辑与触发器，与「不新增触发器」约定冲突 |

**最终选择：方案 A**。依据：
1. 需求 §4.6.6/7、§5 与架构 §3.1 `PROPOSED` 均允许复合 FK 落地；AGENTS §6 要求可 DB 保证的完整性落到 DB。
2. 该复合 FK 同时覆盖「网卡改网段但仍有 IP → `INTERFACE_SEGMENT_CHANGE_REQUIRES_IP_RELEASE`」的并发兜底（应用仍先做前置校验，见 §8）。
3. 冗余列 `segment_id` 不会被应用独立改写（仅创建时取自网卡，且 `NOT NULL`），不存在漂移路径。
4. `segment_id` 在 `ip_addresses` 为 `NOT NULL`：网卡未选网段（`network_interfaces.segment_id IS NULL`）时无父行匹配，插入 IP 直接失败——与「分配 IP 前必须选定网段」一致（应用先返回 `422 SEGMENT_NOT_SELECTED`）。

**冗余列钉住（`PROPOSED`）**：`resource_id` / `cluster_id` 由 `fk_ip_addresses_interface_resource` 对 `network_interfaces(id, resource_id, cluster_id)` 钉住，确保恒等于所属网卡（而 F002 已把网卡 `resource_id`/`cluster_id` 钉在资源上）。此设计替代架构 §3.3 所列的 `UNIQUE(id, cluster_id)`：用单条三列复合 FK 同时钉住 `resource_id` 与 `cluster_id`，避免额外 FK/约束。

### 2.5 「管理 IP 属于本资源」的 DB 表达（决策 `PROPOSED` → 采用复合 FK）

**问题**：`resources.management_ip_id` 只能指向本资源（而非其它资源）的 IP（§4.2.9、场景 46）。

**最终选择：复合 FK**：`ip_addresses` 冗余 `resource_id` + `UNIQUE(resource_id, id)` 作目标，`resources (id, management_ip_id) → ip_addresses(resource_id, id) ON DELETE RESTRICT`。

取舍：
- 采用（DB 保证）：满足 AGENTS §6；删除被引用 IP 由 RESTRICT 兜底，应用先做 `MANAGEMENT_IP_REQUIRED` 前置；代价为 `ip_addresses` 上一处结构性冗余唯一约束 + 一条跨表循环 FK。
- 不采用（应用保证 + 测试）：需放弃一条 DB 可表达的归属完整性，与 AGENTS §6 相悖，故不采用。
- 循环 FK 处理：`resources` 已存在，`ip_addresses` 后建，循环由「`ip_addresses` 侧 FK 随建表创建、`resources` 侧 FK 由增量 ALTER 添加」自然打破（§7）；从空库 `create_all` 时对 `fk_resources_management_ip` 使用 `use_alter=True`。

## 4. `SegmentUsage` 只读查询落地（F005 扩展点，F006 填充）

Database 只定义查询口径与所需索引；实现由 Backend 承担（`app.network_segments.usage` 接口，F006 提供 provider 或在单一函数内读取 `ip_addresses`）。

| 方法 | 语义 | 查询口径 | 索引 | 消费方 |
| --- | --- | --- | --- | --- |
| `allocated_count(segment_id) -> int` | 该网段已分配 IP 数 | `SELECT count(*) FROM ip_addresses WHERE segment_id = :segment_id` | `ix_ip_addresses_segment_id` | F005 `PATCH` CIDR 前 `> 0` → `409 CIDR_IMMUTABLE` |
| `allocated_ip_nums(cluster_id) -> set[int]` | 该集群全部已分配 IP 数值集合（含所有网段，覆盖重叠） | `SELECT ip_key FROM ip_addresses WHERE cluster_id = :cluster_id`（应用转 int 集合） | `uq_ip_addresses_cluster_ip` 的 `cluster_id` 前缀 | F005 分配排除、保留/网关冲突、`auto_assignable_count` 扣除 |

- 二者**只读 `ip_addresses`**（经 `app.network_segments.usage` 扩展点），不反向依赖 `app.resources`；不参与写入。
- `SEGMENT_HAS_ALLOCATIONS` 由应用删除前置（`allocated_count(segment_id) > 0`）直接返回；`fk_ip_addresses_segment` 的 `23503` 仅作兜底。因「有已分配 IP 必有同网段网卡引用」，若无前置检查，PostgreSQL 会先报 `fk_network_interfaces_segment` 而误报 `SEGMENT_HAS_INTERFACES`；故实现必须**先**检查已分配 IP，再落到网卡引用兜底。
- `GET /network-segments/{id}/allocated-ips` 端点数据源：`ip_addresses` JOIN `network_interfaces` JOIN `resources`（取 `resource_name`/`resource_type`/`interface_name`），`is_management` 由 `resources.management_ip_id = ip_addresses.id` 判定；按 `ip_key` 数值升序（应用侧 `ipv4_to_int`）；分页 + `q` 过滤（地址/资源名/接口名）由应用实现。DB 无需额外索引（分页排序在 P0 规模下由现有索引 + 应用排序满足）。

## 5. 与 F002 / F005 的接口与删除保护（错误映射）

**`23503`（外键 RESTRICT）按 `constraint_name` 映射**

| constraint_name | 触发场景 | HTTP / code |
| --- | --- | --- |
| `fk_ip_addresses_interface` | 删除仍有 IP 的网卡 | `409 INTERFACE_HAS_IPS` |
| `fk_ip_addresses_interface_segment`（父 DELETE） | 删除仍有 IP 的网卡 | `409 INTERFACE_HAS_IPS` |
| `fk_ip_addresses_interface_segment`（父 UPDATE 改段） | 网卡改网段但仍有 IP | `422 INTERFACE_SEGMENT_CHANGE_REQUIRES_IP_RELEASE` |
| `fk_ip_addresses_interface_resource` | 删除仍有 IP 的网卡 | `409 INTERFACE_HAS_IPS` |
| `fk_ip_addresses_segment` | 删除仍有已分配 IP 的网段（F005 端点；主要经应用 `allocated_count` 前置，FK 兜底） | `409 SEGMENT_HAS_ALLOCATIONS` |
| `fk_resources_management_ip` | 删除/变更仍被引用的管理 IP 而未同次清空/重选 | `422 MANAGEMENT_IP_REQUIRED`（应用前置校验的兜底） |
| （F002 既有）`fk_network_interfaces_segment` | 删除仍被网卡引用的网段（F005 端点） | `409 SEGMENT_HAS_INTERFACES`（不变） |
| （F005 既有）`fk_segment_reserved_addresses_segment` | 删除仍有保留地址的网段 | `409 SEGMENT_HAS_RESERVED_ADDRESSES`（不变） |

**`23505`（唯一约束）映射**

| constraint_name | 触发场景 | HTTP / code |
| --- | --- | --- |
| `uq_ip_addresses_cluster_ip` | 同集群地址重复（含并发） | 手动：`409 IP_ALREADY_IN_USE`（附 `conflicts`）；自动：`409 NO_AVAILABLE_ADDRESS` |

- 并发语义：`uq_ip_addresses_cluster_ip` 为**最终保证**；触达 `23505` 时整单回滚并按上下文映射（§7 架构）。同资源写入仍由 F002 乐观锁 `version` 串行化；F006 不引入服务端自动重试。
- 应用映射不得仅凭 `SQLSTATE`，须结合 `constraint_name` 与请求上下文（手动/自动）区分错误码。

## 6. 触发器 / 约定

- **不为 `ip_addresses` 新建任何触发器**：IP 需支持**真实删除**（`op:"delete"` 逐项删行、释放占用、无恢复，§4.4.3/§5），故**不得**套用 `csm_reject_mutation()`/append-only。
- **不加 append-only 于任何业务表**；`csm_reject_mutation()` 仅用于历史/审计/保留标识表（`audit_log`、`resource_history`、`reserved_usernames`、`reserved_cluster_codes`），由 F013/F001 初始化脚本建立，**F006 不新增、不修改**。
- `resource_history`/`audit_log` 已由 F001/F013 建立，F006 **只写**（`target_type='resource'`, `action ∈ {update, delete}`），不建表、不改 Schema、不提供查询；`change` 结构化承载 `interfaces[].ips` 与管理 IP 变更（BQ-AB）。
- 结论：`app/bootstrap.py::TRIGGER_STATEMENTS` **无需为 F006 增加语句**。

## 7. 首次建表与幂等增量（P0 无迁移工具，ADR-002）

### 7.1 幂等初始化顺序（与 `backend/app/bootstrap.py` 一致）

在 F013/F001/F005/F002 建表之后执行：

1. **F002 表附加唯一约束**（FK 目标，须先于 `ip_addresses` 建表）：
   - `ALTER TABLE network_interfaces ADD CONSTRAINT uq_network_interfaces_id_segment UNIQUE (id, segment_id);`
   - `ALTER TABLE network_interfaces ADD CONSTRAINT uq_network_interfaces_id_resource_cluster UNIQUE (id, resource_id, cluster_id);`
   - 均含 PK `id`，对既有数据恒成立；用幂等守卫（`DO $$ ... IF NOT EXISTS pg_constraint ... $$`）避免重复执行报错。
2. **`ip_addresses` 建表**：`Base.metadata.create_all`（等价 `CREATE TABLE IF NOT EXISTS`）按 FK 依赖顺序建立新表、PK/UNIQUE/CHECK/FK/索引与 `ip_key` 生成列；复合 FK 目标（步骤 1 的唯一约束）须已存在，否则建表失败。
   - `uq_ip_addresses_cluster_ip` 为 `DEFERRABLE INITIALLY IMMEDIATE`，嵌入建表。
3. **`resources.management_ip_id` 增量**（F002 表上的可空附加列；`create_all` **不会**改动已存在表，须显式 DDL）：
   - `ALTER TABLE resources ADD COLUMN IF NOT EXISTS management_ip_id bigint;`
   - `ALTER TABLE resources ADD CONSTRAINT fk_resources_management_ip FOREIGN KEY (id, management_ip_id) REFERENCES ip_addresses(resource_id, id) ON DELETE RESTRICT;`（幂等守卫）
   - `CREATE INDEX IF NOT EXISTS ix_resources_management_ip_id ON resources (management_ip_id);`

幂等性：全部语句可重复执行不报错、不覆盖已有数据、无种子数据；`create_all` + 显式增量 DDL 组合混合使用。初始化只在部署/启动钩子执行（ADR-004）。

### 7.2 同事务「先删后建同址」

- `uq_ip_addresses_cluster_ip` 设为 `DEFERRABLE INITIALLY IMMEDIATE`：事务内可 `SET CONSTRAINTS uq_ip_addresses_cluster_ip DEFERRED` 使唯一性在事务末统一检查。
- **应用仍须按「先应用 `delete`、再应用 `create`」顺序写入**（架构 §5.1 `PROPOSED`），deferrable 仅作额外安全网；两者结合支持同网卡/换网卡重分配同地址与地址互换。

### 7.3 参考 DDL（Backend 据此落地）

```sql

--       F002 resources/network_interfaces 已建立。

ALTER TABLE network_interfaces

-- (2) ip_addresses
CREATE TABLE ip_addresses (
  id            bigint      GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  interface_id  bigint      NOT NULL,
  resource_id   bigint      NOT NULL,
  cluster_id    bigint      NOT NULL,
  segment_id    bigint      NOT NULL,

  CONSTRAINT chk_ip_addresses_ip
    CHECK (ip ~ '^(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])$'),
  CONSTRAINT fk_ip_addresses_interface FOREIGN KEY (interface_id)
    REFERENCES network_interfaces(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ip_addresses_segment FOREIGN KEY (segment_id)
    REFERENCES network_segments(id) ON DELETE RESTRICT,

);
CREATE INDEX ix_ip_addresses_interface_id ON ip_addresses (interface_id);
CREATE INDEX ix_ip_addresses_segment_id   ON ip_addresses (segment_id);
CREATE INDEX ix_ip_addresses_resource_id  ON ip_addresses (resource_id);
```

- P0 为绿地，**P0 内不改本 Feature 已定 Schema**。

## 8. DB 保证 vs 应用保证

### 8.1 由数据库保证（约束）

1. 同集群仍存有效 IPv4 全局唯一（`uq_ip_addresses_cluster_ip`）；跨集群可重复；删除后可复用。
2. `interface_id` / `segment_id` 引用完整 + `ON DELETE RESTRICT`：网卡/网段删除保护由 DB 保证，`23503` 即表示仍有关联（按约束名区分）。
3. 「IP 属于网卡所选网段」由 `fk_ip_addresses_interface_segment` 保证；「网卡改段须先释放 IP」由该 FK 的父行 UPDATE 检查保证。
4. 「管理 IP 属于本资源」由 `fk_resources_management_ip` 保证；被引用 IP 的删除受 RESTRICT。
5. 冗余 `resource_id`/`cluster_id` 恒等于所属网卡（进而资源）的值（`fk_ip_addresses_interface_resource`）。
6. IPv4 格式护栏（`chk_ip_addresses_ip`）、NOT NULL、主键、时间默认值。
7. 主键、非空、时间默认值。

### 8.2 由应用保证（Backend，DB 无法可靠表达或属业务规则）

1. **IPv4 语义合法性**：`ipaddress` 判定（拒绝非规范写法）；CHECK 仅为护栏；规范化后写库。
2. **网段 CIDR 成员判定**：地址是否在网卡所选网段 CIDR 内（`IP_OUT_OF_SEGMENT`）——DB 只保证 IP 的 `segment_id` 与网卡一致，不保证地址落在该 CIDR 内。
3. **选址算法**：手动/自动、`first_available`、`/31`/`/32` 特例（复用 F005 `addressing` 纯函数）。
4. **排除集**：`allocated_ip_nums(cluster_id)` + 保留/网关（含重叠网段）+ 网络/广播地址（`excluded_nums`），排除已真实删除网段历史。
5. **错误语义与映射**：`404`/`422`/`409`、`errors[]` 字段定位、`conflicts` 内容；`23503`/`23505` 按约束名 + 上下文的映射。
6. **管理 IP 解析**：`{interface_index, address}` / `{ip_id}` → 具体 `id`；删除管理 IP 或其网卡但未显式清空/重选 → 前置 `422 MANAGEMENT_IP_REQUIRED`；解析非本资源 → `422 MANAGEMENT_IP_INVALID`。
7. **网卡改段/删网卡/删资源前置校验**（`INTERFACE_SEGMENT_CHANGE_REQUIRES_IP_RELEASE`/`INTERFACE_HAS_IPS`/`RESOURCE_HAS_INTERFACES`）。
8. **整单原子事务编排**、IP `op ∈ {create, delete}` 合法性、应用顺序 `delete → update → create`、乐观锁 `version` 条件更新（F002）。
9. **审计 / 资源历史写入**时机与内容（删除 IP 前先写历史/审计，同事务）；管理 IP 变更并入 `resource.update`。
10. **写库时设置冗余 `resource_id`/`cluster_id`**（取自网卡；DB 复合 FK 兜底不允许错误值）。
11. `resource_id` 判重、管理 IP 序列化（`is_management` 由 `resources.management_ip_id` 比较得出）。

> 可由 DB 可靠保证的完整性（唯一、CHECK、RESTRICT FK、复合归属）不留给应用单独兜底（AGENTS §6）；业务语义（错误码映射、选址、排除、管理 IP 解析、历史）由应用承担并测试覆盖。

## 9. 数据安全与保留语义

1. **真实删除即删行**：`ip_addresses` 物理删除；无 `deleted_at`/`status`/恢复入口（BQ-M）。
2. **地址删除后可复用**：唯一约束仅覆盖仍存行；释放后该地址可再次分配，须重跑 §5 全部检查。
3. **删除顺序与不级联**：删除资源前须先逐张删网卡（F002 `RESOURCE_HAS_INTERFACES`），每张网卡须先逐项删 IP（F006 `INTERFACE_HAS_IPS`）；删除网段前须先逐项删已分配 IP（F006 `SEGMENT_HAS_ALLOCATIONS`）。任一上级删除不隐式释放/级联其仍存子项。
4. **历史保留**：IP 增/删与管理 IP 变更写入 F001 `resource_history`（`target_type='resource'`、`target_id=str(resource.id)`、`target_key_snapshot=resource.name`、`action='update'`，`change` 内结构化含 `interfaces[].ips`/`management_ip`）与 F013 `audit_log`（`target_type='resource'`、`action='resource.update'`）；append-only、随父资源删除而长期保留、不自动到期（BQ-AB/N/Q/V）。
   - `resource_history.action` CHECK 目前仅允许 `('update','delete')`（F001 §2.3），故 IP 创建并入父资源 `update`，**不新增 IP 级历史表**、不改 F001 约束。
5. **历史不参与在用判定**：分配排除与删除保护只读现存 `ip_addresses`/`network_segments`/`segment_reserved_addresses` 行，**绝不读 `resource_history`**（BQ-O、ADR-005）。
6. **`resource_history`/`audit_log` 无对 `resources(id)`/`ip_addresses(id)` 的阻塞 FK**（F001/F013 已如此设计），不影响删除（§4.4.2）。

**F002 已交付表的附加列迁移记录（`CONFIRMED` 需求 / `PROPOSED` 实现）**：
- `resources.management_ip_id` 为**可空、附加、向前兼容**变更：既有资源行缺省 `NULL`（合法，表示无管理 IP）；`ALTER TABLE ADD COLUMN` 在 PostgreSQL 11+ 为元数据操作、不重写表；无需回填。
- 新增 `fk_resources_management_ip` 与 `ix_resources_management_ip_id` 不改变既有数据语义；因所有既有值 `NULL`，约束添加不会失败。
- 回滚风险：回滚 = 删除列/约束/索引，将**丢失管理 IP 指派**（可重新指派）；因 P0 无迁移工具，回滚以前向修复为主，破坏性回滚需 Product 明确确认（AGENTS §6、ADR-004）。

## 10. 验证方式与测试项

### 10.1 数据库约束测试（pytest + 真实 PostgreSQL，事务内断言）

1. `uq_ip_addresses_cluster_ip`：同集群同 `ip_key` 拒绝（`23505`）；跨集群同地址允许；删除后重新插入同地址成功；deferrable：同事务内先删后建同址（`SET CONSTRAINTS ... DEFERRED`）成功。
2. `chk_ip_addresses_ip`：合法 IPv4 通过；IPv6/前导零八位组/非法/缺段拒绝；`ip_key = ip` 生成列恒等。
3. `fk_ip_addresses_interface ON DELETE RESTRICT`：删除仍有 IP 的网卡 → `23503`（映射 `409 INTERFACE_HAS_IPS`）。
4. `fk_ip_addresses_segment ON DELETE RESTRICT`：约束存在且 `confdeltype='r'`（RESTRICT）；删除仍有已分配 IP 的网段**由应用前置**返回 `409 SEGMENT_HAS_ALLOCATIONS`（FK 为兜底，通常先命中网卡 FK）。
5. **复合 FK 成员关系**：以 `segment_id ≠` 网卡所选网段的 IP 插入 → `23503`（`fk_ip_addresses_interface_segment`）；相等通过；网卡 `segment_id IS NULL` 时插入 IP → `23503`。
6. **网卡改段兜底**：网卡仍有 IP 时 UPDATE `segment_id` → `23503`。
7. **冗余列钉住**：插入 `resource_id`/`cluster_id` ≠ 所属网卡 → `23503`（`fk_ip_addresses_interface_resource`）。
8. **管理 IP 归属**：`resources.management_ip_id` 指向非本资源 IP → `23503`（`fk_resources_management_ip`）；指向本资源 IP 通过；`NULL` 通过。
9. **管理 IP 删除保护**：删除仍被 `management_ip_id` 引用的 IP → `23503`（映射 `422 MANAGEMENT_IP_REQUIRED` 兜底）；先清空/重选再删通过。
10. `network_interfaces` 附加唯一约束：`uq_network_interfaces_id_segment`/`uq_network_interfaces_id_resource_cluster` 存在且可作 FK 目标（建表顺序验证）。
11. `resources.management_ip_id`：既有行缺省为 `NULL`；`ADD COLUMN` 后既有数据不变；`ix_resources_management_ip_id` 存在。

### 10.2 `SegmentUsage` 查询测试

- `allocated_count(segment_id)`：0 / 多行 / 跨网段隔离正确。
- `allocated_ip_nums(cluster_id)`：集合内容覆盖该集群所有网段（含重叠）；跨集群隔离；已删除网段的历史不影响集合。

### 10.3 初始化脚本测试

- 空库顺序执行 + 重复执行：幂等、无错误；`ip_addresses` 表、附加列/约束/索引只创建一次；无新增触发器。
- 已有数据（F002 已交付库）执行增量：`network_interfaces` 附加唯一约束成功、`resources` 加列成功、既有行 `management_ip_id=NULL`。

## 11. Backend 可依赖的保证（公共契约）

1. **唯一性**：`ip_addresses` 在 `(cluster_id, ip_key)` 上唯一（作用域限仍存行）；跨集群可重复；删除后地址可复用；冲突映射 `409 IP_ALREADY_IN_USE`/`NO_AVAILABLE_ADDRESS`（按上下文）。
2. **比较键一致**：`ip_key` 恒等于 `ip`（生成列）；Backend 只需在写入前完成 IPv4 规范化即保证唯一性口径正确。
3. **引用完整与删除保护**：`interface_id`/`segment_id` 为 RESTRICT FK；`23503` 出现即表示仍有关联，按约束名映射 `409`（`INTERFACE_HAS_IPS`/`SEGMENT_HAS_ALLOCATIONS`）或 `422`（改段/管理 IP），事务回滚。
4. **成员关系**：「IP 属于网卡所选网段」「管理 IP 属于本资源」由复合 FK 保证；Backend 写冗余列时取自网卡/资源，无需自行维护一致性。
5. **格式护栏**：IPv4 格式、NOT NULL、PK、时间默认值由 CHECK/表结构保证；CIDR 内、选址、排除属应用保证。
6. **删除语义**：删除网卡/网段/IP 不级联；IP 真实删行无恢复；管理 IP 删除受 RESTRICT 保护；历史/审计无业务 FK、append-only、长期保留。
7. **初始化幂等**：新增 `ip_addresses` 由 `create_all` 覆盖；F002 表附加列/约束/索引由幂等增量 DDL 落地；无新增触发器；重复执行不报错。
8. **计数查询**：`allocated_count(segment_id)`/`allocated_ip_nums(cluster_id)` 有对应索引；`allocated_ip_nums` 只读现存行、不读历史。

## 12. 与架构 §3 的偏差与标记

1. **偏差 A（`network_interfaces` 附加唯一约束命名/组合）**：架构 §3.3 列出可加 `UNIQUE(id, cluster_id)`、`UNIQUE(id, segment_id)`。本设计采用 `UNIQUE(id, segment_id)` + **`UNIQUE(id, resource_id, cluster_id)`**（后者同时钉住 `resource_id` 与 `cluster_id`，替代单独的 `UNIQUE(id, cluster_id)`）。属附加、无破坏、无列/语义变化。
2. **偏差 B（复合 FK 组合）**：`fk_ip_addresses_interface_resource (interface_id, resource_id, cluster_id)` 单条 FK 钉住两个冗余列；架构 §3.1 将冗余列归属列为 `PROPOSED`、由 Database 决定，本选择在授权范围内。
3. **偏差 C（`ip_key` 与可延迟性）**：采用生成列 `= ip` + `UNIQUE(cluster_id, ip_key) DEFERRABLE INITIALLY IMMEDIATE`，与架构 §3.1 PROPOSED（生成列、可延迟）一致；应用仍按 delete→create 顺序写入。
4. **偏差 D（管理 IP 归属的 DB 表达）**：架构 §3.2 PROPOSED 的复合 FK 方案被采用（`ip_addresses` 冗余 `resource_id` + `UNIQUE(resource_id,id)` + `resources (id, management_ip_id) → ip_addresses(resource_id,id)`）；未采用「应用保证 + 测试」。
5. **对齐无偏差**：`ip_addresses` 列集合、`UNIQUE(cluster_id, ip_key)`、`segment_id`/`interface_id` RESTRICT FK、CHECK IPv4、无 `status`/`deleted_at`、`resources.management_ip_id` 可空 + RESTRICT + 不 `SET NULL`、不新增 IP 级历史表、不建触发器、`SegmentUsage` 只读查询——均与架构 §3 一致。
6. 架构 §3.1 提到 `id`「供 F012 查询」、`created_at` 无 `updated_at`：本设计一致。

**标记汇总**：
- `CONFIRMED`：§0 依赖顺序、§1、§2.1 列集合与 §3 REQUIRED-1/2/3/4/10/11/12、§2.2 可空列与不 `SET NULL`、§4 查询语义与消费方、§5 网段/网卡删除保护映射、§6 不建触发器/只写历史、§7.1 顺序与 §7.5 变更纪律、§8.1、§9.1–9.6、§10.4 权限边界。
- `PROPOSED`：§2.4/§2.5 复合 FK 选择、§2.1 `ip_key` 生成列与可延迟唯一、§7.3 `use_alter`/幂等 ALTER 落地方式、§3.1（cluster_id,ip_key）不重复索引、§9 附加列迁移记录、§12 偏差 A–D。
- `OPEN`（非阻塞）：`ip_key` 是否长期保留（若 F012 需按地址检索再评估）、`ip_addresses` 是否需要额外查询索引（P0 规模无必要）、F005 合约需同步修订 `RESERVED_ADDRESS_CONFLICTS_ALLOCATION`/`GATEWAY_CONFLICTS_ALLOCATION`（协调器执行，不改变本 Schema）。
