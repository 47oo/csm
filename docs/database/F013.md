## 0. 交付边界

- 本设计覆盖 F013 独占的 5 张表：`users`、`user_credentials`、`sessions`、`reserved_usernames`、`audit_log`。
- `audit_log` 为跨 Feature 复用的公共审计载体（F001/F002/F005/F006/F007/F012 经 `app.audit.write` 写入）；F013 定义其 Schema 与写入契约，不定义各 Feature 的 action 取值集。
- 用户/角色**不属于受管资源**（`domain-model.md` §2.1）：无集群归属、不写受管资源历史。F013 **不建**资源历史表。
- 本设计不包含：审计查询 API（F013 不提供）、资源历史表（F012/F007）、各受管对象 Schema。

## 1. 实体与关系概览

```
users (1) ──── (1) user_credentials          [user 删除 → credential 删除]
users (1) ──── (0..N) sessions               [user 删除 → session 删除]
users (1) ──── (0..N) audit_log.actor_user_id [user 删除 → actor_user_id 置 NULL，审计行保留]
reserved_usernames                           [无 FK，独立保留标识，只增不删]
```

- 主键统一 `BIGINT GENERATED ALWAYS AS IDENTITY`（`users`、`sessions`、`audit_log`）；`user_credentials.user_id` 与 `reserved_usernames.username_key` 为自然主键。
- 命名：表名/列名 `snake_case`；时间列统一 `TIMESTAMPTZ`（RFC 3339 UTC，与 Contract 一致）。
- 枚举以 `TEXT + CHECK` 表达，**不使用 PostgreSQL 原生 enum**（演进成本：本设计与 AGENTS §2.6、ADR-002 一致，避免无迁移工具下 enum 增删值的破坏性变更）。
- 比较键与展示值分离（ADR-002/BQ-W）：展示保留输入形态，唯一性只用比较键。

## 2. 表设计

### 2.1 `users`

**用途**：平台用户主表（身份、单一角色、启用状态、乐观锁）。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | 稳定用户 ID |
| `username` | `text` | NOT NULL | — | `CHECK (username ~ '^[A-Za-z0-9]{1,128}$')` | 仅字母与数字、长度 1–128；创建后不可修改（BQ-X） |
| `username_key` | `text` | NOT NULL | — | `GENERATED ALWAYS AS (username) STORED`；UNIQUE | 判重/登录比较键：区分大小写（无空格，BQ-W/BQ-X） |
| `role` | `text` | NOT NULL | — | `CHECK (role IN ('viewer','maintainer','admin'))` | 单一角色（§2.1/§4.9.4） |
| `status` | `text` | NOT NULL | `'enabled'` | `CHECK (status IN ('enabled','disabled'))` | 启用/禁用；禁用≠删除（§4.9.6） |
| `must_change_password` | `boolean` | NOT NULL | `true` | — | 首登强制改密（§4.9.11） |
| `version` | `integer` | NOT NULL | `1` | `CHECK (version >= 1)` | 乐观锁（PATCH/DELETE 用） |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — | |
| `updated_at` | `timestamptz` | NOT NULL | `now()` | — | 任何 UPDATE 时由 Backend 刷新 |

**约束与索引**

| 名称 | 类型 | 定义 | 服务的查询/约束 |
| --- | --- | --- | --- |
| `pk_users` | PK | `(id)` | 详情、修改、删除、会话 join |
| `uq_users_username_key` | UNIQUE | `(username_key)` | 仍存用户内用户名唯一；登录比较键查找（`POST /auth/login`） |
| `chk_users_username_format` | CHECK | `username ~ '^[A-Za-z0-9]{1,128}$'` | 仅字母与数字、长度 1–128（BQ-X） |
| `chk_users_role` | CHECK | `role IN (...)` | 固定三角色 |
| `chk_users_status` | CHECK | `status IN (...)` | 固定状态 |
| `chk_users_version` | CHECK | `version >= 1` | 乐观锁数值合法 |
| `ix_users_status` | btree | `(status)` | 列表状态过滤（`GET /users?status=`） |
| `ix_users_role` | btree | `(role)` | 列表角色过滤（`GET /users?role=`） |
| `ix_users_created_at` | btree | `(created_at)` | 排序 `sort=created_at`/`-created_at` |

> 列表默认排序 `sort=username` 建议按 `username_key` 排序（同一比较键语义、可走 `uq_users_username_key` 索引），展示仍返回 `username`。`q` 为包含匹配（`ILIKE %q%`，`%`/`_` 转义），P0 规模（~千级用户）无需 trigram 索引；若后续用户量增大再评估（非阻塞）。
> `username_key` 由生成列保证与 `username` 一致，**不依赖应用层自行计算**。`btrim` 去除首尾 ASCII 空格（U+0020）；见 §9 开放项。

**乐观锁写模式（Backend 必须遵守，REQUIRED）**
```sql
UPDATE users
   SET role = :role, version = version + 1, updated_at = now()
 WHERE id = :id AND version = :expected_version;
-- rowcount = 0 → 409 VERSION_CONFLICT（Contract §0/§3.4/§3.5）
```
- `version` 在任何对 `users` 行的 UPDATE 上自增（改用户名/角色/状态/改密标记）。
- `PATCH /users/{id}`、`DELETE /users/{id}` 必须携带客户端 `version` 并走条件更新；`disable`/`enable`/`reset-password` 无 `version` 参数（Contract）但仍使 `version` 自增（实现为普通 UPDATE）。冲突仅在使用方传入 `version` 时映射为 `409`。

### 2.2 `user_credentials`

**用途**：每用户当前口令哈希（1:1）。与 `users` 分表，避免列表查询误带哈希，并为未来凭据元数据留位。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `user_id` | `bigint` | NOT NULL | — | PK；FK → `users(id)` ON DELETE CASCADE | 1:1 由此 PK 保证“每用户至多一条” |
| `password_hash` | `text` | NOT NULL | — | `CHECK (length(password_hash) > 0)` | Argon2id 编码串（算法+参数+salt+hash），由 `app.security.password` 生成/校验 |
| `password_updated_at` | `timestamptz` | NOT NULL | `now()` | — | 改密/重置时间 |

**约束与索引**

| 名称 | 类型 | 定义 | 服务 |
| --- | --- | --- | --- |
| `pk_user_credentials` | PK | `(user_id)` | 1:1；登录时按 `user_id` 取哈希 |
| `fk_user_credentials_user` | FK | `user_id → users(id) ON DELETE CASCADE` | 用户删除时凭据随之删除（§4.9.7 历史由审计承载） |

> 口令策略（≥8 位且含字母与数字）**不在数据库强制**，由 `app.security.password` 统一校验（架构 §4.3，三处调用点）。数据库只保证哈希非空。
> “每用户至少一条凭据”由 Backend 在同一事务内插入保证（初始化预置与 `POST /users` 均写入）；DB 无法非循环地强制 `users→user_credentials` 的存在性。若产品/架构要求 DB 强约束“必有一条”，可改为将 `password_hash NOT NULL` 并入 `users`（更简单但降低职责分离），本设计**不采用**。

### 2.3 `sessions`

**用途**：服务端会话；只存 token 哈希，不存明文 token。登出/删除/禁用/改密使其失效。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | |
| `token_hash` | `text` | NOT NULL | — | UNIQUE；`CHECK (length(token_hash) > 0)` | 高熵随机 token 的 SHA-256 hex；不存明文（架构 §4.2） |
| `user_id` | `bigint` | NOT NULL | — | FK → `users(id)` ON DELETE CASCADE | |
| `created_at` | `timestamptz` | NOT NULL | `now()` | — | |
| `expires_at` | `timestamptz` | NOT NULL | — | `CHECK (expires_at > created_at)` | 绝对 TTL（PROPOSED 默认 12h） |
| `last_seen_at` | `timestamptz` | NULL | — | — | 可选 |
| `revoked_at` | `timestamptz` | NULL | — | — | 登出/改密等撤销时间；NULL=未撤销 |

**约束与索引**

| 名称 | 类型 | 定义 | 服务 |
| --- | --- | --- | --- |
| `pk_sessions` | PK | `(id)` | |
| `uq_sessions_token_hash` | UNIQUE | `(token_hash)` | 每请求会话解析：`WHERE token_hash = :h AND revoked_at IS NULL AND expires_at > now()` |
| `fk_sessions_user` | FK | `user_id → users(id) ON DELETE CASCADE` | 删除用户时删除其会话（§4.9.7） |
| `chk_sessions_expiry` | CHECK | `expires_at > created_at` | 会话有效期合法 |
| `ix_sessions_user_id` | btree | `(user_id)` | 改密/重置后按用户批量撤销；级联删除 |
| `ix_sessions_expires_at` | btree | `(expires_at)` | 过期清理/诊断（P0 非强制定时清理，可惰性删除） |

> 失效语义（架构 §4.5）：登出→`revoked_at=now()`；改密/重置→该用户全部活动会话 `revoked_at=now()`（PROPOSED）；禁用→靠每请求读 `users.status` 即可（无需删会话，但可选撤销）；删除用户→CASCADE 删除。
> 过期/撤销判定是**查询谓词**（`revoked_at IS NULL AND expires_at > now()`），非 DB 约束：DB 不阻止读取过期行，但所有会话解析必须带该谓词。

### 2.4 `reserved_usernames`

**用途**：用户名跨删除不复用的保留标识表；主键为比较键，**只增不删**。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `username_key` | `text` | NOT NULL | — | PK；`CHECK (btrim(username_key) <> '')` | 去首尾空格、区分大小写的比较键；**永不删除** |
| `reserved_at` | `timestamptz` | NOT NULL | `now()` | — | 首次占用时间 |

**约束与索引**

| 名称 | 类型 | 定义 | 服务 |
| --- | --- | --- | --- |
| `pk_reserved_usernames` | PK | `(username_key)` | 仍存或历史用户名的唯一保留；创建/改名冲突源（→ 409 USERNAME_TAKEN） |
| `chk_reserved_username_key_not_blank` | CHECK | `btrim(username_key) <> ''` | 禁纯空白 |
| `trg_reserved_usernames_no_delete` (PROPOSED) | 触发器 | `BEFORE DELETE OR UPDATE → RAISE EXCEPTION` | 强制只增不删（ADR-002/§3） |

**写入规则（Backend 必须遵守）**
- 创建用户：同一事务内先 `INSERT INTO reserved_usernames(username_key) VALUES (btrim(username))`，冲突 → `409 USERNAME_TAKEN`；成功后插入 `users`。
- 用户名创建后不可修改（BQ-X）；不存在改名写入路径。
- 删除用户：**不**删除任何 `reserved_usernames` 行。
- 与 `users.username_key` 的关系：`reserved_usernames` 覆盖“含已删除”的全历史；`users.username_key` 覆盖“仍存用户内唯一”。两者皆为 DB 唯一约束，先插保留表可同时拦截两类冲突。

### 2.5 `audit_log`

**用途**：跨 Feature 复用、append-only 的操作审计（ADR-005）。记录操作者、时间与关键变更；用户/角色管理操作 `target_type='user'`。

| 列 | 类型 | NULL | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `bigint` | NOT NULL | identity | PK | |
| `occurred_at` | `timestamptz` | NOT NULL | `now()` | — | 操作时间 |
| `actor_user_id` | `bigint` | NULL | — | FK → `users(id)` ON DELETE SET NULL | 操作者；系统动作（预置）为 NULL |
| `actor_username_snapshot` | `text` | NOT NULL | — | `CHECK (btrim(actor_username_snapshot) <> '')` | 操作者名快照；系统动作为 `'system'`；**用户删除后仍可读** |
| `action` | `text` | NOT NULL | — | `CHECK (btrim(action) <> '')` | 动作标识（如 `user.create`）；**不设固定集合**，供各 Feature 扩展 |
| `target_type` | `text` | NOT NULL | — | `CHECK (btrim(target_type) <> '')` | 目标类型（用户管理为 `'user'`） |
| `target_id` | `text` | NULL | — | — | 目标 ID（存字符串；不设 FK，保证删除后仍可读） |
| `target_key_snapshot` | `text` | NULL | — | — | 目标关键标识快照（如用户名） |
| `change` | `jsonb` | NOT NULL | `'{}'::jsonb` | — | 关键变更内容 |
| `result` | `text` | NOT NULL | — | `CHECK (result IN ('success','failure'))` | 结果 |

**约束与索引**

| 名称 | 类型 | 定义 | 服务 |
| --- | --- | --- | --- |
| `pk_audit_log` | PK | `(id)` | |
| `fk_audit_log_actor` | FK | `actor_user_id → users(id) ON DELETE SET NULL` | 用户删除不丢审计 |
| `chk_audit_log_result` | CHECK | `result IN ('success','failure')` | 结果取值 |
| `chk_audit_log_*_not_blank` | CHECK | `action/actor_username_snapshot/target_type` 非空 | 关键字段完整性 |
| `ix_audit_log_occurred_at` | btree | `(occurred_at DESC)` | 时间序查询（F012/后续审计查询） |
| `ix_audit_log_actor` | btree | `(actor_user_id)` | 按操作者查询 |
| `ix_audit_log_target` | btree | `(target_type, target_id)` | 按目标对象查询 |
| `trg_audit_log_append_only` (PROPOSED) | 触发器 | `BEFORE UPDATE OR DELETE → RAISE EXCEPTION` | 强制 append-only（ADR-005） |

> `action` **不设固定 CHECK 集合**：审计为跨 Feature 复用载体，受管对象 Feature 会新增 action 值；固定集合会在无迁移工具下造成演进成本。仅约束非空。
> `actor_user_id` 用 `ON DELETE SET NULL` 而非 CASCADE：**不因删除用户而级联删除审计**（架构 §3、ADR-005）。
> 审计行只由 `app.audit.write(...)` 追加；F013 不提供审计查询 API。

## 4. 删除 / 禁用 / 改密 / 会话行为

### 4.1 删除用户（默认采用物理删除，ADR-002 允许）

删除前同一事务内校验：目标为启用中的 `admin` 且启用中的 `admin` 总数=1 → 拒绝 `409 LAST_ADMIN`，不删除（BQ-X）。

在**单个事务**内：
1. 追加审计行（`action='user.delete'`、`actor`=当前管理员、`target_type='user'`、`target_key_snapshot`=用户名）。
2. `DELETE FROM users WHERE id=:id AND version=:expected`（rowcount=0 → 409 VERSION_CONFLICT；不存在 → 404，由 Backend 先查）。
3. `user_credentials`、`sessions` 经 FK `ON DELETE CASCADE` 随之删除。
4. `reserved_usernames`（该用户所有历史比较键）与 `audit_log`（含该用户既有审计）**保留**；既有审计行 `actor_user_id` 由 FK 置 NULL，`actor_username_snapshot` 仍可读。

等价不变量（任何替代实现——含保留 `users` 行 + 标记——都必须满足）：
- 被删账号**不能登录**；
- 其用户名（比较键）**不可复用**（由 `reserved_usernames` 独立保证，与 `users` 是否留存无关）；
- 其历史审计**保留**且可读。

> 本设计**采用物理删除**：直接满足上述三点、与 ADR-002「不预设直接删行」且「不预设软删」兼容，且避免引入产品未确认的 `deleted_at`/tombstone 语义（AGENTS §2.8）。若架构后续改判保留 `users` 行为软删，`reserved_usernames` 与审计语义不变，`users` 需保留比较键唯一性。

### 4.2 禁用/启用
- `UPDATE users SET status='disabled'|'enabled', version=version+1, updated_at=now()`；幂等。禁用前同一事务内校验：目标为启用中的 `admin` 且启用中的 `admin` 总数=1 → 拒绝 `409 LAST_ADMIN`（BQ-X）。
- 禁用后**每请求读 `users.status`**（架构 §2.2/§4.5）即拒绝登录/操作；可选同时撤销其活动会话（`revoked_at=now()`）。记录审计（`user.disable`/`user.enable`）。

### 4.3 改密 / 重置口令
- 更新 `user_credentials.password_hash`、`password_updated_at`；自助改密同时 `users.must_change_password=false`；管理员重置置 `must_change_password=true`（PROPOSED）；均自增 `users.version`。
- 改密/重置后按 `user_id` 撤销该用户活动会话（PROPOSED，`sessions` 行保留但 `revoked_at` 非空）。
- 记录审计（`user.change_password`/`user.reset_password`）。数据库不校验口令策略。

### 4.4 会话生命周期
- 创建：随机 token → 存 `token_hash`、`user_id`、`expires_at=now()+TTL`。
- 登出：`revoked_at=now()`（幂等；无会话也返回 204，Contract §2.2）。
- 过期行 P0 不做强制定时清理；按 `expires_at` 惰性删除或后续维护（无产品/架构删除保留要求，审计另存）。

## 5. 首次建表与初始化方案（P0 无迁移工具，ADR-002）

### 5.1 幂等初始化脚本（如 `scripts/init_db.py`）
在**一个事务**内执行：
1. **建表与约束**：优先使用 SQLAlchemy 2.0 元数据 `Base.metadata.create_all`（等价 `CREATE TABLE IF NOT EXISTS`）建立 5 张表、PK/FK/UNIQUE/CHECK/普通索引；对 `create_all` 不能表达的项（生成列 `username_key`、append-only 触发器）以显式 DDL 补充。
   - SQLAlchemy 映射提示：`username_key = mapped_column(Computed("btrim(username)", persisted=True), unique=True)`；`Identity()` 主键；`DateTime(timezone=True)`；`JSONB`。
2. **首个管理员预置**：仅当 `SELECT count(*) FROM users WHERE role='admin'` = 0 时执行：
   - 读取 `CSM_INITIAL_ADMIN_USERNAME` / `CSM_INITIAL_ADMIN_PASSWORD`；
   - 未提供口令时生成高熵随机口令并**一次性打印到部署日志**；
   - 同一事务写入 `reserved_usernames`（比较键）→ `users`（`role='admin'`、`status='enabled'`、`must_change_password=true`）→ `user_credentials`（Argon2id 哈希）→ 审计行（`actor_user_id=NULL`、`actor_username_snapshot='system'`、`action='bootstrap.create_admin'`）。
3. **幂等性要求**：重复执行不报错、不覆盖已有数据；已存在 admin 时跳过预置；`reserved_usernames` 写入用 `ON CONFLICT DO NOTHING` 仅限预置路径（业务路径仍以冲突→409）。
4. 部署时机：Docker Compose 启动前/启动钩子执行一次（ADR-004 内网 Docker Compose）。

### 5.2 参考 DDL（Backend 可据此落地）
```sql
CREATE TABLE users (
  id                    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  username              text        NOT NULL CHECK (username ~ '^[A-Za-z0-9]{1,128}$'),
  username_key          text        GENERATED ALWAYS AS (username) STORED NOT NULL,
  role                  text        NOT NULL CHECK (role IN ('viewer','maintainer','admin')),
  status                text        NOT NULL DEFAULT 'enabled' CHECK (status IN ('enabled','disabled')),
  must_change_password  boolean     NOT NULL DEFAULT true,
  version               integer     NOT NULL DEFAULT 1 CHECK (version >= 1),
  created_at            timestamptz NOT NULL DEFAULT now(),
  updated_at            timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_users_username_key UNIQUE (username_key)
);
CREATE INDEX ix_users_status     ON users (status);
CREATE INDEX ix_users_role       ON users (role);
CREATE INDEX ix_users_created_at ON users (created_at);

CREATE TABLE user_credentials (
  user_id             bigint      PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  password_hash       text        NOT NULL CHECK (length(password_hash) > 0),
  password_updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE sessions (
  id           bigint      GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  token_hash   text        NOT NULL UNIQUE CHECK (length(token_hash) > 0),
  user_id      bigint      NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at   timestamptz NOT NULL DEFAULT now(),
  expires_at   timestamptz NOT NULL,
  last_seen_at timestamptz,
  revoked_at   timestamptz,
  CONSTRAINT chk_sessions_expiry CHECK (expires_at > created_at)
);
CREATE INDEX ix_sessions_user_id    ON sessions (user_id);
CREATE INDEX ix_sessions_expires_at ON sessions (expires_at);

CREATE TABLE reserved_usernames (
  username_key text        PRIMARY KEY CHECK (btrim(username_key) <> ''),
  reserved_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE audit_log (
  id                      bigint      GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  occurred_at             timestamptz NOT NULL DEFAULT now(),
  actor_user_id           bigint      REFERENCES users(id) ON DELETE SET NULL,
  actor_username_snapshot text        NOT NULL CHECK (btrim(actor_username_snapshot) <> ''),
  action                  text        NOT NULL CHECK (btrim(action) <> ''),
  target_type             text        NOT NULL CHECK (btrim(target_type) <> ''),
  target_id               text,
  target_key_snapshot     text,
  change                  jsonb       NOT NULL DEFAULT '{}'::jsonb,
  result                  text        NOT NULL CHECK (result IN ('success','failure'))
);
CREATE INDEX ix_audit_log_occurred_at ON audit_log (occurred_at DESC);
CREATE INDEX ix_audit_log_actor       ON audit_log (actor_user_id);
CREATE INDEX ix_audit_log_target      ON audit_log (target_type, target_id);

-- append-only / 只增不删（PROPOSED，Backend 实现；测试可用 TRUNCATE 或 session_replication_role 绕过）
CREATE OR REPLACE FUNCTION csm_reject_mutation() RETURNS trigger AS $$
BEGIN RAISE EXCEPTION 'append-only table: % mutation rejected', TG_TABLE_NAME; END; $$ LANGUAGE plpgsql;
CREATE TRIGGER trg_audit_log_append_only BEFORE UPDATE OR DELETE ON audit_log
  FOR EACH ROW EXECUTE FUNCTION csm_reject_mutation();
CREATE TRIGGER trg_reserved_usernames_append_only BEFORE UPDATE OR DELETE ON reserved_usernames
  FOR EACH ROW EXECUTE FUNCTION csm_reject_mutation();
```

### 5.3 无迁移工具下的后续 Schema 变更纪律（AGENTS §6）
- P0 为绿地；**P0 内不改本 Feature 的已定 Schema**。
- 后续任何 F013 Schema 变更必须：① 先经架构/决策确认（如需产品规则，先回 Product）；② 在 `docs/database/` 记录变更、受影响查询/约束、已有数据处理、验证与回滚风险；③ 考虑已有数据，**不得未评估即执行破坏性修改**。
- 因 P0 无备份（ADR-004）且无迁移工具：变更应以**增量、向前兼容**方式手工脚本化（如 `scripts/migrations/NNNN_*.sql`），破坏性变更需 Product 明确确认；回滚以**前向修复**为主（无备份不可依赖还原）。
- 不得删除 `reserved_usernames` 或 `audit_log` 中因业务删除而保留的行。

## 6. 验证方式与测试项

### 6.1 数据库约束测试（pytest + 真实 PostgreSQL，事务内断言）
1. `users.username_key` 唯一：插入相同比较键（含大小写差异应**允许**、去空格后相同应**拒绝**）→ 验证 BQ-W。
2. `btrim(username)=''` 被拒绝；`username=" abc "` 可存且 `username_key='abc'`。
3. `role`/`status` 非法值被 CHECK 拒绝。
4. `version` 条件更新：`WHERE version` 不匹配 rowcount=0（→409）；匹配则自增。
5. 删除 `users` 行：`user_credentials`、`sessions` 同级行被 CASCADE 删除。
6. 删除 `users` 行：`audit_log.actor_user_id` 置 NULL，审计行与快照仍在；`reserved_usernames` 行仍在。
7. 对 `audit_log`、`reserved_usernames` 执行 UPDATE/DELETE 被触发器拒绝（append-only / 只增不删）。
8. 无 `users` 行也能保留 `reserved_usernames`（跨删除不复用语义）。
9. `sessions.expires_at <= created_at` 被拒绝；会话解析谓词排除过期/撤销会话。

### 6.2 初始化脚本测试
- 空库执行两次：第二次幂等、无错误、无重复预置；`reserved_usernames`/审计各只 1 条预置记录。
- 无 `CSM_INITIAL_ADMIN_PASSWORD` 时生成随机口令且仅日志打印一次；管理员 `must_change_password=true`。

### 6.3 集成/验收映射（Backend 与 Test 执行）

## 7. Backend 可依赖的保证（公共契约）

1. **唯一性**：任意时刻 `users.username_key` 唯一；`reserved_usernames.username_key` 唯一且只增；创建/改名唯一冲突可直接映射 `409 USERNAME_TAKEN`。
2. **比较键一致**：`users.username_key` 恒等于 `username`（生成列），Backend 无需自行维护一致性；登录与判重统一使用该键。
3. **枚举稳定**：`role ∈ {viewer,maintainer,admin}`、`status ∈ {enabled,disabled}`、`audit_log.result ∈ {success,failure}` 由 CHECK 保证。
4. **并发**：以 `version` 条件更新实现乐观锁，DB 保证 `version ≥ 1`；冲突由 rowcount 判定。
5. **删除语义**：删除 `users` 自动清 `user_credentials`/`sessions`，保留 `reserved_usernames` 与审计；审计 `actor_user_id` 自动置 NULL。Backend **不应对保留表/审计表执行 DELETE/UPDATE**。
6. **会话**：`token_hash` 全库唯一；会话有效性 = `revoked_at IS NULL AND expires_at > now()`。
7. **审计写入**：`app.audit.write(actor, action, target_type, target_id, target_key_snapshot, change, result)` 插入单行；`actor=None` 时 `actor_user_id=NULL`、`actor_username_snapshot='system'`；append-only。

## 9. 假设与开放问题

- `CONFIRMED`：本文件所有约束/索引/删除行为均从已确认需求与已批准 ADR/架构派生，不新增业务规则。
- `PROPOSED`（实现建议，非产品规则，不影响 READY）：
  1. `version` 在任意 `users` UPDATE 上自增；
  2. 改密/重置/禁用撤销会话；新增/重置置 `must_change_password=true`；
  3. `token_hash` 采用 SHA-256 hex（`text`）；
  4. append-only 与只增不删用触发器强制；
  5. `username_key` 用生成列。
- `OPEN`（**非阻塞本设计**，返回 Product 供后续确认）：
  1. **用户名长度/字符集（已裁定，BQ-X）**：仅字母与数字、长度 1–128；由 CHECK 与前端校验共同保证。
  2. **“首尾空格”口径（已随 BQ-X 消解）**：用户名仅字母与数字、不含空格，trim 语义不再适用。
  3. `D-LAST-ADMIN`（已裁定，BQ-X）：禁止删除或禁用**最后一个启用中的管理员**；DB 不设约束（计数校验在 Backend 事务内完成），拒绝返回 `409 LAST_ADMIN`。
- 上述均已裁定，**不阻塞数据库实现**。
