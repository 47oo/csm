本文件是 CSM V2 领域规则的权威来源。状态标记：`CONFIRMED` / `PROPOSED` / `OPEN`，定义见 `docs/product/requirements-v2.md`。

## 1. 资源概念与分类 `CONFIRMED`

- “资源（Resource）”是统一业务概念，**不是单一实体或单张表**。
- 计算资源（ComputeResource）：共用实体，`resource_type ∈ {bare_metal, virtual_machine}`，具有稳定 `resource_id` 及公共属性（所属集群、名称、资源类型、创建/更新时间）；真实删除后资源历史另行保留（至少操作人及删除/变更内容，P0 仅管理员可查、不自动到期清除；具体载体 `OPEN`）。
- P0 采用独立模型（不并入计算资源公共表）：Cluster、NetworkSegment、IP、NetworkInterface、Service、DeploymentInstance。
- `resource_type` 创建后不可直接修改。
- 计算资源所属集群在 P0 创建后不可通过普通编辑修改；集群 `code` 创建后不可改，去首尾空格并统一大写后判重，真实删除后仍不复用；集群名称不可重复、可修改，只允许字母/中文/下划线/数字，含空格直接拒绝且判重区分大小写，真实删除后名称可复用；其余属性与字符边界见 `requirements-v2.md` §4.1、§11.2（BQ-M）。
- 展示口径与存储口径的一致性策略属于架构待决事项，不新增产品约束。

## 2. 实体与关键属性

| 实体 | 关键属性 | 状态 |
| --- | --- | --- |
| Cluster | `code`（去首尾空格、统一大写后全局判重；创建后不变、真实删除后仍不复用）、名称（仅字母/中文/下划线/数字，含空格拒绝、区分大小写；真实删除后可复用）、用途（可修改） | `CONFIRMED`（BQ-M）；字符范围/历史载体 `OPEN` |
| ComputeResource | `resource_id`、所属集群、`name`、`resource_type`、状态（`IDLE`/`ALLOC`/`DOWN`/`UNKNOWN`，默认 `ALLOC`）、管理 IP（引用已登记网卡 IP，nullable） | `CONFIRMED`；删前逐项处理子项，部分具体操作仍 `OPEN` |
| BareMetalDetail | SN、CPU、内存、GPU、其他硬件信息 | `CONFIRMED` 存在；必填范围 `OPEN` |
| VirtualMachineDetail | 宿主 `resource_id`、vCPU、内存 | `CONFIRMED` 存在；必填范围 `OPEN` |
| NetworkInterface | 所属计算资源、接口名、可选网段（0..1）、IP 集合 | `CONFIRMED`（BQ-H） |
| NetworkSegment | 所属集群、名称、规范化 CIDR、用途、技术类型、VLAN、网关属性、自动分配范围、保留地址 | `CONFIRMED`；删前清地址/网关、删后历史配置不影响其它重叠网段分配；可自动分配数量为当前可用快照（BQ-N、BQ-O、BQ-R） |
| IP | IPv4 值、所属接口/资源；仅以平台记录判定分配可用性 | `CONFIRMED`；真实删除及历史表达细节 `OPEN`（§7） |
| Service | 编号（全局唯一、真删后不复用）、名称、类型、关联集群（0..N）；允许暂时零部署、零关联 | `CONFIRMED`（BQ-H、BQ-S、BQ-U）；入口/端口校验 `OPEN` |
| DeploymentInstance | 所属服务、目标计算资源、角色、实际监听地址/端口（不强制引用节点 IP） | `CONFIRMED`（BQ-H）；端口校验 `OPEN` |
| 访问入口（AccessEndpoint） | 服务访问入口（VIP / 域名 / 端口），与网卡 IP 分开记录 | `CONFIRMED`；每个服务×集群关联允许 0..N 条，可逐条真实删除；关联解除前须删完（BQ-H、BQ-P） |
| 保留地址（ReservedAddress） | 网段下的单个地址或起止范围；删网段前逐条删除 | `CONFIRMED`（BQ-O） |

### 2.1 平台主体与权限 `PROPOSED`（BQ-V；不属于“受管资源”）

> 用户/角色是平台访问控制主体，**不纳入 §1 受管资源集合**：无集群归属、无网卡/IP，不参与 §5 分配与“删除上级先删子项”的受管资源生命周期；其审计与受管资源历史分开承载。

- `User`：用户名（仅字母与数字、长度 1–128、仍存用户内唯一、创建后不可修改）、启用/禁用状态、口令凭据、单一角色；不属于受管资源。最后一个启用中的平台管理员不得删除或禁用（BQ-X）。
- `Role`：运维查看者 / 资源维护者 / 平台管理员（取值 `CONFIRMED`，见 `requirements-v2.md` §2.1）。
- 关系：`User N — 1 Role`（单一角色，BQ-V）。
- 用户/角色的增删改、角色分配、改密/重置、禁用/启用属平台访问控制，仅平台管理员可执行；相关操作进入审计（§9.1），不并入仅管理员可查的受管资源历史。账户语义详见 `requirements-v2.md` §4.9。

## 3. 关系与基数 `CONFIRMED`

- Cluster 1 — N ComputeResource。
- Cluster 1 — N NetworkSegment。
- ComputeResource 1 — N NetworkInterface。
- NetworkInterface 0 — N IP。
- NetworkInterface N — 0..1 NetworkSegment（P0 可不选网段；分配 IP 前必选）。
- VirtualMachine N — 1 BareMetal（宿主；须同集群且有效；不得为 VM 或自身）。
- Service 0..N — 0..N Cluster（服务可暂时零关联；每条服务×集群关联可有 0..N AccessEndpoint；BQ-S）。
- Service 1 — 0..N DeploymentInstance。
- DeploymentInstance N — 1 ComputeResource（须有效；其实例所属集群须在服务关联集群内）。
- AccessEndpoint 归属 Service×Cluster 关联（Q4、BQ-H）；VIP 不自动生成 IP 分配记录。解除关联前逐条删仍存入口、处理关联集群中的部署实例；最后一条关联也可显式解除，服务仍存并可零关联，不影响其它服务入口（BQ-P、BQ-S）。

## 4. 状态模型

- 计算资源（裸金属与 VM 共用）：`IDLE` / `ALLOC` / `DOWN` / `UNKNOWN`，默认 `ALLOC`；由维护人员更新，展示状态来源及更新时间。`CONFIRMED`（2026-09-24 修订，BQ-A）
- 网段：无“停用”或逻辑删除状态；真实删除后不再作为可分配网段（BQ-C、BQ-M）。
- 所有受管资源：登记 → 维护 → 真实删除；不提供逻辑删除或业务恢复入口，审计与资源历史继续保留（BQ-M）。
- `OPEN`：“状态来源”的具体语义（操作者还是来源系统）。

---

## 5. 唯一性与完整性 `CONFIRMED`

- 同集群内仍存计算资源 `name` 唯一（跨裸金属与 VM 统一），跨集群允许重复。
- 同集群内仍存 IPv4 地址全局唯一，跨集群允许重复；VM IP 同规则；真实删除 IP 后释放当前占用，历史不构成在用分配。
- 同一仍存计算资源下接口名唯一。
- 同集群内仍存网段名称、规范化 CIDR 分别唯一；跨集群允许相同 CIDR。
- 服务编号全局唯一、真实删除后也不复用（BQ-U；判重大小写/空格细节仍 `OPEN`）。集群 `code` 去首尾空格并统一大写后全局判重，真实删除后仍不复用；创建后不可改。集群名称在仍存集群中不可重复、区分大小写、含空格直接拒绝，真实删除后名称可复用（BQ-M）；字符类别具体范围见 §7。
- 同集群重叠网段允许登记但提示风险；**仍存网段**的保留地址/网关阻止该地址从其它仍存重叠网段分配，且须位于其所属 CIDR；已真实删除网段的历史保留地址/网关不再参与分配排除（BQ-H、BQ-O）。可自动分配数量按当前范围内真正可分配的地址数计算（含这些排除），只是快照、非预占（BQ-R）；详见 `requirements-v2.md` §5。
- 名称比较口径（BQ-W）：资源名、接口名、网段名、用户名**去首尾空格后区分大小写**、禁止纯空白；服务编号**去首尾空格后统一大写**、真实删除后不复用；集群名称长度 **1–64**。
- “有效”=仍存业务对象；已真实删除对象只留审计和资源历史，不作为在用对象（BQ-M 覆盖 BQ-C 的逻辑删除定义）。
- `REQUIRED`（依据 `requirements-v2.md` §9.3）：上述唯一性必须由数据库/后端最终保证；具体实现交架构与数据库设计。

## 6. 生命周期

- 所有受管资源真实删除，不提供逻辑删除与业务恢复；删除前须将仍存的下级业务对象/关联逐项先删或解除，不隐式级联。已解除仅余历史的关联不阻止删除；审计/资源历史仍保留，历史至少记录操作人与删除或变更内容，P0 仅管理员可查询且不自动到期清除（BQ-M、BQ-N、BQ-Q）。
- 删除宿主机前须逐项真实删除依赖其的 VM，删除任一计算资源前须逐项真实删除指向它的服务部署实例；VM 自身被实例引用或有网卡/IP 时亦须按依赖顺序逐项清理。任一仍存依赖阻止上级删除，不随上级删除自动改挂或级联（BQ-T）。逐项删除 IP 后释放地址占用，再次分配须符合 `requirements-v2.md` §5。网段删前逐项删全部已分配地址/保留地址并显式清空网关；历史配置不阻止其它重叠网段分配（BQ-N、BQ-O）。
- IP 分配 / 释放 / 保留生命周期（含手动、自动、保留、网关、网络/广播地址排除、`/31`、`/32`、耗尽、释放重用）。`CONFIRMED`，详见 `requirements-v2.md` §5。
- 网段被仍存网卡引用、仍有已分配地址/保留地址或网关未清空时禁止直接真实删除；须先逐项处理引用/地址/保留地址、显式清空网关。存在已分配 IP 时禁止修改 CIDR。`CONFIRMED`（BQ-N、BQ-O）
- 无“停用”或逻辑删除状态；只有仍存业务对象参与在用查询/分配（BQ-M）。
- 已登记计算资源无论是否已有网卡/IP，均可通过同一表单追加/修改网卡或 IP；原有接口按原记录编辑，新增 IP 必须满足 §5 全部可分配规则。同名新增不自动覆盖，须由用户确认进入既有资源编辑。`CONFIRMED`（BQ-G、BQ-H）
- 编辑仍有效资源时移除管理 IP 或其网卡，须同次显式清空或重选，否则整单拒绝；删除整个资源不要求预先单独清空管理 IP 字段，但仍须逐项先删除其已分配 IP/网卡等子项。并发编辑冲突须提示、保留输入，不静默覆盖。`CONFIRMED`（BQ-H、BQ-N）
- 集群仅真实删除：仍存计算资源/网段/服务关系须逐项显式解除/删除；已解除只余历史的关联不阻止删除，零关联服务也不阻止集群删除。真实删除后 `code` 永不复用、名称可复用；资源维护者与管理员可删集群，查看者不可。P0 资源历史仅管理员可查且不自动到期清除，载体仍 `OPEN`。服务或服务—集群关联存在对应部署实例时仍拒绝直接删除/解除，不隐式级联实例；逐条删入口、处理实例后可显式解除包括最后一条在内的关联，零关联服务仍存于独立列表、不计入任一集群。删服务前解除所有关联及其子项（BQ-H、BQ-M、BQ-N、BQ-P、BQ-Q、BQ-S）。
