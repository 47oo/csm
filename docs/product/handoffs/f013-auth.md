## Feature

本地账号认证与会话（F013）— CSM V1 的**认证基座**：本地账号登录、服务端会话、全 `/api/*` 认证边界，以及前端登录页与会话失效处理。

---

## Problem

CSM 的定位是**内部运维平台**（`requirements.md` §1、§3、§19），部署在独立内网虚拟机的 Internal IP + HTTP 上（§20、R-DEPLOY-001~003）。F012（基座）与 F001（Cluster）已 DONE，但当前 `/api/*` **完全无认证**——这是显式、临时、已记录的状态（`docs/api/f012-project-foundation.md` §6；`f001-cluster-handoff.md` 问题 9、`f001-cluster.md` 假设 5），不是产品期望的终态。

在这之前，任何能够到达该内网地址的人都可以读写 CSM 中的资源事实数据（当前已有 `/api/clusters*` 的创建与修改能力），且无法知道「是谁在操作」。

使用者：HPC / AI 集群运维人员、基础设施管理员、平台管理员（§3）。他们的使用场景是「打开 CSM 页面 → 登录 → 进行资源登记与查询」，而不是共享一个无身份的公开页面。

F013 的产品价值是：**让 CSM 知道访问者是谁，并使所有资源 API 在未登录时不可写、不可读**；同时为后续全部资源 Feature（F002 ~ F011）提供一套**自动生效、无需逐端点白名单**的认证边界（F001 已把全部端点放在 `/api` 前缀下，正是为此）。

## Confirmed Requirements

仅列已确认内容，来源见括号。**本 Feature 不新增、不修改任何产品规则。**

1. V1 使用**系统本地账号**进行登录认证（R-AUTH-001；§19）。
2. V1 **不接入** LDAP / AD / OAuth / 企业 SSO（R-AUTH-002；§19）。
3. 无明确产品需求时，**不得**由 Architect 自行扩大为复杂 RBAC（R-AUTH-003；§19、§23）。
4. 认证机制已由用户批准（`adr-0005`，`ACCEPTED`，DEC-013）：
   - 本地 `users` 表（`username` 唯一、`password_hash`、`active`、时间戳）；
   - **服务端会话表** + 随机不可预测的 session id；
   - Cookie 设 `HttpOnly` + `SameSite=Lax`；因 V1 为 HTTP，**不设 `Secure`**；
   - 口令存储为 **Argon2id** 哈希。
5. 账号由**管理员初始化 / 种子创建**，**不开放自助注册**（`adr-0005` §1）。
6. 口令**明文不得落库、不得落日志、不得出现在错误信息中**（`adr-0005` §2）。
7. 权限边界**仅两个状态**——已认证 / 未认证；**所有 `/api/*`（登录端点除外）要求认证**；**不引入**角色、权限表或 RBAC（`adr-0005` §4；`csm-v1-foundation-architecture.md` Backend Work）。
8. **登出使服务端会话失效**（`adr-0005` §5）；会话可**即时作废**（登出、管理员禁用账号）（`adr-0005` Consequences）。
9. F013 的交付面已由已批准文档划定：
   - Backend：本地账号模型、口令哈希、登录 / 登出、会话建立与校验、认证中间件、**初始管理员初始化方式**（`csm-v1-foundation-architecture.md` Backend Work）；
   - Frontend：**登录页**（表单、认证失败提示、**会话失效跳转**）（同上 Frontend Work）；
   - Database：`users` / `sessions` 两张认证表及其增量 migration（`docs/database/csm-v1-schema-design.md`；`f012-project-foundation.md`「本次明确不包含 #3」）。
10. `401 UNAUTHENTICATED` 为未认证的语义码；`403 FORBIDDEN` 码值保留，**V1 极少触发**（`docs/api/api-conventions.md` §6）。
11. 部署形态为内网虚拟机、Internal IP + HTTP，**不要求**公网入口 / 域名 / HTTPS（R-DEPLOY-001~003）；因此会话 Cookie 不带 `Secure` 是**已确认的产品取舍**，必须在部署文档中明确「仅限受控内网」（`adr-0005` §3、Consequences）。
12. `users` / `sessions` **不是** Resource Taxonomy 中的资源；认证表**不使用**资源逻辑删除语义 `deleted_at`（`docs/database/csm-v1-schema-design.md`）。
13. 既有与未来的全部 `/api/*` 端点位于 `/api` 前缀下，F013 的认证中间件**自动覆盖**，**无需白名单成员**（`f001-cluster-handoff.md` 问题 9；`f001-cluster.md` NQ-6）。
14. 接口形态遵循已 `READY` 的通用规范（`api-conventions.md` §1、§5、§6）。

## Scope

### 本次包含

1. **本地账号模型与认证数据落地**：`users` / `sessions` 两张表的增量 migration。
2. **口令哈希**：按 `adr-0005` 以 Argon2id 存储；明文不落库 / 日志 / 错误信息。
3. **登录**：已由管理员建立的账号可用用户名 + 口令登录，并建立服务端会话（登录端点是唯一豁免认证的端点）。
4. **登出**：使当前会话在服务端失效。
5. **会话校验**：受保护请求携带会话凭证时被识别为「已认证」；无效 / 过期 / 已登出的会话被识别为「未认证」。
6. **全 `/api/*` 认证边界（基座性质）**：除登录端点外，所有 `/api/*`（含既有 `/api/clusters*` 与未来全部资源端点）在未认证时返回 `401 UNAUTHENTICATED`；该边界**默认覆盖**，未来新增端点**无需白名单**。
7. **初始管理员初始化方式**：交付一条**文档化、可复现**的路径，使运维人员能够建立第一个可登录的账号。
8. **账号禁用即时生效**：`active = false` 的账号不能登录，其既有会话不再可用。
9. **前端登录页**：未登录访问受保护页面 → 登录页；登录成功进入系统；认证失败显示失败提示且不进入系统；收到 `401 UNAUTHENTICATED` 时执行会话失效跳转。
10. **既有端点行为变更的显式记录**：`/api/clusters*` 从「临时无认证」变为「受认证保护」，并在交接与部署文档中说明。

### 本次明确不包含

1. **LDAP / AD / OAuth / 企业 SSO**（R-AUTH-002；§19）。
2. **复杂 RBAC / 角色 / 权限表 / 权限矩阵 / 审批流**（R-AUTH-003；§19、§23；`adr-0005` §4）。
3. **用户自助注册**（`adr-0005` §1 明确「不开放自助注册」）。
4. **HTTPS / 域名 / 公网入口**（R-DEPLOY-003）；不得因 Web 最佳实践自动加入。
5. **把 `User` / `Session` 建模为 Resource、通用 `resources` 表、EAV、STI、JSONB 万能模型**（§4、§24）。
6. **对认证表应用资源逻辑删除语义 `deleted_at` / Undelete**（§17 不适用于认证表）。
7. **把认证 / 会话 / `current_user` 桩塞进其它 Feature 或基座**（F001 / F012 已明确不做，F013 唯一归属）。
8. **生产部署打包（docker-compose / nginx / locale 文档）**——属 F015。

### 本次未涉及

当前需求没有要求，**不能推断为永远不需要**：

- **账号管理能力**（管理员在工作界面创建 / 停用 / 删除账号、重置口令）；
- **用户自助修改口令**；
- **口令找回 / 重置流程**；
- **登录审计**（谁在何时登录 / 登出 / 登录失败）；
- **登录失败频率限制、账号锁定**；
- **多设备会话管理**（查看 / 踢出某会话）；
- **用户名大小写语义**（见 PROPOSED-2 / NQ-5）；
- **「记住我」、会话时长可配置项**；
- **IP / User-Agent 记录**（数据库设计已明确不设计列）；
- **MFA / OTP**。

## 关键问题的正面回答（A ~ E）

### 问题 A — 账号从哪来 & 密码策略

**结论：判定为 Non-blocking。F013 的产品范围可定稿；但两条行为边界（硬约束）必须明确记录，且不得由实现自行补规则。**

逐条对照 Blocking 判据：

| 判据 | 判定 |
|---|---|
| 不确认就无法确定本次功能范围？ | **否**。范围已由 R-AUTH-001~003、`adr-0005`、Backend/Frontend Work 完整划定。 |
| 不确认会导致两种明显不同的用户行为？ | **抽象层面是**，但**权威文档已经给出唯一允许的行为**：`adr-0005` §1 已确认「账号由管理员初始化 / 种子创建，不开放自助注册」；口令复杂度在**任何 CONFIRMED 文档中都不存在规则**，按 AGENTS.md §2.2「不得自行创造尚未确认的业务规则」，唯一允许的行为是**不新增规则**。这与 F001 对 `undefined_constraints` 的处理方式一致。 |
| 不确认会改变核心领域关系？ | **否**。`User` / `Session` 不属于资源领域模型（§5、§24）。 |
| 不确认会导致验收标准无法定义？ | **否**。AC-01 ~ AC-13 全部可判定，且**没有任何一条依赖**口令复杂度、账号管理界面或用户名大小写语义。 |

**据此的明确行为边界（对 Architect / Backend 是硬约束）**：

- 账号来源**只有一种已确认方式**：管理员 / 运维**先行建立**（种子 / 初始化），**不存在**未认证可达的注册入口。因此任何「首次访问由任意访客 claim 管理员账号」的引导页面都**违反** `adr-0005` §1，不得实现。
- 口令策略（最小长度、复杂度、是否允许空口令）**当前未定义**：F013 **不得**自行引入复杂度规则，也**不得**在契约、前端文案或 AC 中承诺其行为。**后果声明（不是规则）**：在现有已确认规则下，F013 不会因为口令「过短 / 过弱」而拒绝该口令。这**不得**被解读为 CSM 已确认「弱口令合法」。
- 账号**停用**的行为是已确认的（`active = false` → 不能登录、会话即时作废）；但**停用入口**（管理界面 / API）未被确认 → 归入「本次未涉及」，验证可用**绕过应用层直接置位 `active`** 完成（沿用 F001 AC-07 的验证取向）。
- **初始管理员如何设定**（环境变量 / 种子脚本 / 运维手工步骤）属**架构与运维选择**，产品只要求「存在一条文档化、可复现的建立路径」与「不开放自助注册」（AC-11、AC-08）。

**不输出 `FEATURE BLOCKED AT PRODUCT`。** 依据同 F001：权威文档已经规定的不是「某个取值」，而是「不做决定」。

### 问题 B — 会话过期与滑动续期

**结论：这是已被批准的「实现阶段决定」事项，不是待产品确认项。**

依据：`adr-0005` §5 明确「会话过期时间与是否滑动续期**由实现方案决定并记录**」；数据库设计将 `sessions.last_seen_at` 标为 **PROPOSED / OPTIONAL** 并注明「不是产品规则」。**该委托本身已由用户批准**（ADR-0005 = `ACCEPTED`），因此产品层面的位置是：

- V1 **产品不约束**会话时长上限，也不要求滑动续期；
- 实现**必须记录**所选择的过期时长与续期策略，并同步到 F015 部署文档；
- 用户可见后果随该记录确定；若用户希望固定某个值，属**补充产品规则**，属可逆调整。
- 因此该问题**不构成 Blocking**，也不进入产品 AC（登记于 NQ-2 / PROPOSED-5）。

### 问题 C — `GET /api/health` 是否豁免认证

**产品判断：不豁免。**

依据与理由：

1. **没有任何已确认的产品需求**要求未认证可达的健康检查。§23 明确 V1 不做告警平台 / 监控平台替代；§20 只要求内网可达。
2. `adr-0005` §4 的表述是**绝对规则**：「所有 `/api/*`（**登录端点除外**）要求认证」。减少豁免面是「最小、最可审计」的边界；新增一个白名单成员属于**对已批准决策的有意扩展**，须由用户明确确认，不能由 F013 默认取得。
3. F012 交接把该项记为 **PROPOSED（待 F013 确认）**——本 Handoff 的确认结果即：**不采纳该 PROPOSED**；`/api/health` 在 F013 后未认证访问返回 `401 UNAUTHENTICATED`（AC-13）。F012 的 AC-02「`GET /api/health` 返回 200」在**已认证**调用下仍然成立。
4. **F015 的运维探测需求不由产品 API 承担**：Architect 可以为存活 / 就绪探测选择**不经过产品 API 认证面**的实现（例如 `/api` 之外的运行时可操作路径，或容器级探测），这与 `adr-0005` 的「产品 API 只有登录豁免」规则互不冲突。该选择是架构决策，**F013 不替 Architect 定路径**（见 Architecture Handoff #1、PROPOSED-4）。
5. 若用户后续明确批准 `/api/health` 豁免，属**对 ADR-0005 白名单的有意扩展**，须同步记录并修订 AC-13 与问题 C 的裁定。

### 问题 D — F013 的交付边界

| 项 | 结论 | 依据 |
|---|---|---|
| 端点范围 | **登录**（唯一认证豁免）、**登出**、**会话校验**，加上覆盖全部 `/api/*` 的认证边界。具体路径与形态由 Architect 定义 | `adr-0005` §4/§5；foundation architecture Backend Work |

## Acceptance Criteria

每条均为**可判定（是 / 否）**，描述**用户或调用方可观察到的行为**。

- **AC-01（未认证不得访问受保护端点）**：未持有有效会话时，请求任意 `/api/*` 资源端点（含 `GET` / `POST` / `PATCH /api/clusters*`）→ 返回 `401` 且 `error.code == "UNAUTHENTICATED"`；响应**不包含任何资源数据**，不得返回 `200`。
- **AC-02（登录成功后获得访问能力）**：使用已建立的账号 + 正确口令登录 → 登录成功；同一客户端随后 `GET /api/clusters` → `200`。
- **AC-03（口令错误不建立会话）**：口令错误（或账号不存在）时**不建立任何会话**；该客户端随后访问受保护端点仍为 `401 UNAUTHENTICATED`；响应与日志中**不出现口令明文**。
- **AC-04（登出使会话失效）**：已登录用户登出后，同一客户端再访问受保护端点 → `401 UNAUTHENTICATED`，该会话不可复用。
- **AC-05（会话失效时前端回到登录页）**：前端在收到 `401 UNAUTHENTICATED`（会话无效 / 过期 / 已登出）时**回到登录页**，不显示任何资源数据。
- **AC-06（登录页拦截未登录访问）**：未登录用户访问前端受保护页面 → 先看到登录页；提交正确凭据 → 进入系统；提交错误凭据 → 停留在登录页并显示失败提示。
- **AC-07（账号禁用即时生效）**：`users.active = false` 的账号无法登录；其此前建立的会话不再能访问受保护端点。在 F013 不提供账号管理界面时，验证可通过**绕过应用层直接置位 `active`** 完成。
- **AC-08（不存在自助注册入口）**：系统中不存在任何允许**未认证用户创建账号**的入口（无注册端点、无注册页面）。
- **AC-09（仅两态、无 403 触发路径）**：认证通过后，对任一受保护资源端点的访问**不因「角色 / 权限」被拒绝**；系统中不存在角色、权限、RBAC 相关的表、列、端点，也不存在任何触发 `403 FORBIDDEN` 的产品路径。
- **AC-10（口令不以明文存储或泄露）**：数据库中不存在口令明文；口令明文字符串不出现在日志与错误响应中。（「哈希算法为 Argon2id」属架构判据，见 Architecture Handoff #3。）
- **AC-11（初始账号可建立且可登录）**：按仓库内**文档化的初始化步骤**建立初始账号后，该账号可成功登录并访问受保护端点。
- **AC-12（`/api/clusters*` 行为变更为认证保护，且已记录）**：F013 交付后，未认证访问 `/api/clusters*` 一律 `401 UNAUTHENTICATED`；该行为变更在交接文档中明确记录，并作为 F015 部署 / 运维文档的输入。
- **AC-13（`/api/health` 的认证行为）**：F013 交付后，未认证访问 `GET /api/health` → `401 UNAUTHENTICATED`（本 Handoff 问题 C 的裁定：**不新增豁免**）；已认证调用仍返回 `200`，F012 的 AC-02 因此仍成立。若用户在 F013 阶段明确批准豁免，本条与问题 C 的裁定须同步修订。

**明确不进入 F013 产品 AC 的内容**（归属见括号）：口令强度 / 复杂度策略（未确认，见 PROPOSED-1）；用户自助修改口令；账号管理界面 / API；口令找回 / 重置；MFA / OTP；登录审计；登录频率限制 / 账号锁定；多设备会话管理与会话列表；用户名大小写语义（PROPOSED-2）；IP / UA 记录；会话时长与滑动续期的具体数值（属实现，须记录，见 NQ-2）；LDAP/AD/OAuth/SSO（已排除）；RBAC（已排除）；HTTPS / TLS（已排除，属 F015 记录）；生产部署打包（F015）。

## Assumptions

（不阻塞当前工作、可安全暂时采用；**不得当作 CONFIRMED**）

1. **F013 拥有 `users` / `sessions` 两表及其增量 migration**（编号 `0002`+），列与约束沿用已 READY 的数据库设计；**不改动 `0001_f012_baseline`**。

5. **F013 不引入任何授权判断**，因此 `403 FORBIDDEN` 无触发路径。
6. **F013 期间可由 §19 与 `adr-0005` 完整支撑**，不需要新的产品裁定即可进入架构阶段。

## Proposed Rules

**PROPOSED-1（✅ 已裁定为 R-AUTH-004）**：口令长度至少 8 位。

**PROPOSED-2（✅ 已裁定为 R-AUTH-005）**：用户名唯一性与登录匹配均区分大小写。

## Architecture Handoff

以下为 Architect 需要解决的技术设计问题（本 Handoff **不**选择框架、**不**设计表、**不**定义 API 细节、**不**编写代码）：

1. **认证边界的默认保护与豁免机制**：确认除登录端点外，全部 `/api/*` 默认受保护，且**未来新增端点无需白名单**（fail-closed）；明确豁免名单的唯一成员为登录端点。就 `/api/health` 给出与 `adr-0005` 一致的处理（本 Handoff 裁定不豁免），并为 F015 的存活探测给出**不破坏产品认证规则**的方案。回应问题 C。
2. **初始管理员初始化机制**：确定账号建立路径（种子 / 环境变量 / 运维步骤），保证**文档化、可复现、幂等**，且**不产生未认证可达的注册入口**。回应 AC-08 / AC-11。
3. **口令存储的具体落实**：Argon2id 参数、哈希与校验路径；落实「明文不落库、不落日志、不落错误信息」（含异常堆栈与请求日志的过滤）。回应 AC-10。
4. **会话生命周期**：过期时长、是否滑动续期、`sessions.last_seen_at` 是否使用、过期会话的清理方式；并**记录**该决策，供 F015 引用。回应 NQ-2。
5. **Cookie 与会话凭证的落地**：`HttpOnly` / `SameSite=Lax` / **不设 `Secure`** 的具体设置（含路径与作用域），以及在**无 HTTPS** 前提下对 CSRF 的实际缓解考虑。此项属架构取舍，不得反向要求 HTTPS。
6. **`401` 语义与前端的协作契约**：`401 UNAUTHENTICATED` 的错误信封形态；前端 API 客户端的统一会话失效处理与登录页跳转；并明确登出一类端点在会话已失效时的幂等语义。回应 AC-05 / AC-06。
7. **认证表与 migration 的归属与形态**：`users` / `sessions` 的列、约束、索引沿用已 READY 的数据库设计；新增**增量** migration，**不改动** `0001_f012_baseline`；不得引入角色 / 权限 / RBAC 结构，不得为认证表引入 `deleted_at`。回应 AC-09。
8. **既有 `/api/clusters*` 的行为变更的验证**：确认 5 个既有端点未认证时为 `401 UNAUTHENTICATED`（而非 `404` / `405` / `500`），并明确回归范围（F001 既有测试的调整方式）。回应 AC-01 / AC-12。
9. **账号禁用的生效路径**：在 F013 不提供账号管理界面的前提下，给出**运维可执行**的停用路径，并保证停用后**既有会话即时失效**；明确验证方式。回应 AC-07。
10. **F013 ↔ F014 / F015 的接缝**：确认 F014 的统一软删领域服务**不作用**于认证表、F013 **不**实现任何资源软删语义；确认 F015 承接部署文档中的「内网 HTTP / 无 `Secure` / 仅限受控内网」记录与探针路径选择。
