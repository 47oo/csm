## Problem

**谁在什么情况下使用**：CSM 内部运维人员在生产实例（`http://192.168.10.221/`，设计规模 10⁵ 资源 / 并发 50）上维护与排查资源。

**当前怎么做**：F018 已提供 Cluster 内关键字搜索，但结果是一张**只包含「自身字段命中关键字」的资源的扁平混合列表**（R-QUERY-005）。运维人员输入一个 IP，只会看到那条 IP 记录本身；想弄清「这个 IP 挂在哪张网卡、哪台裸金属上」，仍要额外逐层查询。

**困难 / 期望**：用户希望（原文）「将搜索的内容进行聚合，比如输入 ip 地址，显示裸金属 cn001，ip xxx，网卡 eth0 等等」——即**以命中项为中心，把它所在的关联链一并带出来**，让一次搜索直接给出资源的上下文，而不是孤立的一条记录。

**本 Feature 解决的是「搜索结果的上下文聚合与呈现」问题**；**不改变**搜索的范围前置、匹配语义，也**不改变**任何资源的登记、关系、状态、唯一性或生命周期行为。

## Confirmed Requirements

下列 8 点**逐字取自 DEC-022 裁定**（`NQ-1 ~ NQ-8`），不得改写或扩张：

1. **结果形态**：单一**扁平混合列表**（不按资源类型分区块）。
2. **聚合（分组）单位**：按**命中项的关联链**——以每个命中项为单位展开其关联链；顶层仍是扁平列表，组织顺序以「**命中项 + 其关联链**」为单元。
3. **关系扩展**：**做**——命中项的关联链资源也纳入结果，即使其自身字段未命中关键字。
4. **呈现 / 信封**：**方案 A**——「命中行 + 缩进关联行」：每行是一个资源，命中行标注「**命中**」、关联行标注「**关联**」及其**推导路径**。
5. **未关联到任何 BareMetal 的命中资源**：**仅显示搜索涉及的资源**，采纳解读 **(a)**——「查到的资源」= 命中项 **+** 其关联链资源（与第 3 点一致），**不做全量倾销**。
6. **跨组去重**：**不去重**——同一资源因命中多条链时**重复出现**。
7. **排序**：按**关键字最靠近**，具体采纳 **(a) 字段优先级**：**标识字段（`hostname` / `name` / `ip_address`）优先于描述性字段**。
8. **是否取代 F018 扁列表**：**取代**——新的聚合语义取代 F018 的扁平列表行为。

**继承自 F018 / R-QUERY-005（保持不变）**：前置「先选定单一 Cluster」；范围恒为所选 Cluster 且不跨 Cluster；匹配 = 标识字段 + 描述性字段（字段权威见 `domain-model.yaml`）；匹配语义 = 子串包含 + 不区分大小写 + 单关键字；每条结果显示命中字段；无命中复用 R-QUERY-004 Empty 语义；只读；软删不出现；认证 401；空 / 仅空白关键字不构成有效搜索。

**未由用户指定（明确留给 Architecture，不得由 Product 发明）**：同优先级结果之间的**确定性兜底顺序（tie-break）**；分页形态（条目级 vs 组级）；响应字段 / 信封的具体 JSON 结构。以上属**可实现性选择**，由 Architecture 在契约中定稿。

## Acceptance Criteria

**通用 AC（继承 F019 计划基线，已按聚合裁定适配）**

- **AC-01（只读）**：任何一次搜索都不创建 / 修改 / 删除资源；不存在可用的搜索写端点，搜索路径无写副作用（可核验：搜索后相关记录 `updated_at` 与数据内容不变）。
- **AC-02（软删过滤）**：已逻辑删除的资源**不出现**在结果中（命中行与关联行均不含）。
- **AC-03（认证）**：未认证访问搜索相关端点 → `401 UNAUTHENTICATED`，响应体不含任何资源数据。
- **AC-04（Not Found / Empty 区分）**：目标 Cluster 不存在或已软删 → `404 NOT_FOUND`；Cluster 存在且活跃但无命中 → `200` + 空结果 + Empty 态；二者界面互不相同、可独立断言。
- **AC-05（不改既有语义）**：不新增唯一性约束；不改 §22 比较、`by-name` 字面值解析、用户名查找禁止 `lower()/ILIKE`。可核验：`cluster-a` 与 `Cluster-A` 仍被视为不同值；`by-name` 仍精确匹配。搜索匹配的「不区分大小写」仍**仅限搜索匹配**。
- **AC-06（契约一致）**：搜索响应契约已持久化且 `contract.status = READY`，且 R-QUERY-005（已修订）与 R-QUERY-006（已新增）已按 DEC-022 同步；**不得存在「产品规则 / 契约禁止、实现却有」的分裂**。
- **AC-07（前端三态）**：Loading / Empty / Error 互不相同；错误按 `error.code` 渲染、不解析 `message`、不重复实现业务校验。
- **AC-08（范围边界）**：不引入自动资产发现 / 外部同步 / 导出 / 状态筛选 / 统计式聚合；排序仅限 R-QUERY-006 的字段优先级，不含相似度 / 打分式相关性排序，不含 R-QUERY-006 之外的类型 / 时间排序。

**聚合专属 AC（取自 DEC-022 裁定）**

- **AC-A1（扁平列表 + 单列表）**：一次搜索返回**一张单一扁平列表**，不按资源类型分区块 / 分区；列表**每一行恰对应一个资源**（可含 `resource_type` 与 `id`），不存在多张并列列表的呈现。
- **AC-A2（命中 / 关联行标注）**：资源自身字段命中关键字的行标注为「**命中**」；因处于某命中项关联链而出现的行标注为「**关联**」，并显示其**推导路径**；两类标注在界面可区分、可分别识别。
- **AC-A3（关系扩展）**：某资源自身字段**未**命中关键字，但属于某命中项的关联链时，**仍出现在结果**中（标注「关联」）。可核验示例：搜索某 IP → 结果包含该 IP 所在的 NetworkInterface 与 BareMetal，即使网卡 / 裸金属字段未命中。关联判定与 R-QUERY-003「与 BareMetal 相关」（含间接）**一致**。
- **AC-A4（仅搜索涉及资源）**：结果只含**命中项 + 其关联链资源**；不出现「与任何命中项无关联链关系」的资源；**不得**因一次搜索而展示该 Cluster 的全量资源（解读 (a)，不做全量倾销）。
- **AC-A5（不去重）**：同一资源若因**两条不同命中链**出现，则在结果中**出现两次**（各归属其组织单元）；系统不合并为一条。
- **AC-A6（标识字段优先排序）**：以**标识字段**（`hostname` / `name` / `ip_address`）命中的结果排**在**仅以**描述性字段**命中的结果**之前**。可核验：构造资源 X（`hostname` 命中）与资源 Y（仅 `owner` 命中），X 出现在 Y 之前。（**同优先级之间的 tie-break 不在本 AC 内**，由 Architecture 定稿。）
- **AC-A7（取代 F018 扁列表）**：搜索结果的呈现为聚合视图（命中行 + 关联行）；不再提供 F018「仅自身命中、无关联行」的纯扁列表行为；不并存两套相互冲突的结果形态。
- **AC-A8（聚合单元组织顺序）**：顶层为扁平列表，但组织顺序以「命中项 + 其关联链」为单元——同一命中项的关联资源**紧随其命中行**并以缩进 / 标记区分，而非与命中行分离散布。

## Assumptions

（不阻塞、可安全暂用；**不得**当作 CONFIRMED）

- **A-1**：聚合结果的信封 / 字段结构（每个组织单元、命中标记、推导路径如何携带）由 Architecture 在契约中定稿；本 Handoff 只描述**产品可观察行为**（如「关联资源紧随其命中行并以缩进 / 标记区分」）。
- **A-2**：「推导路径」至少表达关联经过的资源 / 关系（如 `IP → NIC → BareMetal`）；具体文案与展示形态由 Frontend 决定。
- **A-3**：命中行与关联行复用各资源 canonical `*Read` 表示；不新增资源字段。
- **A-4**：「关联链」的确切展开范围（逐资源类型的方向 / 深度）由 Architecture 依 R-QUERY-003 推导映射；本 Handoff 只要求与 R-QUERY-003 一致并复现用户示例（见 Non-blocking NQ-D）。
- **A-5**：现行分页信封可沿用或调整，由 Architecture 定稿。

## Proposed Rules

**非 CONFIRMED，不得实现为既定需求：**

- **PROPOSED-1**：当一条资源自身命中、同时又是另一命中项的关联资源时，两处都出现（既作为「命中」行、又作为他项的「关联」行）。与「不去重」（第 6 点）方向一致，但用户未逐字确认此组合情形，**属呈现建议**。
- **PROPOSED-2**：当一条资源有**多个字段**命中时，显示全部命中字段（沿用 F018 PROPOSED-2 的取向）。

除上述外，本 Feature **不提出任何其他产品规则**。
