## 1. 背景与目标

### 1.1 背景与用户问题 `CONFIRMED`

目前集群、服务器、网卡、IP、网段、虚拟机和服务信息分散在表格中。运维人员需要快速回答：

- 某集群有哪些主机及状态；
- 某个 IP 在哪台机器的哪张网卡上；
- 某台宿主机运行哪些 VM；
- 某项服务部署在哪些节点；
- 新增主机时如何一次完成主机、网卡和 IP 的登记。

定位：内网运维资源查询与维护平台，逐步替代分散的 Excel 台账。

### 1.2 P0 目标 `CONFIRMED`

- 按集群查看和维护裸金属、网段、VM、服务及部署实例；
- 支持主机及其网卡/IP 一次录入；
- IPv4 地址支持手动或自动分配；
- 支持从 IP、VM、服务反查实际归属；
- 保证同集群内有效计算资源名称和 IP 唯一；
- 平台记录运维台账；
- 资源状态由维护人员更新，并展示更新时间。

### 1.3 资源抽象 `CONFIRMED`（专有属性必填范围 `OPEN`）

平台统一使用“资源”作为业务概念。

P0 中，裸金属与 VM 共用计算资源身份 `Resource`，通过 `resource_type` 区分：

- `bare_metal`：裸金属；
- `virtual_machine`：虚拟机。

`cn001`、`vm001` 等均是具体资源实例，每个实例具有稳定资源 ID。

计算资源共用：所属集群；名称；资源类型；创建/更新时间。删除后的资源历史与在用业务对象分开保留；至少记录操作人及删除/变更内容，其它历史边界见 §11.2。

CPU、SN、宿主机、vCPU 等专有属性由对应类型详情维护。

网段、IP、服务在业务上也属于资源，但 P0 继续采用独立模型，不作为计算资源公共表的类型。

- `OPEN`：CPU/内存/GPU/SN/vCPU 等专有属性的必填范围（见 §11 Q3）。

## 2. 使用角色与典型任务

### 2.1 角色与首期权限建议 `CONFIRMED`（认证源 `CONFIRMED`：平台自建，BQ-V）

| 角色 | 任务 | 首期权限建议 |
| --- | --- | --- |
| 运维查看者 | 选择集群、搜索主机/IP/VM/服务、查看详情 | 只读 |
| 资源维护者 | 新增和修改主机、网段、网卡、IP、VM、服务与部署；执行已确认的真实删除操作（含集群），仍受关联保护约束 | 读写 |
| 平台管理员 | 维护集群信息、账户权限及冲突处理；可执行真实删除 | 管理 |

- P0 采用全平台统一三角色，集群选择是查询作用域，不是按集群授权边界（BQ-H）。这是本期产品方案，不代表现实组织不存在隔离需求；后续若需要按集群隔离，须另行确认。
- `CONFIRMED`（BQ-V）：认证源为**平台自建用户管理**，不接入组织既有认证方式；用户的增删改、角色分配、改密/重置、登录/登出、账号禁用见 §4.9。

### 2.2 典型任务路径 `CONFIRMED`

- `选择 N96P → 搜索 gpu0756 → 查看基本信息/接口/IP/VM/服务`
- `进入全局 IP 查询 → 搜索 192.168.1.1 → 从带集群的结果中选择 → 定位主机和 eth0`
- `新增 cn001 → 填写 eth0、ib0 及其 IP → 一次提交`
- `新增 cn001 → 填写使用集群、eth0 及其 IP → 一次提交`
- `选择集群并新增 cn001 → 发现同集群已有有效节点 → 用户确认进入其编辑表单 → 复用已有 eth0 或新增网卡并补充可用 IP → 一次提交`
- `搜索 NFS → 查看各部署节点及角色`

> 网络增量补充口径（BQ-G，按本轮 BQ-H 修正过度限定）：已登记资源无论是否已有网卡/IP，均可通过同一资源表单补充网络信息；本次未变更的公共信息、类型详情及既有网络记录保持不变，仍按 §4.5 整单原子保存。“IP 未使用”不等于“节点无网络”，也不等于“IP 可分配”，新增/重新分配仍须满足 §5。已有同名接口应复用编辑，不重复创建；不因同名自动覆盖节点。不新增独立“编辑网络”入口，不新增存储对象。

## 4. 核心业务规则

### 4.1 集群与计算资源 `CONFIRMED`

1. 集群使用稳定编号 `code`，例如 `N96P`。
2. 同集群内有效计算资源 `name` 在裸金属与 VM 之间统一唯一，跨集群允许重复。
3. 裸金属原 hostname 统一使用资源 `name` 表达，表单可显示“资源名称（主机名）”。
4. 网卡和服务部署使用稳定 `resource_id` 关联，资源改名不改变归属。
5. `resource_type` 创建后不允许直接修改。
6. Cluster 是独立受管实体，属性集为稳定编号 `code`、名称、用途；新增/编辑由平台管理员维护，真实删除权限见第 13 条（BQ-M）。
7. 集群 `code` 全局唯一、创建后不可修改，真实删除后仍不得复用（BQ-I、BQ-M）。集群名称不可重复、可以修改，仅允许字母、中文、下划线、数字；包含空格的输入直接拒绝，不先去首尾空格后保存；名称判重区分大小写（`ABC` 与 `abc` 不视为相同），真实删除后名称可复用（BQ-J、BQ-K、BQ-M）。字母/中文/数字的具体字符范围与名称长度待 §11.2 确认；用途可修改。
8. P0 已登记计算资源的所属集群不可直接修改；不通过普通编辑执行跨集群迁移（BQ-H）。
9. 集群仍有关联的计算资源、网段或服务业务关系时，必须先显式删除/解除相应仍存业务关联，才能真实删除集群；不隐式级联。仅余已经解除的历史关联不阻止删除，审计和资源历史不得据此清除（BQ-H、BQ-M）。其它对象的必需关系删除顺序见 §11.2 待确认。
10. 新增时发现同集群同名有效计算资源，应提示已存在并让用户确认是否进入该资源编辑；不创建第二条，不自动覆盖或合并。只有用户确认进入编辑后才按该资源的稳定 ID 更新，跨集群同名仍允许（BQ-H）。
11. 集群 `code` 的判重口径（BQ-I、BQ-M）：先去除首尾空格，再统一转为大写，按该结果全局判重；与任何曾经登记的集群 `code`（包括已真实删除者）等价时拒绝创建。展示/存储形式不由此规定；允许字符集及长度限制尚未确认（见 §11.2）。
12. 所有受管资源仅支持真实删除，不保留逻辑删除状态或业务恢复入口（BQ-M）；删除后的审计与资源历史仍保留，历史记录不作为在用业务关联。仍存业务关联须先处理，不因真实删除自动级联清理。
13. P0 集群真实删除可由非只读用户（资源维护者、平台管理员）操作；运维查看者不得执行，服务端必须校验权限（BQ-M）。删除前必须满足第 9 条与 §4.4 逐项先删原则；具体确认交互、其它必需关系的处理、历史的其它查询权限与保留周期仍待 §11.2 确认。真实删除后 `code` 不复用、名称可复用；实现所需持久约束交架构/数据库设计，不预设直接删除数据库行。

### 4.2 网卡与 IP `CONFIRMED`

1. 同一集群内有效 IP 地址全局唯一，跨集群允许重复。
2. 同一主机可有多张网卡。
3. 一张网卡可有零个或多个 IP。
4. 无 IP 的 IB 接口允许登记。
5. 同一有效计算资源下接口名唯一。
6. 网卡录入时直接选择本集群的网络范围（网段），不再单独填写技术类型和用途。
7. 网络技术、用途、前缀、VLAN 和网关由所选网段关联展示。
8. 仅支持 IPv4。
9. **管理 IP（2026-09-24 裁定，BQ-B）**：从该计算资源已登记的网卡 IP 中指定一个作为管理 IP，不单独自由填写。资源可无管理 IP（`nullable`）；被指定的 IP 必须属于该资源。管理 IP 为资源上的引用/展示字段，不新增独立 IP 记录。
10. **“有效”定义（BQ-M 覆盖 BQ-C 的逻辑删除部分）**：指仍存在的在用业务对象；已真实删除的对象仅保留审计与资源历史，不作为有效业务对象。系统不设“停用”状态。
11. 编辑仍保持有效的资源时，若删除其管理 IP 或该 IP 所属网卡，必须在同次提交中显式清空或重选管理 IP，否则整单拒绝；重选值须在保存结果中属于该资源的有效网卡 IP。不静默清空或改指。删除整个资源按 §4.4 处理，不要求先手工清空管理 IP（BQ-H）。

### 4.3 计算资源状态 `CONFIRMED`（2026-09-24 修订，BQ-A）

裸金属与 VM 共用同一状态模型：

- `IDLE`：空闲；
- `ALLOC`：已分配；
- `DOWN`：宕机 / 不可用；
- `UNKNOWN`：未知。

默认状态为 `ALLOC`。状态由维护人员更新，页面展示状态来源及更新时间。

> 本次修订取代原“`AVAILABLE` / `IN_USE` / `FAULT` / `UNKNOWN`，默认 `UNKNOWN`”定义。

- `OPEN`：“状态来源”的具体语义（操作者还是来源系统）。

### 4.4 真实删除与历史保留 `CONFIRMED`（BQ-M；详细数据边界仍 `OPEN`）

1. 全部受管资源取消逻辑删除功能，仅执行真实删除；不提供将已删除业务对象恢复到在用状态的入口。历史 BQ-C/BQ-H 的逻辑删除/恢复规则由 BQ-M 覆盖。
2. 真实删除上级资源前，须将其仍存的下级业务对象/关联**逐项显式删除或解除**，再删除上级；任一仍存子项或未解除业务关联不允许因删除上级而隐式级联。仅在资源历史中留存的**已解除**关联不阻止删除。网段保留地址须逐条删除、网关属性须显式清空（§5）；服务关联下的访问入口须逐条真实删除（§4.8）；其它必需关系的合法处理见 §11.2。
3. 删除计算资源前须逐项删除其网卡/IP 等仍存子项；逐项真实删除 IP 后释放在用地址占用，重新分配仍须满足 §5 全部条件，不随上级资源删除隐式级联释放（BQ-N）。
4. 审计和资源历史保留，不随业务对象真实删除而清除；资源历史至少保留**操作人**及**删除或变更的内容**，P0 **仅平台管理员**可以查询，查看者与资源维护者不得查询（BQ-N、BQ-Q）。`CONFIRMED`（BQ-V）：审计与资源历史 P0 **长期保留、不自动到期清除**（与 BQ-Q 一致），将来调整保留政策须另行确认；审计继续记录 §9.1 已确认的操作者、时间及关键变更，其载体边界见 §11.2、§9.3。历史不视作仍存业务关联或恢复入口。
5. 删除宿主机前，须先逐项真实删除依赖它的 VM；删除任一计算资源前，须先逐项真实删除指向该资源的服务部署实例；若 VM 自身有网卡/IP 或被实例引用，还须按本节逐项先处理。任一依赖仍存则拒绝删除上级，不自动改挂/级联 VM 或实例（BQ-T）。平时是否允许独立改挂另见 §11.2；服务及服务—集群关联保护仍见 §4.8。
6. 普通列表仅显示仍存业务对象；仅管理员可以查询真实删除/变更的资源历史；具体查询交互/载体由后续设计确定，不改变权限边界。

### 4.5 一次提交 `CONFIRMED`

同一资源表单涵盖以下内容，并支持一次保存：

- 资源公共信息；
- 与 `resource_type` 对应的类型详情；
- 全部网卡；
- 全部 IP。

整个保存过程必须作为一次完整操作：

- 任一校验或写入失败，整单失败；
- 不能出现“主机已创建但第二张网卡失败”等半完成状态；
- 编辑时必须区分“删除一张网卡”“删除一个 IP”和“未修改该项”。
- 对已登记资源补充/修改网卡与 IP 时，仍使用同一资源表单、一次提交，对保存后的完整资源及其关系进行校验，任一失败整单失败。“仅更新网络内容”指本次不改动其他字段，不得覆盖未修改的已有数据；不限制节点必须没有网络记录（BQ-G、BQ-H）。
- 两人基于同一旧版本编辑同一资源时，先提交成功后，后提交者必须收到冲突提示并保留填写内容；刷新、确认后方可重新提交，不静默覆盖或自动合并他人的修改（BQ-H）。
- “原子”表示该次操作的全部变更要么生效、要么均不生效；本文不据此规定 HTTP 方法或必须传输全字段快照，具体契约由架构/API 阶段确定。

### 4.6 网段 `CONFIRMED`

1. 一个集群可以有多个 IPv4 网段。
2. 每个网段只属于一个集群。
3. 同集群内仍存网段名称和规范化 CIDR 分别唯一。
4. 不同集群可以登记相同 CIDR。
5. 同集群内网段重叠时提示风险，允许保存；重叠不豁免名称/CIDR 唯一性及 §5 分配约束（Q5，本轮 BQ-H 确认）。
6. 新增或重新分配 IP 时，地址必须属于网卡所选择的同集群有效网段。
7. P0 一条网卡/逻辑接口可关联 0 或 1 个网段；分配 IP 前必须选定网段。
8. 该接口可分配同网段多个 IP。
9. 无 IP 网卡可仅关联网段。
10. 尚未确定网络时允许暂不选网段；分配 IP 前必须补选。

### 4.7 VM `CONFIRMED`

1. VM 必须属于一个集群。
2. VM 必须关联一台已登记宿主机。
3. 宿主机只能是同集群有效裸金属资源。
4. 宿主机不能是 VM 或自身。
5. VM 名称参与计算资源统一唯一校验。
6. VM 可有多张网卡及多个 IP。
7. VM IP 同样参与同集群 IP 唯一校验。
8. 宿主机支持通过主机名称或已登记 IPv4 地址模糊查找。
9. 删除宿主机前，其仍存 VM 必须逐项先真实删除；不因删除宿主机自动将 VM 改挂到其它主机。日常独立改挂能力未在本次裁定（BQ-T）。

### 4.8 服务 `CONFIRMED`

1. 服务是可跨集群关联的独立资源。
2. 服务编号全局唯一，**真实删除后仍不得复用**；保持与已删除服务历史的身份区分。实现记录方式交架构/数据库设计，不据此推定直接删行或独立业务恢复（BQ-U）。
3. 一项服务可关联 **0..N** 个集群、多个部署实例；新建时及解除最后一条关联后均可暂时零关联。零关联的仍存服务在独立服务列表可见，不计入任何集群的服务数，也不构成集群删除时的在用关联（BQ-S）。
4. 每个实例必须指向一条有效计算资源（裸金属或 VM）。
5. 实例所属集群必须在服务的关联集群内。
6. 服务访问入口与实例监听地址/端口分别记录。
7. **访问入口按关联集群分别配置（2026-09-24 裁定，Q4）**：每个“服务 × 关联集群”各自维护自己的访问入口（VIP / 域名 / 端口）；入口归属服务-集群关联，而非服务全局。
8. 服务允许暂时没有部署实例；每个“服务 × 关联集群”可有 0～多个访问入口（BQ-H）。
9. 访问入口与节点网卡 IP 分开记录；P0 登记 VIP 不自动生成 IP 分配记录，也不自动纳入 IP 分配管理（BQ-H）。
10. 部署实例监听地址允许记录实际监听值（例如 `0.0.0.0`），不强制引用目标节点已登记 IP；不因填写监听地址产生 IP 分配记录。端口具体校验仍待 §11.2 确认（BQ-H）。
11. 真实删除服务时若存在部署实例，必须拒绝并提示先显式处理实例；解除服务—集群关联时若该关联集群内存在该服务的部署实例，同样拒绝。不隐式级联删除部署实例（BQ-H、BQ-M）。
12. 每条“服务 × 集群”访问入口支持**逐条真实删除**，删除后不提供业务恢复；解除关联前须先逐条删除该关联下全部仍存入口，不隐式级联，也不影响其它服务的入口（BQ-P）。
13. 无仍存访问入口、该关联下的部署实例已逐项处理后，允许**显式解除最后一条**服务—集群关联；仍存的零关联服务继续出现在独立服务列表中。真实删除服务前须先逐项删除其各关联下入口、处理全部部署实例并解除所有关联，再删除服务；解除关联或删除服务都不隐式级联其它对象（BQ-S、BQ-N）。

### 4.9 用户与角色管理 `CONFIRMED`（BQ-V；会话与口令实现细节交架构）

1. 平台采用**自建用户管理**，不接入组织既有认证方式；P0 能力为：用户增删改、角色分配、改密/重置、登录/登出、账号禁用。
2. 角色沿用 §2.1 平台统一三角色：运维查看者、资源维护者、平台管理员；集群选择不是授权边界。
3. 用户名在仍存用户中唯一（大小写/首尾空格比较口径并入 §11.2 `NAME-COMPARISON`）。
4. 一个用户采用**单一角色**；角色分配后，该用户的新操作按新角色鉴权，旧角色不再生效。
5. **登录/登出**：使用已启用账号 + 正确口令登录并建立会话；禁用账号、未知账号或错误口令不得建立会话；登出后原会话失效，再次访问受保护资源须重新登录。
6. **账号禁用**：禁止登录但保留用户记录，可重新启用；与删除不同。
7. **删除用户**：移除账号、不能登录；其历史操作与审计保留，不因删除用户而清除；用户名不复用。
8. **口令策略**：最短 8 位且同时包含字母与数字；P0 不强制定期过期；用户可自助改密，平台管理员可重置；不含自助找回。
9. **用户与角色维护（用户增删改、角色分配、改密/重置、禁用/启用）仅平台管理员可执行**，关键权限由服务端校验；查看者与资源维护者的越权请求被拒绝且数据不变。
10. 用户与角色管理操作按 §9.1 记录审计（操作者、时间、关键变更）；不并入仅管理员可查的**资源历史**（资源历史仍只针对受管资源）。
11. 首个平台管理员由部署/初始化预置，首登须修改初始口令；之后在平台内维护。
12. 明确排除（P0 不含，不构成永久排除）：组织认证/SSO/LDAP/AD 对接、自助注册、口令找回、多因素认证、按集群或资源的细粒度授权。

## 5. IPv4 分配规则 `CONFIRMED`

| 项目 | 规则 |
| --- | --- |
| 手动分配 | 先选择集群及网段，再填写 IPv4；允许使用自动分配范围以外、但仍在网段内的可用地址 |
| 自动分配 | 在网段配置的起止范围内按地址数值从小到大选择可用地址 |
| 自动分配范围 | 每个网段可独立启用；两端均需在网段内且起始不大于结束 |
| 不可分配地址 | 排除同集群已分配地址、**仍存网段**登记的保留地址与网关，以及普通网段的网络地址和广播地址；已真实删除网段的历史保留/网关不参与排除（BQ-O） |
| 特殊前缀 | `/31` 仅用于明确标记的点到点网段；`/32` 按单主机地址处理 |
| 保留地址 | 支持单个地址或起止范围；保留地址不绑定网卡 |
| 地址耗尽 | 明确提示当前网段无可用地址，不自动切换其他网段 |
| 释放与重新分配 | 逐项真实删除 IP 后释放地址占用，再删除所属网卡/资源；再次分配须重新检查地址是否已被占用或保留；不以删除上级对象隐式释放其仍存 IP（§4.4） |

- 手动与自动分配的可用性判断均以平台记录及本节规则为依据；P0 不通过网络扫描或实时探测判断占用（BQ-H）。
- 同集群**仍存网段**登记的保留地址或网关，也阻止该地址从另一个仍存的重叠网段分配给网卡；不可通过换网段绕过排除规则。新增保留地址/修改网关时，冲突检查同样覆盖同集群既有分配（BQ-H、BQ-O）。
- 保留地址（含范围两端）及网关必须落在其所属网段 CIDR 内（BQ-H）。真实删除网段后，其历史保留地址/网关**不再阻止**同集群其它仍存重叠网段手动或自动分配对应地址；仍须满足其它在用分配约束（BQ-O）。
- 未变更的既有 IP 保持原归属，不因已由自身占用而在编辑时被当作新分配冲突；新增/重新分配 IP 才按可用性规则选址。
- 前端预览候选地址不构成占用，最终提交后返回实际分配结果。
- 缩小自动分配范围不会回收已有分配。
- 网段页面“可自动分配数量”=当前查询时，在**已启用的该网段自动分配范围**内满足本节所有实际可自动分配条件的地址数；未启用自动分配范围时为 0。须排除同集群已分配地址、该网段及其它仍存重叠网段登记的保留地址/网关、适用的网络/广播地址（`/31`、`/32` 按本节特殊前缀规则），但不排除已真实删除网段仅留历史的保留地址/网关。该数量只是随在用记录变化而重新计算的**快照，不预占地址、不保证下一次分配成功**；并发分配仍受最终唯一性保证约束（BQ-R）。
- 真实删除网段前，须先**逐项删除该网段全部已分配地址**、**逐条删除保留地址**并**显式清空网关属性**；任一项未处理时拒绝删除。仍被网卡引用时也须先显式解除对应业务关联，不自动级联删除网卡/IP（BQ-N、BQ-O）。
- 存在已分配 IP 时禁止修改 CIDR。
- 网段无“停用”或逻辑删除状态（BQ-C、BQ-M）；真实删除的网段不再可选用，历史记录不构成可分配网段。网段仍有网卡/IP 等关联时须按 §4.4 显式处理；历史保留地址/网关的分配影响见本节 BQ-O。
- `REQUIRED`（依据 §9.3）：并发下地址不重复须由数据库/后端最终保证（技术实现交架构）。

## 7. 表单与交互要求 `CONFIRMED`

### 7.1 网卡/IP 录入顺序

建议顺序：`集群 → 网卡接口名 → 网络范围 → 手动/自动分配 IP`。

网络范围下拉显示：`网段名称 · CIDR · 用途`。只列出当前集群可用网段。网络技术和用途作为只读信息带出。新增表单尚未保存时切换集群，清除不再匹配的网段选择；已登记资源不允许通过编辑切换集群（§4.1.8）。

### 7.2 校验

前端负责基础校验：必填项、IPv4/CIDR 语法、IPv4 前缀、同表单重复接口名、同表单重复 IP。

服务端负责最终：唯一性、归属关系、权限、并发冲突。

### 7.3 错误提示

错误必须定位到具体字段和记录。例如：`第 2 张网卡 ib0：10.0.0.1 已被本集群 cn002/ib0 使用`。

错误后保留用户已填写内容。提交期间禁用重复点击。成功后跳转详情并展示保存结果。并发编辑冲突也须保留输入并提示刷新确认后重提，不静默覆盖（§4.5）。

### 7.4 网段切换

切换尚未保存的网卡网段时：清除原网段的待分配地址；提示重新选择分配方式。

已有 IP 的网卡不能只改网段后保留旧地址。必须显式释放旧 IP 并在新网段重新分配。

### 7.5 VM 宿主机选择

宿主机选择为必填搜索下拉框。可输入：完整或部分主机名称；任一已登记网卡 IPv4。

候选显示：`主机名称 · 管理 IP（如有）· 集群`，并标出命中的 IP。相同资源只展示一次。多个候选必须由用户选择，不能根据模糊输入自动绑定。

## 8. 搜索与下拉规范 `CONFIRMED`

所有搜索框及所有下拉选择框均支持用户直接输入关键词进行模糊匹配，包括：单选；多选；关联对象选择器；固定枚举选择器。

### 8.1 支持匹配的内容

| 控件/对象 | 可输入匹配内容 |
| --- | --- |
| 集群 | 集群名称、编号 |
| 计算资源、宿主机、服务实例目标 | 资源名称、资源 ID、已分配 IPv4 |
| 网络范围 | 网段名称、CIDR、网络用途、技术类型 |
| 服务 | 服务名称、编号、类型 |
| 固定枚举 | 中文展示名、英文代码 |
| 页面搜索 | 当前页面对象名称、编号等；资源页面包含 IPv4 |

### 8.2 匹配规则

- 英文不区分大小写；
- 去除首尾空格；
- 完全匹配优先；
- 其次前缀匹配；
- 再其次包含匹配；
- 同级按名称及 ID 稳定排序；
- IPv4 搜索允许部分字符串；
- `%`、`_` 等按普通字符处理；
- P0 不要求拼音、错字纠正或语义搜索。

### 8.3 交互

- 输入后约 300ms 防抖自动更新；
- 回车可立即触发搜索；
- 搜索期间显示加载状态；
- 旧请求不能覆盖较新请求；
- 支持键盘上下选择、回车确认、Esc 关闭和清空；
- 无结果显示“没有匹配项”；
- 清空关键词后回到当前筛选条件下的初始候选。

大量资源采用服务端模糊查询与分页加载，不能只匹配当前页。

## 9. 非功能要求

### 9.1 安全 `CONFIRMED`

- 仅内网访问；`CONFIRMED`（BQ-V）：仅启用 **HTTP、不启用 HTTPS**，接受明文传输风险。
- `CONFIRMED`（BQ-V，覆盖原“接入组织现有认证方式”）：平台**自建用户管理**，不接入组织既有认证方式；登录/登出、改密/重置、账号禁用与用户/角色管理见 §4.9。

- 记录新增、编辑、删除的操作者、时间及关键变更；
- `CONFIRMED`（BQ-M/BQ-N/BQ-Q/BQ-V）：审计与资源历史不随业务对象真实删除而消失；**长期保留、不自动到期清除**，P0 **仅平台管理员**可查询。审计期限与历史载体边界见 §11.2 `RESOURCE-HISTORY`。

### 9.2 性能 `CONFIRMED`

以约 1,000 台裸金属/集群为初期基线：

- 主机、VM、服务、网段列表均服务端分页；
- 常用查询字段建立适当查询能力；
- `CONFIRMED`（BQ-V）：常用列表与详情 **P95 < 1s**，搜索 **P95 < 1.5s**。
- `OPEN`（交架构）：测量方法、测量环境与其余延迟目标；不得据此新增业务规则。

### 9.3 可靠性 `CONFIRMED`（不设备份，风险已由用户接受，BQ-V）

- 数据库/后端必须承担最终并发保护；

### 9.4 可用性 `CONFIRMED`
