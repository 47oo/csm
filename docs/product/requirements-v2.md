## 1. 背景与目标

### 1.1 背景与用户问题 `CONFIRMED`

目前集群、服务器、网卡、IP、网段、虚拟机和服务信息分散在表格中。运维人员需要快速回答：

- 某集群有哪些主机及状态；
- 某个 IP 在哪台机器的哪张网卡上；
- 某台宿主机运行哪些 VM；
- 某项服务部署在哪些节点；
- 新增主机时如何一次完成主机、网卡和 IP 的登记。

定位：内网运维资源查询与维护平台，逐步替代分散的 Excel 台账。

### 1.2 P0 目标 `CONFIRMED`

- 按集群查看和维护裸金属、网段、VM、服务及部署实例；
- 支持主机及其网卡/IP 一次录入；
- IPv4 地址支持手动或自动分配；
- 支持从 IP、VM、服务反查实际归属；
- 保证同集群内有效计算资源名称和 IP 唯一；
- 平台记录运维台账；
- 资源状态由维护人员更新，并展示更新时间。

### 1.3 资源抽象 `CONFIRMED`（专有属性必填范围 `OPEN`）

平台统一使用“资源”作为业务概念。

P0 中，裸金属与 VM 共用计算资源身份 `Resource`，通过 `resource_type` 区分：

- `bare_metal`：裸金属；
- `virtual_machine`：虚拟机。

`cn001`、`vm001` 等均是具体资源实例，每个实例具有稳定资源 ID。

计算资源共用：所属集群；名称；资源类型；创建/更新时间；逻辑删除状态。

CPU、SN、宿主机、vCPU 等专有属性由对应类型详情维护。

网段、IP、服务在业务上也属于资源，但 P0 继续采用独立模型，不作为计算资源公共表的类型。

- `OPEN`：CPU/内存/GPU/SN/vCPU 等专有属性的必填范围（见 §11 Q3）。

## 2. 使用角色与典型任务

### 2.1 角色与首期权限建议 `CONFIRMED`（认证源 `OPEN`）

| 角色 | 任务 | 首期权限建议 |
| --- | --- | --- |
| 运维查看者 | 选择集群、搜索主机/IP/VM/服务、查看详情 | 只读 |
| 资源维护者 | 新增和修改主机、网段、网卡、IP、VM、服务与部署，逻辑删除 | 读写 |
| 平台管理员 | 维护集群信息、账户权限及恢复/冲突处理 | 管理 |

- P0 采用全平台统一三角色，集群选择是查询作用域，不是按集群授权边界（BQ-H）。这是本期产品方案，不代表现实组织不存在隔离需求；后续若需要按集群隔离，须另行确认。
- `OPEN`：“接入组织现有认证方式”的具体认证源（架构/部署阶段裁定，见 §11 BQ-F）。

### 2.2 典型任务路径 `CONFIRMED`

- `选择 N96P → 搜索 gpu0756 → 查看基本信息/接口/IP/VM/服务`
- `进入全局 IP 查询 → 搜索 192.168.1.1 → 从带集群的结果中选择 → 定位主机和 eth0`
- `新增 cn001 → 填写 eth0、ib0 及其 IP → 一次提交`
- `新增 cn001 → 填写使用集群、eth0 及其 IP → 一次提交`
- `选择集群并新增 cn001 → 发现同集群已有有效节点 → 用户确认进入其编辑表单 → 复用已有 eth0 或新增网卡并补充可用 IP → 一次提交`
- `搜索 NFS → 查看各部署节点及角色`

> 网络增量补充口径（BQ-G，按本轮 BQ-H 修正过度限定）：已登记资源无论是否已有网卡/IP，均可通过同一资源表单补充网络信息；本次未变更的公共信息、类型详情及既有网络记录保持不变，仍按 §4.5 整单原子保存。“IP 未使用”不等于“节点无网络”，也不等于“IP 可分配”，新增/重新分配仍须满足 §5。已有同名接口应复用编辑，不重复创建；不因同名自动覆盖节点。不新增独立“编辑网络”入口，不新增存储对象。

## 4. 核心业务规则

### 4.1 集群与计算资源 `CONFIRMED`

1. 集群使用稳定编号 `code`，例如 `N96P`。
2. 同集群内有效计算资源 `name` 在裸金属与 VM 之间统一唯一，跨集群允许重复。
3. 裸金属原 hostname 统一使用资源 `name` 表达，表单可显示“资源名称（主机名）”。
4. 网卡和服务部署使用稳定 `resource_id` 关联，资源改名不改变归属。
5. `resource_type` 创建后不允许直接修改。
6. Cluster 是独立受管实体，属性集为稳定编号 `code`、名称、用途；由平台管理员维护。
7. 集群 `code` 全局唯一且创建后不可修改；名称、用途可以修改（BQ-H）。
8. P0 已登记计算资源的所属集群不可直接修改；不通过普通编辑执行跨集群迁移（BQ-H）。
9. 集群存在有效计算资源、有效网段或服务关联时，禁止删除，需先显式处理关联，不级联删除这些对象（BQ-H）。
10. 新增时发现同集群同名有效计算资源，应提示已存在并让用户确认是否进入该资源编辑；不创建第二条，不自动覆盖或合并。只有用户确认进入编辑后才按该资源的稳定 ID 更新，跨集群同名仍允许（BQ-H）。

### 4.2 网卡与 IP `CONFIRMED`

1. 同一集群内有效 IP 地址全局唯一，跨集群允许重复。
2. 同一主机可有多张网卡。
3. 一张网卡可有零个或多个 IP。
4. 无 IP 的 IB 接口允许登记。
5. 同一有效计算资源下接口名唯一。
6. 网卡录入时直接选择本集群的网络范围（网段），不再单独填写技术类型和用途。
7. 网络技术、用途、前缀、VLAN 和网关由所选网段关联展示。
8. 仅支持 IPv4。
9. **管理 IP（2026-09-24 裁定，BQ-B）**：从该计算资源已登记的网卡 IP 中指定一个作为管理 IP，不单独自由填写。资源可无管理 IP（`nullable`）；被指定的 IP 必须属于该资源。管理 IP 为资源上的引用/展示字段，不新增独立 IP 记录。
10. **“有效”定义（2026-09-24 裁定，BQ-C）**：指未被逻辑删除；系统不再有“停用”状态。
11. 编辑仍保持有效的资源时，若删除其管理 IP 或该 IP 所属网卡，必须在同次提交中显式清空或重选管理 IP，否则整单拒绝；重选值须在保存结果中属于该资源的有效网卡 IP。不静默清空或改指。删除整个资源按 §4.4 处理，不要求先手工清空管理 IP（BQ-H）。

### 4.3 计算资源状态 `CONFIRMED`（2026-09-24 修订，BQ-A）

裸金属与 VM 共用同一状态模型：

- `IDLE`：空闲；
- `ALLOC`：已分配；
- `DOWN`：宕机 / 不可用；
- `UNKNOWN`：未知。

默认状态为 `ALLOC`。状态由维护人员更新，页面展示状态来源及更新时间。

> 本次修订取代原“`AVAILABLE` / `IN_USE` / `FAULT` / `UNKNOWN`，默认 `UNKNOWN`”定义。

- `OPEN`：“状态来源”的具体语义（操作者还是来源系统）。

### 4.4 删除与恢复 `CONFIRMED`（2026-09-24 修订，BQ-C）

1. 删除采用逻辑删除。
2. **系统不设“停用”状态（2026-09-24 用户裁定，BQ-C）**；资源只区分“有效（未删除）”与“已逻辑删除”。
3. 删除主机时，其网卡/IP 不得继续占用有效资源唯一性。
4. 如存在 VM 或服务部署关联，应先处理关联关系，再允许删除。
5. 恢复计算资源时重新检查名称、IP 唯一性与可分配规则、网段有效性及 IP 归属、管理 IP 引用、宿主/服务等关联约束。任一冲突均列出原因并使整次恢复失败，不跳过冲突记录或部分恢复（BQ-H）。
6. 普通列表只显示有效资源，管理员可追溯历史记录。
7. 恢复范围仅包括资源本身及随该次资源删除而删除的网卡/IP；此前已单独删除的网卡/IP 不随之恢复。全部生效或全部不生效（BQ-H）。
8. 删除主机不级联删除 VM 或服务部署实例；这些关联存在时仍按第 4 条拒绝。服务及服务—集群关联的删除保护见 §4.8（BQ-H）。

### 4.5 一次提交 `CONFIRMED`

同一资源表单涵盖以下内容，并支持一次保存：

- 资源公共信息；
- 与 `resource_type` 对应的类型详情；
- 全部网卡；
- 全部 IP。

整个保存过程必须作为一次完整操作：

- 任一校验或写入失败，整单失败；
- 不能出现“主机已创建但第二张网卡失败”等半完成状态；
- 编辑时必须区分“删除一张网卡”“删除一个 IP”和“未修改该项”。
- 对已登记资源补充/修改网卡与 IP 时，仍使用同一资源表单、一次提交，对保存后的完整资源及其关系进行校验，任一失败整单失败。“仅更新网络内容”指本次不改动其他字段，不得覆盖未修改的已有数据；不限制节点必须没有网络记录（BQ-G、BQ-H）。
- 两人基于同一旧版本编辑同一资源时，先提交成功后，后提交者必须收到冲突提示并保留填写内容；刷新、确认后方可重新提交，不静默覆盖或自动合并他人的修改（BQ-H）。
- “原子”表示该次操作的全部变更要么生效、要么均不生效；本文不据此规定 HTTP 方法或必须传输全字段快照，具体契约由架构/API 阶段确定。

### 4.6 网段 `CONFIRMED`

1. 一个集群可以有多个 IPv4 网段。
2. 每个网段只属于一个集群。
3. 同集群内有效网段名称和规范化 CIDR 分别唯一。
4. 不同集群可以登记相同 CIDR。
5. 同集群内网段重叠时提示风险，允许保存；重叠不豁免名称/CIDR 唯一性及 §5 分配约束（Q5，本轮 BQ-H 确认）。
6. 新增或重新分配 IP 时，地址必须属于网卡所选择的同集群有效网段。
7. P0 一条网卡/逻辑接口可关联 0 或 1 个网段；分配 IP 前必须选定网段。
8. 该接口可分配同网段多个 IP。
9. 无 IP 网卡可仅关联网段。
10. 尚未确定网络时允许暂不选网段；分配 IP 前必须补选。

### 4.7 VM `CONFIRMED`

1. VM 必须属于一个集群。
2. VM 必须关联一台已登记宿主机。
3. 宿主机只能是同集群有效裸金属资源。
4. 宿主机不能是 VM 或自身。
5. VM 名称参与计算资源统一唯一校验。
6. VM 可有多张网卡及多个 IP。
7. VM IP 同样参与同集群 IP 唯一校验。
8. 宿主机支持通过主机名称或已登记 IPv4 地址模糊查找。

### 4.8 服务 `CONFIRMED`

1. 服务是可跨集群关联的独立资源。
2. 服务编号全局唯一。
3. 一项服务可关联多个集群和多个部署实例。
4. 每个实例必须指向一条有效计算资源（裸金属或 VM）。
5. 实例所属集群必须在服务的关联集群内。
6. 服务访问入口与实例监听地址/端口分别记录。
7. **访问入口按关联集群分别配置（2026-09-24 裁定，Q4）**：每个“服务 × 关联集群”各自维护自己的访问入口（VIP / 域名 / 端口）；入口归属服务-集群关联，而非服务全局。
8. 服务允许暂时没有部署实例；每个“服务 × 关联集群”可有 0～多个访问入口（BQ-H）。
9. 访问入口与节点网卡 IP 分开记录；P0 登记 VIP 不自动生成 IP 分配记录，也不自动纳入 IP 分配管理（BQ-H）。
10. 部署实例监听地址允许记录实际监听值（例如 `0.0.0.0`），不强制引用目标节点已登记 IP；不因填写监听地址产生 IP 分配记录。端口具体校验仍待 §11.2 确认（BQ-H）。
11. 删除服务时若存在部署实例，必须拒绝并提示先显式处理实例；解除服务—集群关联时若该关联集群内存在该服务的部署实例，同样拒绝。不隐式级联删除部署实例。访问入口在删除/解除关联及恢复时的处理仍见 §11.2，不得自行补全（BQ-H）。

## 5. IPv4 分配规则 `CONFIRMED`

| 项目 | 规则 |
| --- | --- |
| 手动分配 | 先选择集群及网段，再填写 IPv4；允许使用自动分配范围以外、但仍在网段内的可用地址 |
| 自动分配 | 在网段配置的起止范围内按地址数值从小到大选择可用地址 |
| 自动分配范围 | 每个网段可独立启用；两端均需在网段内且起始不大于结束 |
| 不可分配地址 | 排除同集群已分配地址、管理员保留地址、已登记网关，以及普通网段的网络地址和广播地址 |
| 特殊前缀 | `/31` 仅用于明确标记的点到点网段；`/32` 按单主机地址处理 |
| 保留地址 | 支持单个地址或起止范围；保留地址不绑定网卡 |
| 地址耗尽 | 明确提示当前网段无可用地址，不自动切换其他网段 |
| 释放与恢复 | 删除 IP 或所属网卡/资源时释放占用；恢复前重新检查地址是否已被占用或保留 |

- 手动与自动分配的可用性判断均以平台记录及本节规则为依据；P0 不通过网络扫描或实时探测判断占用（BQ-H）。
- 同集群内某网段登记的保留地址或网关，也阻止该地址从另一个重叠网段分配给网卡；不可通过换网段绕过排除规则。新增保留地址/修改网关时，冲突检查同样覆盖同集群既有分配（BQ-H）。
- 保留地址（含范围两端）及网关必须落在其所属网段 CIDR 内（BQ-H）。已删除网段的保留/网关记录是否继续排除分配，仍待 §11.2 确认。
- 未变更的既有 IP 保持原归属，不因已由自身占用而在编辑时被当作新分配冲突；新增/重新分配 IP 才按可用性规则选址。
- 前端预览候选地址不构成占用，最终提交后返回实际分配结果。
- 缩小自动分配范围不会回收已有分配。
- 网段被有效网卡引用时禁止直接删除。
- 存在已分配 IP 时禁止修改 CIDR。
- 网段无“停用”状态（2026-09-24 裁定，BQ-C）；停止使用通过逻辑删除实现，已逻辑删除的网段不得再分配 IP。
- `REQUIRED`（依据 §9.3）：并发下地址不重复须由数据库/后端最终保证（技术实现交架构）。

## 7. 表单与交互要求 `CONFIRMED`

### 7.1 网卡/IP 录入顺序

建议顺序：`集群 → 网卡接口名 → 网络范围 → 手动/自动分配 IP`。

网络范围下拉显示：`网段名称 · CIDR · 用途`。只列出当前集群可用网段。网络技术和用途作为只读信息带出。新增表单尚未保存时切换集群，清除不再匹配的网段选择；已登记资源不允许通过编辑切换集群（§4.1.8）。

### 7.2 校验

前端负责基础校验：必填项、IPv4/CIDR 语法、IPv4 前缀、同表单重复接口名、同表单重复 IP。

服务端负责最终：唯一性、归属关系、权限、并发冲突。

### 7.3 错误提示

错误必须定位到具体字段和记录。例如：`第 2 张网卡 ib0：10.0.0.1 已被本集群 cn002/ib0 使用`。

错误后保留用户已填写内容。提交期间禁用重复点击。成功后跳转详情并展示保存结果。并发编辑冲突也须保留输入并提示刷新确认后重提，不静默覆盖（§4.5）。

### 7.4 网段切换

切换尚未保存的网卡网段时：清除原网段的待分配地址；提示重新选择分配方式。

已有 IP 的网卡不能只改网段后保留旧地址。必须显式释放旧 IP 并在新网段重新分配。

### 7.5 VM 宿主机选择

宿主机选择为必填搜索下拉框。可输入：完整或部分主机名称；任一已登记网卡 IPv4。

候选显示：`主机名称 · 管理 IP（如有）· 集群`，并标出命中的 IP。相同资源只展示一次。多个候选必须由用户选择，不能根据模糊输入自动绑定。

## 8. 搜索与下拉规范 `CONFIRMED`

所有搜索框及所有下拉选择框均支持用户直接输入关键词进行模糊匹配，包括：单选；多选；关联对象选择器；固定枚举选择器。

### 8.1 支持匹配的内容

| 控件/对象 | 可输入匹配内容 |
| --- | --- |
| 集群 | 集群名称、编号 |
| 计算资源、宿主机、服务实例目标 | 资源名称、资源 ID、已分配 IPv4 |
| 网络范围 | 网段名称、CIDR、网络用途、技术类型 |
| 服务 | 服务名称、编号、类型 |
| 固定枚举 | 中文展示名、英文代码 |
| 页面搜索 | 当前页面对象名称、编号等；资源页面包含 IPv4 |

### 8.2 匹配规则

- 英文不区分大小写；
- 去除首尾空格；
- 完全匹配优先；
- 其次前缀匹配；
- 再其次包含匹配；
- 同级按名称及 ID 稳定排序；
- IPv4 搜索允许部分字符串；
- `%`、`_` 等按普通字符处理；
- P0 不要求拼音、错字纠正或语义搜索。

### 8.3 交互

- 输入后约 300ms 防抖自动更新；
- 回车可立即触发搜索；
- 搜索期间显示加载状态；
- 旧请求不能覆盖较新请求；
- 支持键盘上下选择、回车确认、Esc 关闭和清空；
- 无结果显示“没有匹配项”；
- 清空关键词后回到当前筛选条件下的初始候选。

大量资源采用服务端模糊查询与分页加载，不能只匹配当前页。

## 10. P0 验收场景 `CONFIRMED`（随已确认规则修订）

1. 一次录入 `cn001 + eth0 + 192.168.1.1/24 + ib0 + 10.0.0.1/24`，详情完整可查。
2. 同集群已有裸金属 `cn001` 时，再创建同名裸金属或 VM 均被拒绝，不产生第二条记录或覆盖原记录；允许提示用户确认进入既有资源编辑（§4.1.10）。
3. 同集群重复 IPv4 被拒绝，不同集群允许同资源名称、同 IP。
4. 一个请求中第二个 IP 冲突时，整台新主机及之前的网卡/IP 都不应残留。
5. 修改资源 name 后，网卡、IP 和服务部署仍归属原资源。
6. 删除/恢复主机时唯一性与关联可见性正确。
7. 约千台主机按资源名称、类型、状态和 IP 查找，分页与跳转详情正常。
8. 无 IP 网卡正常显示。
9. 输入 IPv6、非法 IPv4/CIDR、IPv4 前缀超 32、同表单重复接口/IP 时能定位错误且不清空表单。
10. 同一集群可以登记管理、计算和存储等多个 IPv4 网段。
11. 越界 IP、错误 CIDR 或跨集群网段关联被拒绝。
12. 同集群登记重叠但非相同规范化 CIDR 的网段时，给出明确风险提示；其余校验通过时允许保存。
13. 一次录入 `vm001` 及其网卡/IP，可在 VM 详情及宿主机详情双向查看。
14. 跨集群宿主机关联与 VM/IP 冲突被拒绝。
15. 缺少宿主机的 VM 不允许保存。
16. 服务可跨集群关联，并在裸金属/VM 上登记部署实例。
17. 未关联集群的节点不能作为服务实例目标。
18. 对存在 VM 或服务实例关联的主机执行删除时，明确提示需先处理的关联对象。
19. 手动分配自动范围之外但仍在所选网段内的可用 IPv4 可以成功。
20. 越界、已占用、保留、网关及普通网段网络/广播地址被拒绝。
21. 自动分配范围 `192.168.1.20–192.168.1.30` 中，`.20` 已分配、`.21` 已保留时，下一次自动分配得到 `.22`。
22. 两个并发请求不能拿到同一个地址。
23. 地址耗尽时整单失败且不残留占用。
24. 释放地址后允许重新分配。
25. 未启用自动分配的网段只能手动分配。
26. 已逻辑删除的网段禁止新分配（原“停用网段禁止新分配”随 BQ-C 取消“停用”而改写）。
27. 新增保留范围或修改网关不能与现有分配冲突。
28. 新增网卡选择网段后，技术、用途、前缀及网关自动展示。
29. 网卡请求不需要单独录入 technology/purpose。
30. 未分配 IP 的网卡可仅选择网段保存，也可暂不选择网段；一张网卡最多关联一个网段，分配 IP 前必须补选。
31. 未选网段时拒绝分配 IP。
32. 统一资源列表可切换全部/裸金属/虚拟机。
33. 详情及新增表单按资源类型显示字段。
34. 资源类型创建后不能通过普通编辑修改。
35. 输入主机名称片段或 IPv4 片段可以找到宿主机。
36. 同一宿主机多个 IP 命中时按资源去重。
37. 每个搜索框、单选/多选下拉均可直接输入。
38. 模糊匹配覆盖全部符合条件的数据，而非仅当前页。
39. 快速连续输入不会出现旧结果覆盖。
40. 集群切换及权限限制生效。
41. 关联字段最终提交稳定资源 ID，未匹配输入不能意外创建资源。
42. 对已登记资源（包括已有 eth0 和 IP 的情况），可复用 eth0 追加可用 IP 或新增网卡；仅补充网络内容时，未修改的既有网卡/IP、公共信息、类型详情、状态及 VM/服务关联保持不变。不以“节点已有网络记录”为由拒绝。
43. 对已登记资源补充/修改网卡与 IP 时，若新增 IP 冲突或任一校验失败，整单失败，原资源及其既有网卡/IP 保持原状，不出现部分更新。
44. 对已登记资源新增/重新分配 IP 时，地址须属于其同集群有效网段，且满足 §5 全部可分配条件；即使未被占用，保留、网关或普通网段网络/广播地址仍被拒绝。未变更的既有 IP 保持自身归属。
45. 新增时发现同集群同名有效资源，提示用户选择是否进入该稳定 ID 对应的编辑表单；未确认前原资源不变，确认后加载既有网卡/IP，不自动覆盖或新建同名资源。
46. 编辑仍有效资源时删除管理 IP 或其网卡，未同次显式清空/重选则整单失败；显式清空或重选为保存后仍属于该资源的有效 IP 后可保存。删除整个资源不要求先清空管理 IP，仍遵守关联保护。
47. 两人基于同一旧版本编辑资源，先提交成功后，后提交者收到冲突提示且输入保留；刷新确认后才能重提，先提交的修改不被静默覆盖。
48. 资源恢复仅恢复随该次资源删除的网卡/IP，此前单独删除者不恢复；名称冲突、任一 IP 不可分配、IP 所属网段无效或引用/关联不合法时，整次恢复失败且原删除状态不变。全部校验通过才整体恢复。
49. 存在部署实例的服务不能直接删除；某服务—集群关联下存在该服务部署实例时不能解除该关联，须提示具体实例并要求先显式处理，不级联删除实例。
50. 集群 code 全局重复或创建后修改 code 被拒绝；名称和用途允许维护。已登记计算资源通过普通编辑修改所属集群被拒绝。
51. 集群存在有效计算资源、有效网段或服务关联时删除被拒绝，关联对象保持不变。
52. 同集群两个有效重叠网段中，A 登记的保留地址/网关不能由 B 手动或自动分配；A 新增保留地址/修改网关与 B 已分配 IP 冲突时被拒绝。
53. 保留地址或范围端点、网关超出所属网段 CIDR 时被拒绝且原配置不变。
54. 服务在已有集群关联且无部署实例时可保存；该关联允许零个或多个入口；登记 VIP 不产生 IP 分配记录；实例监听允许记录 0.0.0.0，不要求绑定节点已有 IP。
55. 集群主机数仅统计有效裸金属，VM/网段分别仅统计有效对象；同一有效服务在本集群部署多个实例仍只计一次，关联另一个集群时也在该集群计一次，逻辑删除对象不计入。
56. 两个集群存在相同 IP 时，当前集群资源页只返回本集群数据；独立全局 IP 查询返回带集群、资源、接口的分别列示结果，可选择定位，不静默切换查询作用域。
57. P0 三角色权限在全平台生效，切换集群不改变角色权限：查看者不能写入，维护者不能执行仅管理员允许的集群维护或恢复；对应限制由服务端验证。
