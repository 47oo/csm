### 28.1 对象选择控件的候选完整性（revision 16）

本节为 V3 一期交付后新增范围。

CONFIRMED［待用户确认后置标］：用于选择已存在对象的候选控件（下拉 / 选择框）必须能检索并选定其数据源中的全部可见对象，不得因前端一次性预取的条数上限使超出部分无法被选定。候选的检索与分页由服务端提供，前端只加载当前检索所需的一页，不采用一次加载全部对象的方式。

CONFIRMED：候选复用被选对象所属域的既有列表端点及其既有 `q` 与分页参数；候选的范围与可见性沿用该端点既有规则：过滤与排序语义、§23 角色矩阵、§23.2 集群范围（未授权集群的对象不出现，`total` 与提示不泄露其规模）、§21 软删可见性（默认排除已删除对象）、既有 401 / 403 / 422 错误口径。本节不定义新的候选过滤规则，不新增权限项。

CONFIRMED：完整性判定标准为「排名超出既有单页上限（`page_size` 上限 100）的对象可被检索并选定提交」；候选总数超出当前页时界面显式提示总数与分页边界，不静默截断。本节不改变既有 `page_size` 上限，也不改变列表 `q` 的匹配语义。

CONFIRMED：候选的加载中、加载失败、空闲（前置条件未满足，例如尚未选择集群）与空结果必须显式区分；加载失败可重试，且不伪装为空列表。

CONFIRMED 本期覆盖范围仅以下两个控件：
* VM 表单的 Host 选择（候选来源 GET /api/v1/resources，限定同 Cluster 的 BARE_METAL；含新增 VM 与编辑 VM 更换 Host，§9 / T08 / T09 / T19 的关系校验不变）。
* Resource 创建页的 Cluster 选择（候选来源 GET /api/v1/clusters；编辑时 Cluster 只读，不涉及候选）。

其余对象选择控件（Interface、Network、IP Pool、IP Address、Service、Service Endpoint 等）本期不纳入，留作后续评估；未纳入不表示永久排除，也不表示已默认满足本节要求。

CONFIRMED 明确不做：
* 不新增端点、查询参数、权限项或错误码；候选不就两处控件各建专用选项接口。
* 不允许「一次加载全部对象」作为实现方式（含提高 page_size、循环抓取全部分页、前端缓存全量候选）。
* 不改变各域列表端点的 q 匹配实现（继续沿用既有 ILIKE 子串语义，F013 §1.4 / §6 冻结口径），本节不引入 pg_trgm 或其它匹配变更。
* 不改变 §13.4 接口侧 IP 候选语义，也不把 §13.4 的 IP 专属过滤并入本节；不改变 §17 全局搜索入口行为。
* 不改变共享 Select 组件的既有全局交互语义（既有客户端筛选用法保持不变，新行为由承载服务端检索的候选组件提供）。
* 不改变唯一性、关系、状态、软删、审计与版本冲突规则：候选可被选中不等于服务端必然接受，提交时仍按既有规则返回 409 / 422。

验收：T127–T129。
